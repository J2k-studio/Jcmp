# ใบตัดสินใจก่อน 1.0 — คำตอบที่ผมแนะนำ (2026-10-22)

> วิธีใช้: ตอบสั้นๆ ได้ เช่น "ใช้ตามที่เสนอทั้งหมด" หรือ "ข้อ 3 เลือก ข แล้วข้ออื่นตามที่เสนอ" · ผมไม่ล็อก syntax เอง: ทุกข้อรอคำตอบของคุณ · ข้อที่คุณไม่ตอบ ผมทำต่อไปโดยไม่รอ (และไม่ปล่อย 1.0 จนกว่าข้อที่กระทบภาษาจะมีคำตอบ)
> ข้ออื่นๆ ใน `open-questions.md` ส่วนใหญ่ตอบไปแล้วหรือทำตามค่าเริ่มต้นแล้ว (เช่น `true` เป็น bool ไม่ใช่ int, หารศูนย์ = panic) ผมจะไล่ทำความสะอาดไฟล์นั้นหลังคุณตอบชุดนี้

| # | คำถาม | ตัวเลือก | **ที่ผมแนะนำ** | เหตุผล (กฎ 3 ตัวตาย: ยืมจากภาษาอื่น / คนจำง่าย / เครื่องทำง่าย) |
|---|---|---|---|---|
| 1 | ไลบรารีที่คอมไพล์แล้ว ชื่อนามสกุล | `.jo` / `.so` / อย่างอื่น | **`.jo`** (ตามที่คุณเสนอ) | ชื่อบอกว่าเป็นของ J2K, ไม่ชนกับ `.so` ของ C |
| 2 | ข้างใน `.jo` | IR ต่อฟังก์ชัน / โค้ดเครื่อง | **IR** ผูกกับเวอร์ชันคอมไพเลอร์ | inline ข้ามไฟล์ได้, ใช้ได้ทุก target (ARM64, ARM32, x86_64) |
| 3 | คำสั่งสร้าง | `jcmp -lib core` / อย่างอื่น | **`jcmp -lib NAME`** → `libNAME.jo` | สั้น เข้ากับ `-api`, `-jh` ที่มี |
| 4 | รอกด Enter / อ่านบรรทัดดิบ | `Term::wait_enter()`, `cin.line()` | **ทั้งสอง**: `Term::wait_enter()` และ `Term::read_line()` คืน `Result<String, Error>` | `cin >> char` ข้ามช่องว่าง ทำให้ทำไม่ได้; EOF → `Err(end of input)` ไม่ throw |
| 5 | ชื่อ register บน ARM32 | `x0..x30` (ตอนนี้) / `r0..r12` | **คง `x0..x30`** สำหรับบล็อก `register{}` และ `naked` (ซอร์สเดียวใช้ได้สอง target); ใช้ `r0..r12` เฉพาะใน `raw` ที่เป็นคำสั่งเครื่องจริง | ซอร์สพกพาได้ ไม่ต้องเขียนสองชุด |
| 6 | ARM32 ต้องมีคำสั่งหาร (ARMv7VE ขึ้นไป) | ต้องมี / ไม่ต้อง | **ต้องมี** (ทุกมือถือ ARMv8 มี) | ใช้ `udiv`/`sdiv` ตรงๆ: `gcd`, `loop` เร็วขึ้นหลายเท่า; ARMv7 รุ่นเก่าไม่ใช่เป้า |
| 7 | `cerr << ...` (เขียน stderr) | เพิ่ม / ใช้ `Log::` อย่างเดียว | **เพิ่ม `cerr`** เหมือน `cout` | C++ คุ้นเคย, `jget` ใช้ syscall ตรงๆ อยู่ |
| 8 | ถ้อยคำ error ของ ownership | ผมร่าง / คุณเขียน | **ผมร่าง 3 ประโยค คุณแก้**: "ตัวแปร 'p' ถูกย้ายไปแล้วที่บรรทัด N", "'p' ถูกคืนหน่วยความจำแล้วที่บรรทัด N", "'p' ถูกคืนสองครั้ง (ครั้งแรกบรรทัด N)" (อังกฤษตามกฎ) | บอกว่าอะไรเกิด ที่ไหน ทำอะไรต่อ |
| 9 | ขอบเขต `Regex` / `Toml` | ตอนนี้ (ไม่มี group, ไม่มี array) / ขยาย | **คงไว้สำหรับ 1.0** แล้วขยายในรุ่น B ภายหลัง | 1.0 = ล็อกสิ่งที่มี ไม่เพิ่มของใหญ่ |
| 10 | `net` แบบออบเจ็กต์ (`Listener`/`Connection`) | ตามข้อ 10a (ตอบแล้ว) | **ทำตามที่ตอบไว้**: `accept receive send close` + ปิดเองเมื่อมีการย้ายความเป็นเจ้าของ | คุณตอบไว้แล้ว ค้างแค่ลงมือ (หลัง 1.0 ได้) |

## "สั่ง CPU โดยตรง ไม่ปิดบัง" (ข้อ 11–17 = 7 ข้อใน `open-questions.md` หัว "CPU โดยตรง")
| # | เรื่อง | **ที่ผมแนะนำ** |
|---|---|---|
| 11 | ธง CPU (NZCV) | **ทั้งฟังก์ชันและตัวแปรพิเศษ**: `Bit::add_carry(a, b, c)` คืน (ผลรวม, carry) และ `Flags::c / z / n / v` อ่านได้ใน `register { }` |
| 12 | ผลคูณเต็ม / หารพร้อมเศษ / บวกอิ่มตัว | **เพิ่ม** `Bit::mul_hi`, `Bit::mul_wide`, `Bit::div_rem`, `Bit::add_sat` — แต่ละอันคือคำสั่งเดียวที่รับประกัน |
| 13 | ล็อกตัวแปรใน register | **เพิ่ม** `register(x19) int count;` (error ถ้าล็อกไม่ได้) |
| 14 | ดูโค้ด / รับประกันขนาด | **`jcmp -show` (ทำแล้ว) + `#expect instructions <= N`** |
| 15 | prefetch / ตัวกันการเดา | **เพิ่ม** `Cache::prefetch(p)`, `Cpu::speculation_barrier()` |
| 16 | คำสั่งส่วนขยาย CPU | **`#require cpu "crc32"`** แล้ว `Cpu::crc32(..)` (ไม่มี = error ตอนคอมไพล์) |
| 17 | ลำดับ | ทำข้อ 14 (`#expect`) → 11 → 12 → 13 → 15 → 16, ปล่อยทีละรุ่น B (หลังตอบ) |

ผลต่อแผน: ตอบข้อ 1–10 ได้ **พาร์ท I เต็ม (+5)**; ตอบข้อ 11–17 ได้ **พาร์ท K เต็ม (+1)** และเริ่มงานฟีเจอร์ได้
