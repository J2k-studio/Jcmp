# Compiler architecture

This page describes how `jcmp` (the J2K compiler, written in J2K) turns a `.jk` program into an ARM64 Linux executable.
It is for people who read or change the compiler. For the language itself see [LANGUAGE.md](LANGUAGE.md); for the
steps of a change see [CONTRIBUTING.md](CONTRIBUTING.md).

Source layout (all in `jcmp/`, the entry is `jcmp.jk`, the other files are parts joined with `#import`):

| file | role |
|---|---|
| `jcmp.jk` | command line, the state of a build, the pipeline in `main` |
| `jc_base.j` | output buffers, text helpers, errors, the option variables (`opt_*`) |
| `jc_lex.j` | tokenizer; `import` switches to another file (`lex_import`) |
| `jc_par.j` | runs the IR and register passes once per function, forks processes for big programs (`par_pass`) |
| `jc_stmt.j` | top level (`parse_program`), statements, functions, globals, the start stub |
| `jc_expr.j` | symbols, types and expressions of the text path |
| `jc_low.j` | `naked` functions and `register { }` blocks (statements that map to instructions) |
| `jc_gen.j` | generics: each instance is written as source text before the item that uses it (`gen_item`) |
| `jc_ast.j` | the syntax tree of a function body (`ast_probe`, node kinds `AK_*`) |
| `jc_astlow.j` | lowers the tree of the functions it understands straight to the IR |
| `jc_ir.j` | the IR: instructions, virtual registers, basic blocks |
| `jc_lift.j` | reads the assembler text of a function into the IR (`lift`), and writes the IR back as text (`lw_*`); `ir_run`, `ir_pipeline` |
| `jc_opt.j` | the passes on the IR, and the text passes that finish a function's frame and alignment (`fr_run`, `al_run`) |
| `jc_vec.j` | vector values (class 2 of the IR): stack objects kept in vector registers |
| `jc_regs.j` | register pass on the text: busy whole-number locals of loops go to `x19`..`x25` |
| `jc_peep.j` | peephole pass on the text (`peep_run`), loop rotation (`rot_run`) |
| `jc_a32.j` | the ARM32 back end (`-target arm32`): IR to ELF32 |
| `jc_asm.j` | the assembler as a library: assembler text to ELF64 |
| `jc_cache.j` | the cache of the back end (per function key) |
| `jc_jh.j` | the interface file of a module (`-jh`) |
| `jc_fmt.j` | the formatter (`jcmp fmt`) |
| `jc_logo.j` | the `-space` picture |
| `jc_std.j` | generated by `gen_std.sh`: the text of the standard library (from `std/*.j` and `Library/`) |

## 1. The pipeline

```
 program.jk  (and the files it imports)
      |
      v
 jc_lex.j ........ tokens; `import` reads another file (up to 16 nested files)
 jc_gen.j ........ generic instances, written before the item that uses them
 jc_stmt.j ....... parse_program: top-level items, one function body at a time
      |
      +-- for each function body:
      |     jc_ast.j ...... syntax tree of the body (the parser is put back afterwards)
      |     jc_astlow.j .... the functions it understands: tree -> IR (no text)
      |     text path ...... jc_expr.j, jc_stmt.j, jc_low.j write ARM64 assembler text
      |                      for the functions that are not lowered from the tree
      v
 assembler text of the whole program (one buffer)
      |
      v  nr_run ........ the ;NB / ;NE markers of @no_reorder regions become ;N lines
      v  peep_run ...... first peephole pass, only when -irpre is on
      v  ir_run ........ for each function (jc_par.j may fork one process per core):
      |                    lift (jc_lift.j) text -> IR, for functions not lowered from the tree
      |                    passes (jc_opt.j), see section 4
      |                    lower (jc_lift.j) IR -> text
      |                   [-target arm32: a32_finish, jc_a32.j, makes the ARM32 code of the functions that main reaches
      |                    from the IR and writes the ELF32 file]
      v  peep_run ...... peephole pass (jc_peep.j)
      v  regs_run ...... register pass (jc_regs.j)
      v  peep_run, rot_run (loop rotation), fr_run, al_run (alignment, in jc_opt.j)
      |
      v  jc_cache.j .... stores the functions that were made, skips the ones whose key is in the cache
      v  jc_asm.j ...... assembler: reads the text once, writes ELF64 (labels in a hash table)
      |
      v  program (or -emit-asm file.jasm, the text, written before the assembler; -show NAME stops after the code of one function)
```

The order above is the one in `main` (`jcmp/jcmp.jk`) and `ir_pipeline` (`jcmp/jc_lift.j`). Each stage can be
switched off (section 7); the text between the stages is ARM64 assembler text in every case except inside the IR.

## 2. The front end

Two paths make the code of a function body. Both end in the same assembler text, or in the IR directly.

* **Tree path (default).** When the parser reaches the `{` of a function body, `ast_probe()` (`jc_ast.j`) reads the
  body again with a small parser into a tree. The node kinds are `AK_NUM`, `AK_VAR`, `AK_BIN`, `AK_CALL`,
  `AK_ASSIGN`, `AK_IF`, `AK_WHILE`, `AK_FOR`, `AK_RET`, `AK_BLOCK`, `AK_DECL`, and others. `jc_astlow.j` builds
  the IR of a body that uses only the subset it understands (`int`, `bool`, `double`, arithmetic, comparisons,
  `if`, `while`, `for a..b`, `break`, `continue`, `return` and calls of such functions). Any other body keeps the
  text path. The frame layout the tree computes is compared with the layout of the text parser; if they differ,
  the body is lifted from its text.
* **Text path.** `jc_expr.j`, `jc_stmt.j` and `jc_low.j` write ARM64 assembler text while they parse. Every
  function that is not built from the tree goes this way and is lifted to the IR (section 3).

Switches: `-noast` makes every function go through the text path; `-ast` reports, for each function, whether the
tree path took it; `-xast` and `-xast2` report the subset (see the table in section 7).

## 3. The IR and the lifter

`jc_ir.j` holds the intermediate representation of one function at a time.

* A function is a list of **basic blocks**. A block is a run of instructions and ends with exactly one terminator
  (`jmp`, `br`, `ret`, `trap`).
* Instructions are three-address code. The opcodes are `IR_CONST`, `IR_COPY`, `IR_ADD`, `IR_SUB`, `IR_MUL`,
  `IR_SDIV`, `IR_UDIV`, `IR_AND`, `IR_OR`, `IR_XOR`, `IR_SHL`, `IR_LSHR`, `IR_ASHR`, `IR_NEG` and more (`jc_ir.j` lists them).
* A **virtual register** (vreg) is a number. It may be assigned many times: **the IR is not SSA**. Its class is
  0 (a 64-bit whole number or a pointer) or 1 (a double); class 2 is a 128-bit vector (`jc_vec.j`).
* Memory is touched only by `load` and `store` with a width.
* The IR does not know the machine. The arrays have fixed sizes (`IR_MAXI`, `IR_MAXB`, `IR_MAXV`, `IR_MAXA`).

**The lifter** (`jc_lift.j`, `lift`) reads the text of one function. The vregs are the machine registers at
first: `x0`..`x30` are vregs 1..31, `d0`..`d31` are vregs 32..63, and temporaries start at 64. Stack temporaries
(`[sp, #n]`) become loads and stores at fixed places of the frame. A comparison and the jump that uses it become
one IR jump. A function with an instruction the lifter does not know stays as text (it is not lifted).

**The lowering** (`jc_lift.j`, `lw_*`) writes the IR back as assembler text. With `-irtrip` every liftable function
is lifted and lowered again, which is how the lifter itself is tested.

## 4. The passes on the IR (`jc_opt.j`)

`ir_pipeline` runs, for each function, the passes in this order (the names are the procedure names in `jc_opt.j`
and the comments at the head of its sections):

1. **Inlining** (`op_inline`): a small function that can be lifted is copied into its callers; its frame slots and
   stack cells get new places in the caller's frame, its returns jump to the rest of the call block.
2. **Basic cleaning**: merging of blocks that have one way in (`op_merge_blocks`), null checks of array variables
   that are redundant (`op_nullchk`), dead temporaries (`op_dead_temps`), struct temporaries in the frame
   (**SROA**, `op_sroa`), **value numbering** inside a block (`op_cse_run`), **cell forwarding** of temporary
   cells (`op_cell_fwd`, `op_vfwd`), constant cells followed through blocks (`op_const_cells`), dead cells (`op_dead_cells`).
3. **Loop-invariant constants** (`op_run`): a constant that needs two or more instructions and is made in a loop
   is kept in a stack cell that is filled before the outermost loop.
4. **Counted loops** (`op_counted_loops`): a loop with one induction variable, a loop-invariant bound and one exit.
5. **Known ranges** (`op_range_run`): a `[lo, hi]` range for whole numbers, used by later passes.
6. **Vectoriser** (`op_vectorize`, the `vz_*` procedures): loops over arrays (global, frame and heap arrays) become
   128-bit vector loops with a scalar remainder; it is switched off by `-novec`. Vector registers are then assigned
   by `jc_vec.j`.
7. **Strength reduction** (`op_ssr`) of array addresses.
8. **Expressions out of loops** (`op_licm_exprs`): an instruction whose inputs do not change in a loop moves in front of the loop.
9. **Cell promotion** (`op_cell_promote`): a temporary cell that is written and read again inside a block is kept in a register.
10. **Register allocation on the IR** (`op_ra_run`, `-irra`, off by default): linear scan over the webs (`op_webs`).
11. Other passes are described in the headers of `jc_opt.j`: jump threading, copies and constants read through
    (`-iropt`), dead code, removal of double round trips, and known ranges. Whether each one runs depends on the bits
    of `ir_opt`.

The bits of `ir_opt` (`jc_ir.j`) switch the passes; `-irclr N` clears bits. The bit numbers are internal debug bits
(see section 7).

## 5. Registers and the text passes

* **Webs** (`op_webs`, `jc_opt.j`) are the definitions of one machine register joined through their uses.
  The webs are computed for the IR passes; the text register pass does not use them.
* **Register pass** (`jc_regs.j`, `regs_run`): in a function with loops, the whole-number locals that are used most
  (weighted by loop depth) move from frame slots to `x19`..`x25`. The pass works on the text, after the code is made
  and before the peephole pass. It also has rules for fusion and forwarding of instructions. A function with a
  `try`, a `defer` or a `#multithread` loop keeps its variables in the frame. `-noregs` switches the pass off.
* **Peephole** (`jc_peep.j`, `peep_run`): short rules on neighbouring lines (for example a store and a reload of the
  same register, a push that is popped at once, a constant loaded into a register just for an `add` that becomes an
  immediate). `-nopeep` switches it off.
* **Loop rotation** (`rot_run`, `jc_peep.j`): a loop test is placed at the bottom. `-norot` switches it off.
* **Alignment** (`al_run`, `jc_opt.j`): every function starts at a multiple of 32 bytes. `-noalign` switches it off.
* **Parallel passes** (`jc_par.j`): the IR and register passes are per function, so a big program is split among
  forked processes; the parent takes the text of each function from its child. `-j N` chooses the number of processes.

## 6. The assembler, ARM32, the cache

* **Assembler** (`jc_asm.j`): reads the assembler text once and writes an ELF64 executable. Labels are found through
  a hash table. The same code is used by the stand-alone assembler tool.
* **ARM32** (`jc_a32.j`, `-target arm32`): `a32_finish` translates the IR of the functions that `main` can reach to
  ARM32 and writes an ELF32 file (EABI 5) itself. Each virtual register has a stack cell, per the header of `jc_a32.j`. The status and the
  limits of this back end are in [LIMITS.md](LIMITS.md): it runs, it is slower than ARM64, and some features are
  not available. ARM32 has no `-d` checks.
* **Cache** (`jc_cache.j`): the key of a function is a hash of its text, with local label numbers renumbered in order
  of appearance, mixed with the keys of the functions it can call (the inliner reads their bodies). A function whose
  key has a stored file takes its final text from the cache, and the back end skips it. The cache is used by default
  for programs whose output is large enough to gain (`jcmp.jk`); `J2K_CACHE=DIR` chooses the folder, `-nocache`
  turns it off, `-cache DIR` names one. The key includes the version of the compiler and the options
  ([USAGE.md](USAGE.md)).

## 7. How the compiler builds itself, and the switches

**Self-build.** `bootstrap.sh` builds the compiler three times: stage 0 is the committed binary `bin/jcmp`, which
compiles `jcmp/jcmp.jk` into `jcmp1`; `jcmp1` compiles it into `jcmp2`; `jcmp2` compiles it into `jcmp3`. Success
means that `jcmp2` and `jcmp3` are identical, both as binaries and as assembler text. The standard library is read from `Library/` (found through `JCMP_LIB`, or next to the
compiler); `gen_std.sh` turns `std/*.j` into `Library/` and into `jcmp/jc_std.j`. `bootstrap.sh` does not replace
`bin/jcmp`: it prints a note when the new binary differs, and the copy is made by hand.

**Seed.** The first compiler was written in assembly. Its sources are in `seed/`, which is kept in the development
repository only and is frozen: no new features are added there. The bootstrap uses the seed, when it is present,
to compare the two compilers on the tests.

**Switches.** These are the switches of `jcmp` that concern the compiler's own stages (checked against the code of
`jcmp.jk`). Options marked *hidden* are not in `jcmp -help`.

| switch | effect |
|---|---|
| `-emit-asm FILE` | also writes the assembler text (the text the assembler reads) |
| `-show NAME` | writes the machine code of one function as it is in the program, and stops |
| `-irstat` | says which functions the IR could not handle, and why (`DEVELOPING.md`) |
| `-noir` | no IR: the text of the functions goes straight to the peephole and register passes |
| `-irtrip` | every liftable function is lifted and lowered again (tests the lifter) |
| `-noinl` | no inlining |
| `-novec` | no vectoriser |
| `-noregs` | no register pass (`jc_regs.j`) |
| `-nopeep` | no peephole pass |
| `-noalign` | no function alignment |
| `-nonullchk` | the null checks of array variables are all kept |
| `-nofma` | `a * b + c` is not fused into one instruction (the last bit of the result can differ) |
| `-noast` | every function is made by the text path (no tree) |
| `-noastmain` | `main` is made by the text path |
| `-ast`, `-xast`, `-xast2`, `-xastdump` | hidden: report the tree path (which functions, which nodes) |
| `-irdbg N` | hidden: internal debug bits for the passes (not documented on this page) |
| `-irclr N` | hidden: clears bits of the pass mask |
| `-irra`, `-iropt`, `-irpre`, `-iralways` | hidden: allocator on the IR, cleaning of the IR, text peephole before the lifter, every function written back |
| `-xtime` | hidden: prints the time of each stage |
| `-target arm32` | the ARM32 back end |
| `-d` | the debug build: array bounds checks and a memory leak report (ARM64 only) |

Several of the hidden switches are described only in the source of `jcmp/jcmp.jk` and the pass headers.

## 8. Diagram of one function

```
 text of f:   sub sp / str x0 ... / ldr x1, [x29,#16] / add x0, x1, x2 / ...
      |  lift (jc_lift.j): vregs 1..31 = x0..x30, 32..63 = d0..d31, 64+ temporaries
      v
 IR of f:     block 0: v1 = load [frame+16]; v3 = add v1, v2; ...  -> jmp 1
              block 1: br v3 < v4, block 2, block 3 ...
      |  passes (jc_opt.j): inline, value numbering, cell promotion, vectoriser, ...
      v
 IR of f:     (fewer instructions, some loops are vector loops)
      |  lower (jc_lift.j, lw_*): IR -> text
      v
 text of f:   the same kind of text as before, then the peephole and register passes
```
