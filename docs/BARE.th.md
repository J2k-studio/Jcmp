# โปรแกรมที่ไม่มีระบบปฏิบัติการ (โหมดดิบ)

โปรแกรมสำหรับบอร์ด เคอร์เนล หรือเครื่องจำลอง `jemu --system` ไม่มี OS อยู่ข้างใต้: ไม่มีใครเปิดไฟล์ แจกหน่วยความจำ พิมพ์ข้อความ หรือจบโปรแกรมให้ J2K เขียนโปรแกรมแบบนี้ได้ และ **ใช้คำเดิมได้เลย**: `jout`, `jin`, `alloc`, `arr`, `String`, `Arena` ทำงานบนเครื่องเปล่าเหมือนบน Linux โดยวางอยู่บนชั้นล่างเล็ก ๆ (ห้าการเรียก) ที่ `#target` ใส่ค่าปริยายให้ และคุณเขียนเองแทนได้ แกนของภาษาไม่รู้จัก OS และคอมไพเลอร์ไม่แอบเพิ่มการเรียกฟังก์ชัน การจองหน่วยความจำ หรือไลบรารีให้โปรแกรมที่ไม่ได้ใช้

บทนี้เป็นคู่มือโหมดดิบ คำสั่งแต่ละตัวอยู่ใน `LANGUAGE.md` (`#!library`, `naked`, `register { }`, `raw<>`, `interrupt`, `frame`) การตัดสินใจอยู่ใน `syntax-design.md` หัวข้อ 120

## 1. เจ็ดความลึก เลือกระดับที่ต้องการ

| ระดับ | สิ่งที่เขียน | ใช้เมื่อ |
|---|---|---|
| 1. โค้ดปกติ | `fn sum(int n) { ... }` | เกือบทุกอย่าง คอมไพเลอร์เขียนโค้ดเครื่องให้ |
| 2. ฮาร์ดแวร์ในโค้ดปกติ | `char uart @ 0x09000000;`, `Cpu::wait()`, `interrupt fnv timer() { }` | รีจิสเตอร์ของอุปกรณ์ รอ interrupt |
| 3. จุดเริ่มของโปรแกรม | `#target`, `#start` | เครื่องไม่มีโค้ดเริ่มต้น คอมไพเลอร์เขียนให้ |
| 4. คำสั่งเครื่องเขียนเหมือนกำหนดค่า | ฟังก์ชัน `naked` กับ `x0 = x0 + x1;` `ret;` | อยากเลือกรีจิสเตอร์เอง เช่น สลับ task, handler |
| 5. คำสั่งเดียวตามชื่อ | `Cpu::inst("adr", x0, label);` | คำสั่งที่ภาษาไม่มีคำให้ |
| 6. ไบต์ดิบ | `raw<u32>[0xd503201f, ...]` | ตารางเวกเตอร์ คำสั่งที่ assembler ไม่รู้จัก |
| 7. บรรทัดแอสเซมบลีตามที่เขียน | `asm { mov x0, 1  add x0, x0, x1  ret }` (ระดับไฟล์ก็ได้) | รู้คำสั่งและไม่อยากให้คอมไพเลอร์คั่น; `#!asm` ทั้งไฟล์วางแผนไว้ |

ระดับ 1–6 ไม่ต้องมีมาร์กเกอร์ที่หัวไฟล์: คำระดับต่ำเปิดอยู่ในทุกไฟล์ บรรทัด `#target` (ระดับ 3) หรือ `#!library` ทำให้ไฟล์เป็นไฟล์ดิบ คอมไพเลอร์ไม่ใส่โค้ดเริ่มต้นของ OS

## 2. โปรแกรมแรก

```jk-no
#target virt {
    entry 0x40000000;
    ram 0x40100000 1M;
    stack 64K;
    heap 64K;
    console 0x09000000;
    exit 0x09100000;
}
#import <os>

fn main() {
    Console::line("hello, machine");
    Console::num(6 * 7);
    Console::put(10);
    return 0;                       // เขียนลงอุปกรณ์ exit
}
```

คอมไพล์เหมือนโปรแกรมทั่วไป: `jcmp prog.jk -o prog.elf` ได้ไฟล์ ELF ที่ loader อ่าน (เครื่องจำลองของ Jaric: `jemu --system prog.elf`) ถ้าใส่ `format bin;` ในบล็อก `#target` ไฟล์จะเป็นแค่ไบต์ของโค้ด (ภาพ flash สำหรับบอร์ด)

คอมไพเลอร์เขียนโค้ดเริ่มต้นให้: ตั้งฐานของตัวแปร global และ stack ล้าง global เป็นศูนย์ เก็บค่าเริ่มต้นของ global เรียก `main` แล้วเขียนผลลัพธ์ของ `main` ลงอุปกรณ์ exit จากนั้น CPU หยุดรอ (`wfi`)

## 3. บรรทัด `#target`

วางไว้บนสุดของไฟล์

```
#target ชื่อ {
    entry ที่อยู่;          // ที่ที่ไฟล์ถูกโหลด เป็นพหุคูณของ 64K คำสั่งแรกคือ `b j2k_start`
    ram ที่อยู่ ขนาด;       // หน่วยความจำที่เขียนได้: global อยู่ต้น stack อยู่ปลาย
    stack ขนาด;            // ส่วนท้าย RAM ที่ stack ใช้ (ปริยาย 64K)
    heap ขนาด;             // ส่วนใต้ stack ที่ alloc, array, String ใช้ขอหน่วยความจำ (ปริยาย 0)
    console ที่อยู่;        // ไม่บังคับ: รีจิสเตอร์ไบต์ที่ jout เขียนลง
    input ที่อยู่;          // ไม่บังคับ: UART ที่ jin อ่าน (รีจิสเตอร์ข้อมูล แฟลกอยู่ที่ +0x18)
    exit ที่อยู่;           // ไม่บังคับ: รีจิสเตอร์ที่รับผลลัพธ์ของ main
    format elf;            // elf (ปริยาย) หรือ bin (ไบต์ของโค้ดอย่างเดียว)
}
```

ตัวเลขเป็นทศนิยม `0x40000000` (หรือ `0x4000_0000`) หรือมี `K` / `M` (`64K`, `1M`) หน้าตาของ RAM:

```
ต้น RAM    ตัวแปร global (โค้ดเริ่มต้นเก็บค่าเริ่มต้นให้)
           ... ว่าง ...
           heap   (TARGET_HEAP_SIZE ไบต์: alloc, array, String, Pool และ Heap ของ <os>)
           stack  (โตลงมาจากปลาย RAM)
ปลาย RAM
```

บล็อกนี้ให้ชื่อแก่โปรแกรม: `TARGET_ENTRY`, `TARGET_RAM`, `TARGET_RAM_SIZE`, `TARGET_STACK`, `TARGET_STACK_TOP`, `TARGET_HEAP_START`, `TARGET_HEAP_SIZE`, `TARGET_CONSOLE`, `TARGET_EXIT` คอมไพเลอร์หยุดพร้อมข้อความเมื่อไม่มี RAM, stack กับ heap ไม่พอดีกับ RAM, หรือ `entry` ไม่ใช่พหุคูณของ 64K ตัวเลขมาจากแผนที่หน่วยความจำของเครื่อง (data sheet ของบอร์ด)

`main` เป็นฟังก์ชันธรรมดาที่นี่ (คืนกลับไปที่โค้ดเริ่มต้น) ถ้าหารศูนย์ ดัชนีเกิน หรือฟังก์ชันที่ต้องคืนค่าจบโดยไม่คืน เครื่องจะจบด้วยรหัส 254, 253 หรือ 252 ที่อุปกรณ์ exit

## 4. `#start ชื่อ`: โปรแกรมเริ่มที่ไหน

```jk-no
#target virt { entry 0x40000000; ram 0x40100000 1M; stack 64K; console 0x09000000; exit 0x09100000; }
#start kernel_main

fnv kernel_main() {
    Console::line("started in kernel_main");
}
```

`#start` ระบุฟังก์ชันที่ทำงานก่อน (ปริยาย: `main`) ในโปรแกรม `#target` โค้ดเริ่มต้นเรียกมัน ฟังก์ชันที่ไม่คืนค่าจบเครื่องด้วย 0 ในไฟล์ดิบที่ไม่มี `#target` (`#!library`) `#start ชื่อ` ทำให้คำสั่งแรกเป็น `b ชื่อ` ลำดับฟังก์ชันในไฟล์จึงไม่สำคัญ (ถ้าไม่มี คำสั่งแรกของฟังก์ชันแรกคือจุดเริ่ม) ชื่อที่ไม่มีในโปรแกรมเป็นข้อผิดพลาด

## 5. ตัวแปรที่อยู่ที่ที่อยู่ที่กำหนด: รีจิสเตอร์ของฮาร์ดแวร์

```jk-no
#target virt { entry 0x40000000; ram 0x40100000 1M; console 0x09000000; exit 0x09100000; }
int status @ 0x09200000;           // รีจิสเตอร์ 32 บิตของอุปกรณ์
char data @ TARGET_CONSOLE;        // รีจิสเตอร์ 1 ไบต์

fn main() {
    data = 'A';                    // เขียนหนึ่งครั้ง
    status |= 1 << 3;              // อ่านหนึ่งครั้ง เขียนหนึ่งครั้ง
    while (status & 1) == 0 { }    // อ่านใหม่ทุกรอบ (รออุปกรณ์ตั้งบิต 0)
    return 0;
}
```

`ชนิด ชื่อ @ ที่อยู่;` วางตัวแปรที่ที่อยู่ที่กำหนด ไม่กินที่ในพื้นที่ global ความกว้างของชนิดคือความกว้างของการเข้าถึง: `char` 8 บิต `i16` 16 `int` 32 `i64` 64 (พอยน์เตอร์และ bool ด้วย) **ทุกการอ่านและทุกการเขียนในโค้ดคือการเข้าถึงหนึ่งครั้งตามลำดับ**: คอมไพเลอร์ไม่รวมการอ่านสองครั้ง ไม่ตัดทิ้ง ไม่ย้ายข้ามกัน ไม่ทำซ้ำ (การเข้าถึงเป็นคำสั่ง `ldar` / `stlr` ที่ไม่มีขั้นตอนไหนของคอมไพเลอร์แก้) ที่อยู่ต้องเป็นพหุคูณของขนาด ตัวแปรแบบนี้ไม่มีค่าเริ่มต้น และ float หรือ struct ที่ที่อยู่ที่กำหนดยังไม่ได้สร้าง

## 6. คำสั่งของ CPU

* `Cpu::irq_off()` / `Cpu::irq_on()` (interrupt ของแกนนี้), `Cpu::irq_state()` / `Cpu::irq_restore(s)` (เก็บสถานะก่อน `irq_off` แล้วคืนหลังจบ), `Cpu::read_sysreg(vbar_el1)` / `Cpu::write_sysreg(vbar_el1, ตาราง)` (รีจิสเตอร์เป็นคำ คอมไพเลอร์เขียน `mrs` / `msr`)
* `Cpu::wait()` (`wfi`), `Cpu::event()`, `Cpu::send_event()`, `Cpu::nop()`, `Cpu::isb()`, `Cpu::counter()` (ตัวนับของระบบ), `Cpu::id()` (หมายเลขแกน), `Cpu::speculation_barrier()`
* `Atomic::`, `Cache::` (clean, invalidate, prefetch) และ `Mem::barrier*()` อยู่ในไลบรารีแกน ไม่เรียกระบบ
* system register ของ CPU เป็นชื่อในปริภูมิ `Sys::`: `Sys::vbar_el1 = x0;` เขียนรีจิสเตอร์ `VBAR_EL1` (มี `elr_el1`, `spsr_el1`, `esr_el1`, `far_el1`, `sp_el0`, `daif`, `mair_el1` ... และรูปทั่วไป `s3_0_c12_c0_0`) ใช้เป็นคำสั่งในฟังก์ชัน `naked` หรือบล็อก `register { }`
* `interrupt fnv timer() { }`: handler ที่เซฟ `x0` .. `x18` และจบด้วย `eret` ตารางเวกเตอร์เป็นฟังก์ชัน `naked` ที่คุณเขียน (16 ช่อง ช่องละ 128 ไบต์ `align(2048)`) เคอร์เนล K1–K7 ของ Jaric (`os/kernel`) แสดงเส้นทางทั้งหมด: exception, timer, MMU, task, โปรแกรมผู้ใช้, ดิสก์

## 7. ระดับ 4 ถึง 6: เลือกรีจิสเตอร์เอง

```jk-no
#target virt { entry 0x40000000; ram 0x40100000 1M; stack 64K; console 0x09000000; exit 0x09100000; }
#start kernel_main

naked i64 add_fast(i64 a, i64 b) {      // อาร์กิวเมนต์คือ x0 กับ x1 ผลลัพธ์ใส่ใน x0
    x0 = x0 + x1;
    x0 = x0 << 1;
    ret;
}

fnv kernel_main() {
    Console::num(add_fast(20, 1));       // (20 + 1) * 2 = 42
    Console::put(10);
}
```

ฟังก์ชัน `naked` ไม่มีเฟรมและไม่มีโค้ดต้น/ท้ายที่คอมไพเลอร์เขียน: คุณเขียน `ret` เอง ข้างในเขียนรีจิสเตอร์ `x0` .. `x30` เป็นชื่อ และคำสั่งอ่านเหมือนการกำหนดค่า `Cpu::inst("ชื่อ", ตัวถูกดำเนินการ...)` เขียนหนึ่งคำสั่งตามชื่อ และ `raw<u32>[0x...]` เขียนคำของเครื่อง รายการเต็มอยู่ใน `LANGUAGE.md` (บล็อก `register { }` กับ `in` / `out`, `frame Context`, `@no_reorder`, `align(N)`)

## 7b. `asm { }`: บรรทัดแอสเซมบลีตามที่เขียน

```jk-no
naked i64 countdown(i64 n) {           // ผลรวม n + (n - 1) + ... + 1
    asm {
        mov x1, 0
    again:
        add x1, x1, x0
        subs x0, x0, #1
        b.ne again
        mov x0, x1
        ret
    }
}
```

ทุกบรรทัด (หรือทุกส่วนระหว่าง `;`) ในบล็อกส่งให้ assembler ตามที่เขียน `//` เริ่มคอมเมนต์ ป้ายกำกับเขียน `ชื่อ:` วงเล็บปีกกาในบรรทัด (`{v0.4s}`) นับคู่ บล็อกอยู่ในฟังก์ชันได้ (ดีที่สุดคือ `naked` เพราะคอมไพเลอร์ไม่มีรีจิสเตอร์ของตัวเองในนั้น) หรืออยู่ระหว่างฟังก์ชัน (ตารางเวกเตอร์: `asm { .align 11 ... }`) ไฟล์ที่มีแต่บล็อก `asm { }` เป็นโปรแกรมสมบูรณ์ที่ไม่มีรันไทม์เลย:

```jk-no
#!library
asm {
    mov x0, 7
    mov x8, 93
    svc 0
}
```

ในฟังก์ชันธรรมดาให้ใช้เฉพาะ `x0` .. `x15` และอย่าแตะ `sp`, `x28`, `x29` (คอมไพเลอร์เก็บตัวแปรไว้ตรงนั้น) assembler รู้จักคำสั่งที่คอมไพเลอร์เขียนเอง (ประมาณ 190 ชื่อ) คำสั่งที่ไม่รู้จักเป็น error ที่ระบุบรรทัด และ `raw<u32>[...]` ใช้ใส่คำของเครื่องแทนได้

## 8. ชั้นต่าง ๆ: ภาษาทำอะไร คุณเขียนอะไรได้ และ `<os>`

โปรแกรม `#target` เป็นโปรแกรมธรรมดา: **`jout`, `jin`, `alloc` / `free` / `alloc<int n>(50)`, array แบบ dynamic (`arr`, `push`), `String` และ `Arena` ใช้ได้** เหมือนบน Linux และซอร์สเดียวกันรันได้ทั้งสองที่ ข้างใต้เป็นชั้นล่างห้าการเรียกที่รันไทม์ใช้: *ขอก้อนหน่วยความจำ*, *เขียนไบต์*, *อ่านไบต์*, *คืนก้อน*, *จบ* `#target` ใส่ค่าปริยายให้แต่ละอย่าง (เส้น heap, รีจิสเตอร์ `console`, รีจิสเตอร์ `input`, ไม่ทำอะไร, รีจิสเตอร์ `exit`) **คุณเขียนชั้นล่างเองได้**: ฟังก์ชันของโปรแกรมที่ใช้ชื่อต่อไปนี้จะแทนค่าปริยาย

```jk-no
char uart @ 0x09000000;

fn os_write(i64 file, char^ buffer, i64 count) {      // jout, jerr และข้อความ panic จบที่นี่
    i64 i = 0;
    while i < count { uart = buffer[i]; i += 1; }
    return count;
}
```

| ฟังก์ชันที่เขียนได้ | ถูกเรียกเมื่อ | คืนค่า |
|---|---|---|
| `os_write(file, buffer, count)` | บัฟเฟอร์ของ `jout` / `jerr` ถูกเขียน | จำนวนไบต์ |
| `os_read(file, buffer, count)` | `jin` ต้องการไบต์ | จำนวนไบต์ (0 = จบ) |
| `os_map(address, length)` | heap ต้องการก้อนใหม่ | ที่อยู่ก้อนที่เป็นศูนย์ หรือเลขลบ |
| `os_unmap(address, length)` | คืนก้อนใหญ่ | 0 |
| `os_exit(code)` | โปรแกรมจบ | ไม่กลับ |

ฟังก์ชันเหล่านี้ห้ามใช้ `jout`, `jin`, `alloc`, `arr` เอง (เป็นชั้นใต้สิ่งเหล่านั้น) เป็นที่สำหรับไดรเวอร์ของคุณ (UART ที่มีแฟลกพร้อม ตัวจัดการหน่วยความจำของคุณเอง บันทึกลง flash)

**`#import <os>` คือชั้นบน**: บริการที่ใช้แทน `jout` และ `alloc` ได้โดยไม่มีอะไรอยู่ข้างใต้: `Console` (`put`, `print`, `line`, `num`, `hex` ไปรีจิสเตอร์ console), `Heap` (`alloc` / `free` จากช่วงที่คุณให้), `Pool` (แจกต่อกัน คืนทีเดียว) เรียกส่วนด้วยชื่อ (`Console::line("x")`) หรือเขียน `using Console;` แล้วเรียกโดยไม่ใส่ชื่อ (`line("x")`)

| ที่เขียน | ผลลัพธ์ |
|---|---|
| thread | error ที่ระบุชื่อฟังก์ชัน: เครื่องมีแกนเดียวและไม่มีตัวจัดคิว (เขียน task ในเคอร์เนล ดู `examples/os` ของ Jaric) |
| ไม่มี `main` (หรือชื่อของ `#start`) | error: โปรแกรม #target ต้องมีฟังก์ชัน main |
| stack กับ heap ไม่พอดี RAM | error พร้อมขนาด |
| `jin` โดยไม่มีบรรทัด `input` | ไม่อ่านอะไร (จบอินพุตทันที) |
| heap เต็ม | รันไทม์ panic "out of memory" (ข้อความไปที่ `os_write`) |

ไฟล์ เครือข่าย นาฬิกา และ `Env` เป็นการเรียก OS: ตอบว่า "ไม่มี" (ชั้นล่างไม่มี) array ขนาดคงที่ struct พอยน์เตอร์ ลูป การเรียกซ้ำ ทศนิยม `switch` เมธอด และทั้งแกนของภาษาใช้ได้

## 10. การทดสอบ

โปรแกรม `#target` ทดสอบในเครื่องจำลองก่อนขึ้นบอร์ด: `jemu --system prog.elf` โหลดไฟล์ ELF รันบนเครื่องของ Jaric (UART ที่ `0x09000000` อุปกรณ์ exit ที่ `0x09100000` RAM ตั้งแต่ `0x40000000`) รหัสออกคือผลของ `main` เทสต์ `K0`, `K0b` ... `K7` ของ Jaric (`os/kernel/test.sh`) รันแบบนี้ บอร์ดจริงต้องใส่ตัวเลขจากแผนที่หน่วยความจำของบอร์ดในบล็อก `#target` และ `format bin;`

คอมไพเลอร์สร้างโค้ด ARM64 ให้โปรแกรมเหล่านี้ เป้าหมาย ARM32 / Thumb-2 ของบอร์ดและ x86_64 จะมาทีหลัง
