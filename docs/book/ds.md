## นับขั้น Big-O
**คืออะไร.** Big-O คือวิธีบอกว่าจำนวนขั้นตอนของโปรแกรมเพิ่มขึ้นเท่าใดเมื่อข้อมูลใหญ่ขึ้น เราไม่วัดด้วยนาฬิกาแต่นับขั้นตอน และตัดตัวคูณเล็ก ๆ กับพจน์ที่เล็กทิ้ง O(n) หมายถึงขั้นตอนโตตามจำนวนข้อมูล O(log n) หมายถึงโตช้ามาก เพราะแบ่งครึ่งทุกรอบ O(n^2) หมายถึงลูปซ้อนสองชั้น
**ทำไมต้องรู้.** เครื่องแต่ละเครื่องเร็วไม่เท่ากัน แต่การเพิ่มขึ้นของขั้นตอนไม่เปลี่ยน ถ้าข้อมูลมีหนึ่งล้านแถว โปรแกรม O(n^2) จะทำงานล้านล้านขั้น ซึ่งไม่มีทางรอไหว ดังนั้นการเลือกอัลกอริทึมสำคัญกว่าการซื้อเครื่องที่เร็วขึ้น
**ทำอย่างไร.**

ดูจำนวนลูปที่ซ้อนกันและลูปที่ทำงานขึ้นกับ n อย่างไร ลูปเดียวที่วนทุกตัวคือ O(n) ลูปสองชั้นที่วนทุกคู่คือ O(n^2) ถ้าทุกรอบตัดข้อมูลครึ่งหนึ่งคือ O(log n)
```jk
int n = 8;
int steps = 0;
for i in 0..n {
    for j in 0..n { steps += 1; }
}
jout << steps << "\n";
```
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    int n = 16;
    for t in 0..3 {
        int linear = n;
        int halving = 0;
        int m = n;
        while m > 1 {
            m = m / 2;
            halving += 1;
        }
        jout << "n " << n << " linear " << linear << " halving " << halving << "\n";
        n = n * 16;
    }
}
```

```
n 16 linear 16 halving 4
n 256 linear 256 halving 8
n 4096 linear 4096 halving 12
```

> **ระวัง:** ข้อผิดพลาดที่พบบ่อยคือคิดว่า O(n) เร็วกว่า O(n^2) เฉพาะกับข้อมูลเล็ก ๆ เท่านั้น จริงแล้วเมื่อข้อมูลโตขึ้น ความต่างจะมากขึ้นเรื่อย ๆ ลองเพิ่ม n แล้วนับขั้นตอนดู
**แบบฝึกหัด**
- ลูปเดียวที่วนทุกตัวของข้อมูล n ตัวเป็น Big-O อะไร
  - a) O(n)  b) O(n^2)  c) O(1)  — เฉลย: a. ลูปเดียวทำงาน n รอบ จึงโตตามจำนวนข้อมูลโดยตรง
- O(log n) โตเร็วกว่า O(n) เมื่อ n ใหญ่ — เฉลย: f. O(log n) โตช้ากว่ามาก เพราะแบ่งครึ่งทุกรอบ ส่วน O(n) โตตามจำนวนข้อมูลโดยตรง
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int n = 4;
int steps = 0;
for i in 0..n {
    for j in 0..n { steps += 1; }
}
jout << steps << "\n";
}
```
  ผลลัพธ์ที่ได้: `16`. ลูปซ้อนสองชั้นที่แต่ละชั้นวน n รอบ ทำงานทั้งหมด n คูณ n รอบ คือ 16
- ลูปที่แบ่งข้อมูลครึ่งหนึ่งทุกรอบ เวลาจะโตแบบ O(log ___) — เฉลย: **n**. log n หมายถึงลอการิทึมของจำนวนข้อมูล
- การหา Big-O ของโปรแกรมหนึ่ง: ดูจำนวนลูปที่ซ้อนกัน → ดูว่าแต่ละลูปวนตามอะไร → รวมจำนวนรอบ → ตัดตัวคูณและพจน์เล็ก. ต้องดูโครงสร้างก่อนแล้วนับ แล้วจึงตัดส่วนที่ไม่ทำให้ภาพรวมเปลี่ยน
- ถ้าข้อมูลเพิ่มเป็น 10 เท่า โปรแกรม O(n^2) จะทำงานเพิ่มกี่เท่า
  - a) 100 เท่า  b) 10 เท่า  c) 20 เท่า  — เฉลย: a. n เพิ่ม 10 เท่า n คูณ n จึงเพิ่มเป็น 100 เท่า
**โจทย์**
- **นับคู่** — วนลูปซ้อน n = 8 ทุกคู่ (i, j) แล้วนับจำนวนรอบ พิมพ์ pairs 64. ผลลัพธ์ที่ได้: `pairs 64`. คำใบ้: ใช้ลูปซ้อนสองชั้นที่วน 0..n ทั้งคู่
- **นับการหารครึ่ง** — เริ่มที่ 1024 แบ่งครึ่งด้วยการหาร 2 จนเหลือ 1 แล้วนับจำนวนครั้ง พิมพ์ halvings 10. ผลลัพธ์ที่ได้: `halvings 10`. คำใบ้: ใช้ while m > 1 แล้วนับทีละหนึ่ง

## อาเรย์และลิสต์
**คืออะไร.** อาเรย์เก็บข้อมูลติดกันในหน่วยความจำ อ่านค่าที่ตำแหน่ง i ได้ทันทีใน O(1) แต่การแทรกตรงกลางต้องเลื่อนข้อมูลหลังจากนั้น ลิสต์ในภาษา J2K คืออาเรย์ที่ยืดได้ด้วย push และ pop เอาค่าท้ายออก การเพิ่มท้ายจึงทำได้เร็วโดยเฉลี่ย O(1)
**ทำไมต้องรู้.** เกือบทุกโครงสร้างข้อมูลถูกสร้างบนอาเรย์ เมื่อคุณรู้ว่าการอ่านการเขียนที่ตำแหน่งต่างกันมีค่าใช้จ่ายเท่าใด คุณจะเลือกโครงสร้างที่เหมาะกับงานได้
**ทำอย่างไร.**

ใช้ int[] list = arr(n) แล้ว push เพื่อเพิ่มท้าย pop เพื่อเอาค่าท้ายออก และ list.len เป็นจำนวนสมาชิก
```jk
int[] list = arr(4);
list.push(10);
list.push(20);
list.pop();
jout << list.len << "\n";
```
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    int[] list = arr(4);
    for i in 1..6 { list.push(i * i); }
    jout << "len " << list.len << "\n";
    jout << "first " << list[0] << " last " << list[list.len - 1] << "\n";
    list.pop();
    jout << "after pop " << list.len << "\n";
}
```

```
len 5
first 1 last 25
after pop 4
```

> **ระวัง:** การอ่านด้วยดัชนีเกินความยาว เช่น list[list.len] ใช้ไม่ได้ เพราะช่องสุดท้ายคือ len - 1 ใช้ -d เพื่อให้โปรแกรมตรวจขอบตอนรัน
**แบบฝึกหัด**
- การอ่านค่าที่ตำแหน่ง i ของอาเรย์ใช้เวลาเท่าใด
  - a) O(1)  b) O(n)  c) O(n^2)  — เฉลย: a. อาเรย์คำนวณตำแหน่งจาก i ได้ตรงทันที จึงไม่ต้องเดินผ่านข้อมูล
- การแทรกค่าตรงกลางอาเรย์ไม่ต้องย้ายข้อมูลใด ๆ — เฉลย: f. ต้องเลื่อนข้อมูลตั้งแต่ตำแหน่งที่แทรกจนถึงท้ายไปทางขวา
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int[] a = arr(2);
a.push(3);
a.push(4);
a.pop();
jout << a.len << "\n";
}
```
  ผลลัพธ์ที่ได้: `1`. push สองครั้งได้สองค่า pop เอาหนึ่งค่าออก เหลือหนึ่ง
- การเพิ่มค่าท้ายลิสต์ในภาษา J2K ใช้เมธอด ___ — เฉลย: **push**. push เพิ่มค่าไว้ท้ายสุด
- การเพิ่มค่าสามตัวแล้วลบค่าท้ายหนึ่งตัว: สร้าง arr ว่าง → push ค่าที่หนึ่ง สอง สาม → pop หนึ่งครั้ง → ตรวจ len ได้ 2. ต้องเพิ่มก่อนจึงลบได้
- ทำไมการแทรกที่หัวของอาเรย์ช้ากว่าการ push ท้าย
  - a) เพราะต้องเลื่อนทุกค่าไปทางขวาก่อน  b) เพราะ push ทำงานกับหัว  c) เพราะอาเรย์ไม่รับค่า  — เฉลย: a. การแทรกที่หัวต้องย้ายทุกค่า ทำให้เป็น O(n) แต่ push ท้ายเฉลี่ย O(1)
**โจทย์**
- **ความยาว** — สร้าง list ด้วย arr แล้ว push ห้าค่า พิมพ์ len 5. ผลลัพธ์ที่ได้: `len 5`. คำใบ้: ใช้ list.len
- **ผลรวมหลัง pop** — push ค่า 1 ถึง 5 แล้ว pop หนึ่งครั้ง พิมพ์ผลรวมของค่าที่เหลือ. ผลลัพธ์ที่ได้: `sum 10`. คำใบ้: ใช้ลูปรวมค่าทั้งหมดหลัง pop

## สแตก
**คืออะไร.** สแตก (stack) เป็นโครงสร้างแบบเข้าทีหลังออกก่อน (LIFO) ค่าที่ push เข้าล่าสุดจะถูก pop ออกก่อน ทั้ง push และ pop ทำในเวลาคงที่ O(1) สแตกใช้เป็นกลไกของการเรียกฟังก์ชัน และปุ่มย้อนกลับ
**ทำไมต้องรู้.** เมื่อโปรแกรมเรียกฟังก์ชันซ้อนกัน ระบบจำที่กลับของแต่ละชั้นด้วยสแตก ถ้าคุณเข้าใจสแตกคุณจะเข้าใจการ recursion และการตรวจวงเล็บที่ซ้อนกันได้
**ทำอย่างไร.**

เก็บสแตกในอาเรย์ และให้ push ใส่ท้าย pop เอาท้ายออก ระวังว่า pop กับสแตกว่างจะให้ผลผิด ต้องเช็กว่ามีสมาชิกก่อน
```jk
int[] st = arr(8);
st.push(1);
st.push(2);
jout << st[st.len - 1] << "\n";
```
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

int[] st;

void push(int x) { st.push(x); }

int pop() {
    int x = st[st.len - 1];
    st.pop();
    return x;
}

void main() {
    st = arr(8);
    push(1); push(2); push(3);
    jout << pop() << " " << pop() << "\n";
    push(9);
    jout << pop() << " " << st.len << "\n";
}
```

```
3 2
9 1
```

> **ระวัง:** การ pop จากสแตกว่างจะให้ค่าขยะหรือข้อผิดพลาด ให้ตรวจ len == 0 ก่อนทุกครั้ง
**แบบฝึกหัด**
- ถ้า push 1, 2, 3 แล้ว pop ค่าแรกที่ออกคือเท่าใด
  - a) 3  b) 1  c) 2  — เฉลย: a. สแตกเป็น LIFO ค่าที่เข้าท้ายสุดจะออกก่อน
- สแตกให้ค่าออกตามลำดับที่เข้าก่อนออกก่อน — เฉลย: f. นั่นคือคิว สแตกเป็นแบบเข้าทีหลังออกก่อน
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

int[] st;

void main() {
st = arr(4);
st.push(5);
st.push(6);
st.pop();
jout << st[st.len - 1] << "\n";
}
```
  ผลลัพธ์ที่ได้: `5`. หลัง push 5 และ 6 แล้ว pop เอา 6 ออก ค่าบนสุดคือ 5
- การเข้าทีหลังออกก่อนเรียกว่า LIFO ซึ่งย่อมาจาก last in, first ___ — เฉลย: **out**. last in, first out คือเข้าท้ายสุด ออกก่อน
- การตรวจว่าวงเล็บ ( ปิดถูกต้อง: เจอ ( แล้ว push → เจอ ) แล้ว pop → ตรวจว่าคู่กัน → สแตกว่างเมื่อจบ. ทุกวงเล็บเปิดต้องมีคู่ที่ปิดตามหลังโดยเรียงกลับทาง
- การเรียกฟังก์ชันซ้อนกันใช้สแตกทำอะไร
  - a) จำที่กลับของแต่ละฟังก์ชัน  b) เก็บรูปภาพ  c) ย้ายไฟล์  — เฉลย: a. ระบบจำจุดกลับของแต่ละการเรียกไว้ในสแตก เมื่อฟังก์ชันจบจึงกลับไปจุดเดิม
**โจทย์**
- **สแตกเลข** — push 1, 2, 3 แล้วพิมพ์ค่าที่ pop ได้สองครั้งเป็น 3 2. ผลลัพธ์ที่ได้: `3 2`. คำใบ้: ใช้ pop สองครั้งในบรรทัดเดียว
- **ตรวจวงเล็บ** — ตรวจว่าข้อความ "(a[b])" มีวงเล็บสมดุลหรือไม่ แล้วพิมพ์ balanced yes. ผลลัพธ์ที่ได้: `balanced yes`. คำใบ้: ใช้สแตกเก็บวงเล็บเปิด และ pop เมื่อเจอวงเล็บปิด

## คิวและ ring buffer
**คืออะไร.** คิว (queue) เป็นแบบเข้าก่อนออกก่อน (FIFO) เช่นคนเข้าแถว ring buffer คือคิวที่เก็บในอาเรย์ขนาดคงที่ โดยมี head และ tail เลื่อนไปข้างหน้าและวนกลับเมื่อถึงท้ายอาเรย์ จึงไม่ต้องย้ายข้อมูลเลย
**ทำไมต้องรู้.** ระบบจริงใช้คิวทุกที่ เช่น การรับข้อมูลจากคีย์บอร์ด การส่งแพ็กเก็ต และเสียง ถ้าคิวเต็มต้องมีการตัดสินใจ คือรอหรือทิ้ง ring buffer บอกชัดว่าความจุคือเท่าใด
**ทำอย่างไร.**

ตำแหน่งช่องว่างถัดไปคือ (head + count) % cap เมื่อเอาออกให้ head เลื่อนไปข้างหน้าด้วย % เช่นกัน
```jk
int cap = 3;
int head = 0;
int count = 0;
int[] buf = arr(cap);
buf.push(0); buf.push(0); buf.push(0);
```
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

int[] buf;
int head = 0;
int count = 0;
int cap = 4;

bool enqueue(int x) {
    if count == cap { return false; }
    buf[(head + count) % cap] = x;
    count += 1;
    return true;
}

int dequeue() {
    int x = buf[head];
    head = (head + 1) % cap;
    count -= 1;
    return x;
}

void main() {
    buf = arr(cap);
    for i in 0..cap { buf.push(0); }
    for i in 1..6 { jout << enqueue(i * 10) << " "; }
    jout << "\n";
    jout << dequeue() << " " << dequeue() << "\n";
}
```

```
true true true true false 
10 20
```

> **ระวัง:** คิวที่เต็มแล้วยังรับค่าเพิ่มจะเขียนทับข้อมูลเก่า ถ้าไม่เช็ก count == cap ก่อน ให้ตรวจเงื่อนไขนี้เสมอ
**แบบฝึกหัด**
- ข้อใดเป็นลำดับของคิว
  - a) เข้าก่อนออกก่อน  b) เข้าทีหลังออกก่อน  c) สุ่ม  — เฉลย: a. คิวให้ค่าตามลำดับที่เข้า เหมือนคนเข้าแถว
- ring buffer ต้องย้ายข้อมูลทุกครั้งที่เอาค่าออก — เฉลย: f. ring buffer เลื่อนตำแหน่ง head แทนการย้ายข้อมูล
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

int[] buf;
int head = 0;
int cap = 3;

void main() {
buf = arr(cap);
buf.push(1); buf.push(2); buf.push(3);
head = (head + 1) % cap;
jout << buf[head] << "\n";
}
```
  ผลลัพธ์ที่ได้: `2`. head เลื่อนจาก 0 ไป 1 และอ่าน buf[1] ซึ่งเป็น 2
- เมื่อถึงท้ายอาเรย์ ring buffer จะวนกลับมาที่ ___ โดยใช้ % — เฉลย: **head**. ตำแหน่ง head วนกลับไปที่ศูนย์เมื่อถึงความจุ
- การเอาค่าหนึ่งค่าออกจาก ring buffer: อ่านค่าที่ head → เลื่อน head ด้วย % → ลด count → คืนค่าที่อ่านได้. ต้องอ่านก่อนเลื่อน ไม่เช่นนั้นจะได้ค่าถัดไป
- คิวเต็มควรทำอย่างไร
  - a) บอกว่าเต็มและไม่รับค่า  b) เขียนทับค่าเก่า  c) ลบคิวทั้งหมด  — เฉลย: a. การเขียนทับทำให้ข้อมูลหาย การบอกว่าเต็มทำให้รู้ว่าต้องรอ
**โจทย์**
- **คิวสองค่า** — ใน ring buffer ขนาด 3 enqueue 1, 2, 3 แล้ว dequeue ค่าแรกและพิมพ์ 1. ผลลัพธ์ที่ได้: `1`. คำใบ้: ใช้ head ที่เลื่อนได้
- **คิวใช้ซ้ำ** — ใน ring buffer ขนาด 3 enqueue 1, 2, 3 dequeue ค่าแรก enqueue 4 แล้ว dequeue สองครั้งพิมพ์ 2 3. ผลลัพธ์ที่ได้: `2 3`. คำใบ้: ช่องที่ว่างถูกใช้ซ้ำโดย % ของ cap

## ตารางแฮช
**คืออะไร.** ตารางแฮช (hash table) หาค่าจากคีย์ได้เกือบทันที โดยฟังก์ชันแฮชแปลงคีย์เป็นตำแหน่งในอาเรย์ เมื่อสองคีย์ได้ตำแหน่งเดียวกันเรียกว่าการชน (collision) วิธี open addressing จะลองตำแหน่งถัดไป ภาษาให้ Map<K, V> ที่ทำงานนี้ให้แล้ว
**ทำไมต้องรู้.** ค่าที่ค้นด้วยชื่อ เช่นผู้ใช้หรือคำในพจนานุกรม ต้องหาเร็ว การค้นทีละตัวในอาเรย์ใหญ่ช้าเกินไป ตารางแฮชเป็นวิธีที่ใช้ในฐานข้อมูลและภาษาเกือบทุกภาษา
**ทำอย่างไร.**

ใช้ Map<String, int> แล้ว put เพื่อเก็บ get เพื่ออ่าน และ has เพื่อเช็กว่ามีคีย์ไหม
```jk
Map<String, int> ages;
ages.put("ann", 31);
if ages.has("ann") { jout << ages.get("ann") << "\n"; }
```
**ตัวอย่าง.**

```jk
#import <stdlib>

void main() {
    Map<String, int> ages;
    ages.put("ann", 31);
    ages.put("bob", 25);
    ages.put("ann", 32);

    if ages.has("zed") { jout << "zed found\n"; } else { jout << "zed not found\n"; }
```

**แบบฝึกหัด**
- ตารางแฮชหาค่าจากคีย์โดยประมาณกี่ขั้น
  - a) ประมาณหนึ่งขั้น  b) ตามจำนวนข้อมูลทั้งหมด  c) สองเท่า  — เฉลย: a. ฟังก์ชันแฮชคำนวณตำแหน่งจากคีย์โดยตรง ถ้าไม่มีการชนมาก
- put ด้วยคีย์เดิมจะเพิ่มค่าซ้ำให้เห็นเป็นสองรายการ — เฉลย: f. Map เก็บคีย์หนึ่งครั้ง put คีย์เดิมจะเขียนค่าใหม่ทับค่าเก่า
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>

void main() {
Map<String, int> m;
m.put("x", 1);
m.put("x", 7);
jout << m.get("x") << " " << m.len << "\n";

```
  ผลลัพธ์ที่ได้: `7 1`. คีย์ x ถูกเขียนทับเป็น 7 และมีเพียงหนึ่งคีย์
- เมธอดที่เช็กว่ามีคีย์ใน Map หรือไม่คือ ___ — เฉลย: **has**. has คืน true หรือ false
- การใช้ Map อย่างปลอดภัย: put คีย์และค่า → has ตรวจว่ามีคีย์ → get ถ้ามี → ทำอย่างอื่นถ้าไม่มี. ต้องตรวจก่อนอ่าน ไม่เช่นนั้นโปรแกรมจะล้มเหลวเมื่อไม่พบ
- ทำไมการชนของแฮชทำให้ช้าลง
  - a) ต้องลองหลายตำแหน่งกว่าจะหาเจอหรือพบช่องว่าง  b) เพราะต้องคูณคีย์  c) เพราะข้อมูลถูกลบ  — เฉลย: a. เมื่อชนกันจะต้องเดินหาช่องถัดไป ถ้าตารางเต็มมากการค้นจะช้า
**โจทย์**
- **เก็บค่า** — สร้าง Map<String, int> แล้ว put "a" 1, put "b" 2, put "a" 5 แล้วพิมพ์ค่าของ a เป็น a 5. ผลลัพธ์ที่ได้: `a 5`. คำใบ้: put คีย์เดิมจะเขียนทับค่า
- **นับจำนวนคีย์** — put คีย์ x, y, z แล้วพิมพ์ keys 3 จาก len ของ Map. ผลลัพธ์ที่ได้: `keys 3`. คำใบ้: ใช้ .len ของ Map

## การค้นแบบแบ่งครึ่ง
**คืออะไร.** การค้นแบบแบ่งครึ่ง (binary search) ใช้กับอาเรย์ที่เรียงแล้ว ดูตรงกลาง ถ้าค่าที่หาน้อยกว่าให้ตัดครึ่งขวาทิ้ง ถ้ามากกว่าให้ตัดครึ่งซ้ายทิ้ง ทุกรอบข้อมูลลดครึ่ง จึงใช้ประมาณ log n ขั้น
**ทำไมต้องรู้.** ข้อมูลหนึ่งล้านรายการใช้เพียง 20 ขั้น ถ้าค้นทีละตัวต้องดูถึงหนึ่งล้านครั้ง ข้อมูลส่วนใหญ่ที่เรียงแล้วจึงค้นด้วยวิธีนี้
**ทำอย่างไร.**

กำหนด lo และ hi เป็นขอบของช่วง คำนวณ mid แล้วเปรียบเทียบ ทำซ้ำจนพบค่า หรือจนช่วงว่าง
```jk
#import <stdlib>
using stdlib;

void main() {
    int[] a = arr(4);
    a.push(1); a.push(3); a.push(5); a.push(7);
    int lo = 0;
    int hi = a.len - 1;
    int mid = (lo + hi) / 2;
    jout << mid << "\n";
}
```
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

int find(int[] a, int x) {
    int lo = 0;
    int hi = a.len - 1;
    while lo <= hi {
        int mid = (lo + hi) / 2;
        if a[mid] == x { return mid; }
        if a[mid] < x { lo = mid + 1; } else { hi = mid - 1; }
    }
    return 0 - 1;
}

void main() {
    int[] a = arr(8);
    for i in 0..8 { a.push(i * 3); }
    jout << find(a, 9) << " " << find(a, 10) << " " << find(a, 21) << "\n";
}
```

```
3 -1 7
```

> **ระวัง:** อาเรย์ต้องเรียงแล้วเท่านั้น ถ้าไม่เรียง ผลลัพธ์จะผิดโดยไม่มีข้อความเตือน และตรวจขอบ hi = mid - 1 ให้ถูก มิฉะนั้นจะวนไม่จบ
**แบบฝึกหัด**
- การค้นแบบแบ่งครึ่งต้องมีเงื่อนไขอะไร
  - a) อาเรย์ต้องเรียงแล้ว  b) อาเรย์ต้องมีค่าเดียวกัน  c) อาเรย์ต้องยาวกว่า 100  — เฉลย: a. ถ้าไม่เรียง การเลือกครึ่งซ้ายหรือขวาจะผิด
- ข้อมูล 1,000,000 รายการค้นแบบแบ่งครึ่งได้ประมาณ 20 ขั้น — เฉลย: t. log2 ของหนึ่งล้านประมาณ 20
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int[] a = arr(5);
for i in 0..5 { a.push(i * 2); }
int lo = 0;
int hi = a.len - 1;
int mid = (lo + hi) / 2;
jout << a[mid] << "\n";
}
```
  ผลลัพธ์ที่ได้: `4`. a มี 0 2 4 6 8 ตรงกลางของ 0 ถึง 4 คือ 2 ซึ่งเป็นช่อง 2 ที่มีค่า 4
- ค่าตรงกลางของช่วงคำนวณด้วย (lo + hi) / ___ (เขียนเป็นคำอังกฤษ) — เฉลย: **two**. การหารด้วยสองหาค่ากลาง
- การค้นค่า 9 ในอาเรย์ที่เรียงแล้ว: ตั้ง lo และ hi → คำนวณ mid → ถ้าเจอคืนตำแหน่ง → ถ้าน้อยกว่าตัดซ้าย มากกว่าตัดขวา. ทำซ้ำจนเจอหรือช่วงว่าง
- ถ้าค้นค่าที่ไม่มี ฟังก์ชันคืนค่าเท่าใด
  - a) -1  b) 0  c) ค่าสุดท้าย  — เฉลย: a. -1 บอกว่าไม่พบ เพราะตำแหน่งจริงเป็นค่าบวก
**โจทย์**
- **ค้นค่า** — ในอาเรย์ 1, 3, 5, 7, 9, 11 ค้นค่า 9 แล้วพิมพ์ตำแหน่ง. ผลลัพธ์ที่ได้: `4`. คำใบ้: ใช้ binary search
- **ค้นไม่เจอ** — ค้นค่า 4 ในอาเรย์เดียวกันแล้วพิมพ์ผล. ผลลัพธ์ที่ได้: `-1`. คำใบ้: ตัวเลขที่ไม่มีต้องได้ -1

## การเรียงข้อมูลสองแบบ
**คืออะไร.** การเรียงแทรก (insertion sort) เลื่อนแต่ละค่าไปที่ที่ถูกต้องในส่วนที่เรียงแล้ว ใช้เวลา O(n^2) แต่เร็วกับข้อมูลน้อย การเรียงแบบผสาน (merge sort) แบ่งครึ่ง เรียงแต่ละครึ่ง แล้วรวมกัน ใช้เวลา O(n log n) เสมอ
**ทำไมต้องรู้.** การเรียงข้อมูลเป็นพื้นฐานของการค้นและการรายงาน ถ้าเข้าใจทั้งสองแบบ คุณจะเห็นว่าอัลกอริทึมเดียวกันให้ผลเดียวกันแต่ใช้เวลาต่างกันมากเมื่อข้อมูลใหญ่
**ทำอย่างไร.**

เรียงแทรก: ดึงค่าที่ i ออกมา แล้วเลื่อนค่าที่มากกว่าไปทางขวา แล้ววางค่านั้นลงช่องที่ว่าง
```jk
#import <stdlib>
using stdlib;

void main() {
    int[] a = arr(3);
    a.push(3); a.push(1); a.push(2);
    for i in 1..a.len {
        int x = a[i];
        int j = i - 1;
        while j >= 0 && a[j] > x {
            a[j + 1] = a[j];
            j -= 1;
        }
        a[j + 1] = x;
    }
    jout << a[0] << a[1] << a[2] << "\n";
}
```
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void insertion(int[] a) {
    for i in 1..a.len {
        int x = a[i];
        int j = i - 1;
        while j >= 0 {
            if a[j] <= x { break; }
            a[j + 1] = a[j];
            j -= 1;
        }
        a[j + 1] = x;
    }
}

void main() {
    int[] a = arr(4);
    a.push(5); a.push(2); a.push(4); a.push(1);
    insertion(a);
    for i in 0..a.len { jout << a[i] << "\n"; }
}
```

```
1
2
4
5
```

> **ระวัง:** ถ้าเปลี่ยนเงื่อนไขการเลื่อนผิด การเรียงจะไม่สมบูรณ์ เช่นลืมตรวจ j >= 0 แล้วอ่านดัชนี -1 ทำให้เกิดข้อผิดพลาด
**แบบฝึกหัด**
- เรียงแทรกมีเวลาโดยทั่วไปเท่าใด
  - a) O(n^2)  b) O(log n)  c) O(1)  — เฉลย: a. ต้องเปรียบเทียบและเลื่อนค่าจำนวนมากเมื่อข้อมูลใหญ่
- merge sort ใช้เวลา O(n log n) ในทุกกรณี — เฉลย: t. การแบ่งครึ่งและการรวมทำให้เวลาเป็น n log n เสมอ
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int[] a = arr(3);
a.push(3); a.push(1); a.push(2);
for i in 1..a.len {
    int x = a[i];
    int j = i - 1;
    while j >= 0 && a[j] > x {
        a[j + 1] = a[j];
        j -= 1;
    }
    a[j + 1] = x;
}
jout << a[0] << a[1] << a[2] << "\n";
}
```
  ผลลัพธ์ที่ได้: `123`. เรียงแทรกทำให้อาเรย์เป็น 1 2 3 แล้วพิมพ์ติดกัน
- การเรียงที่แบ่งครึ่งแล้วรวมกันเรียกว่า merge ___ — เฉลย: **sort**. merge sort คือการเรียงแบบผสาน
- การเรียงแบบผสาน: แบ่งอาเรย์เป็นสองครึ่ง → เรียงแต่ละครึ่งด้วยการเรียกตัวเอง → รวมสองครึ่งที่เรียงแล้ว → ได้ผลเรียงทั้งหมด. ต้องเรียงครึ่งก่อนจึงรวมได้ถูก
- เมื่อข้อมูลน้อยมาก เรียงแทรกอาจเร็วกว่าเพราะเหตุใด
  - a) ไม่ต้องใช้อาเรย์ใหม่และไม่ต้องเรียกซ้ำ  b) เพราะมันเรียกไม่ได้  c) เพราะมันข้ามค่า  — เฉลย: a. merge sort ต้องสร้างอาเรย์พักและเรียกซ้ำ ซึ่งมีค่าใช้จ่ายสำหรับข้อมูลน้อย
**โจทย์**
- **เรียงแทรก** — เรียง 4, 2, 5, 1 ด้วยเรียงแทรก แล้วพิมพ์ค่าเรียงกันเป็นบรรทัดละค่า. ผลลัพธ์ที่ได้: `1 / 2 / 4 / 5`. คำใบ้: ใช้ตัวอย่างในหัวข้อนี้
- **เรียงสามค่า** — เรียง 3, 1, 2 แล้วพิมพ์ค่าสุดท้ายที่ดัชนี 2. ผลลัพธ์ที่ได้: `3`. คำใบ้: หลังเรียงค่าสุดท้ายคือค่าที่มากที่สุด

## ต้นไม้ค้นหา
**คืออะไร.** ต้นไม้ค้นหาแบบทวิภาค (binary search tree) เก็บค่าที่เล็กกว่าไว้ทางซ้ายของโหนด และค่าที่ใหญ่กว่าไว้ทางขวา การค้นและการแทรกเดินลงทีละกิ่ง ถ้าต้นไม้สมดุลจะใช้ประมาณ log n ขั้น ถ้าเรียงค่าที่แทรกเป็นลำดับ ต้นไม้จะกลายเป็นเส้นตรง
**ทำไมต้องรู้.** ข้อมูลที่ต้องแทรกและค้นสลับกันตลอด เช่นดัชนีหรือตารางในระบบ ใช้ต้นไม้ค้นหาได้ดี การอ่านแบบ in-order จะได้ข้อมูลเรียงโดยไม่ต้องเรียงใหม่
**ทำอย่างไร.**

เก็บโหนดในอาเรย์ key, left, right และใช้ดัชนีเป็นตัวชี้ เมื่อแทรก ให้เดินจากราก ไปซ้ายถ้าเล็กกว่า ไปขวาถ้าใหญ่กว่า จนพบช่องว่าง
```jk
#import <stdlib>
using stdlib;

void main() {
    int[] key = arr(2);
    key.push(50); key.push(30);
    int k = 40;
    int cur = 0;
    if k < key[cur] { jout << "left\n"; } else { jout << "right\n"; }
}
```
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

int[] key;
int[] left;
int[] right;

int insert(int root, int k) {
    key.push(k); left.push(0 - 1); right.push(0 - 1);
    int id = key.len - 1;
    if root < 0 { return id; }
    int cur = root;
    while true {
        if k < key[cur] {
            if left[cur] < 0 { left[cur] = id; break; }
            cur = left[cur];
        } else {
            if right[cur] < 0 { right[cur] = id; break; }
            cur = right[cur];
        }
    }
    return root;
}

void inorder(int n) {
    if n < 0 { return; }
    inorder(left[n]);
    jout << key[n] << " ";
    inorder(right[n]);
}

void main() {
    key = arr(8); left = arr(8); right = arr(8);
    int root = 0 - 1;
    int[] data = arr(3);
    data.push(50); data.push(30); data.push(70);
    for i in 0..data.len { root = insert(root, data[i]); }
    inorder(root);
    jout << "\n";
}
```

```
30 50 70
```

> **ระวัง:** เมื่อแทรกค่าที่เรียงแล้วทีละค่า ต้นไม้จะเป็นเส้นตรง ทำให้การค้นช้าเท่ากับ O(n) ต้นไม้จริงมีการปรับสมดุลเพื่อกันเรื่องนี้
**แบบฝึกหัด**
- ค่าใดอยู่ทางซ้ายของโหนดที่มีค่า 10
  - a) ค่าที่น้อยกว่า 10  b) ค่าที่มากกว่า 10  c) ค่าทุกตัว  — เฉลย: a. กฎของต้นไม้ค้นหาคือซ้ายเล็กกว่า ขวาใหญ่กว่า
- การอ่านต้นไม้แบบ in-order จะได้ค่าเรียงจากน้อยไปมาก — เฉลย: t. ซ้าย โหนด ขวา ทำให้ค่าออกมาเรียงกันเสมอ
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int[] a = arr(3);
a.push(10); a.push(20); a.push(30);
jout << a[0] + a[2] << "\n";
}
```
  ผลลัพธ์ที่ได้: `40`. ค่าช่องแรกและช่องสุดท้ายคือ 10 และ 30 รวมได้ 40
- ค่าที่หาได้ในต้นไม้ค้นหาจะเปรียบเทียบเริ่มจาก ___ ของต้นไม้ — เฉลย: **root**. การค้นเริ่มจากรากแล้วเดินลง
- การแทรก 5 เข้าต้นไม้ที่มี 3 เป็นราก: เริ่มที่ราก 3 → 5 มากกว่า 3 ไปทางขวา → ถ้าว่างวางตรงนั้น → เสร็จ. ต้องเดินตามกฎจากราก
- ทำไมการแทรก 1 2 3 4 ทำให้ต้นไม้ช้า
  - a) ต้นไม้กลายเป็นเส้นตรง  b) เพราะตัวเลขเล็ก  c) เพราะไม่มีรากเลย  — เฉลย: a. ทุกค่าไปทางขวาทั้งหมด ทำให้ความสูงเท่าจำนวนข้อมูล
**โจทย์**
- **เรียงจากต้นไม้** — แทรก 50, 30, 70 ลงในต้นไม้ค้นหาแล้วพิมพ์ค่าแบบ in-order บรรทัดเดียวคั่นด้วยช่องว่างโดยไม่มีช่องท้าย. ผลลัพธ์ที่ได้: `30 50 70`. คำใบ้: ใช้ inorder ที่พิมพ์ค่าแล้วขึ้นบรรทัด
- **ความสูง** — แทรก 10, 20, 30 ลงต้นไม้แล้วพิมพ์ height 3 ถ้าความสูงของต้นไม้เป็น 3. ผลลัพธ์ที่ได้: `height 3`. คำใบ้: ต้นไม้เส้นตรงสามโหนดมีความสูงสาม

## ฮีป (heap)
**คืออะไร.** ฮีปแบบค่าต่ำสุด (min-heap) เป็นต้นไม้สมบูรณ์ที่โหนดแม่มีค่าน้อยกว่าลูกเสมอ ค่าต่ำสุดจึงอยู่ที่รากเสมอ การ push และ pop ใช้เวลา O(log n) เก็บในอาเรย์ได้ โดยลูกของ i คือ 2i+1 และ 2i+2
**ทำไมต้องรู้.** คิวความสำคัญต้องการดึงรายการสำคัญที่สุดได้เร็ว เช่นงานที่ควรทำก่อนในระบบ หรือเส้นทางที่สั้นที่สุดในกราฟ ฮีปทำให้ทำได้ทุกครั้งในเวลา log n
**ทำอย่างไร.**

push ใส่ค่าท้ายอาเรย์แล้ว sift up คือสลับกับแม่ถ้าน้อยกว่า pop เอาค่าที่รากออก เอาค่าท้ายมาไว้ที่ราก แล้ว sift down คือสลับกับลูกที่เล็กที่สุดจนเสร็จ
```jk
#import <stdlib>
using stdlib;

void main() {
    int[] h = arr(2);
    h.push(1); h.push(5);
    if h[1] < h[0] { jout << "swap\n"; } else { jout << "keep\n"; }
}
```
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

int[] h;

void push(int x) {
    h.push(x);
    int i = h.len - 1;
    while i > 0 {
        int p = (i - 1) / 2;
        if h[p] <= h[i] { break; }
        int t = h[p]; h[p] = h[i]; h[i] = t;
        i = p;
    }
}

int pop_min() {
    int top = h[0];
    h[0] = h[h.len - 1];
    h.pop();
    int i = 0;
    while true {
        int l = 2 * i + 1;
        int r = 2 * i + 2;
        int m = i;
        if l < h.len && h[l] < h[m] { m = l; }
        if r < h.len && h[r] < h[m] { m = r; }
        if m == i { break; }
        int t = h[m]; h[m] = h[i]; h[i] = t;
        i = m;
    }
    return top;
}

void main() {
    h = arr(8);
    push(5); push(3); push(8); push(1);
    jout << pop_min() << " " << pop_min() << "\n";
}
```

```
1 3
```

> **ระวัง:** ถ้าลืม sift down หลัง pop ฮีปจะไม่เป็นฮีปอีกต่อไป และค่าที่ออกมาจะผิดลำดับ ทดสอบด้วยค่าที่ไม่เรียงเสมอ
**แบบฝึกหัด**
- ค่าใดอยู่ที่รากของ min-heap เสมอ
  - a) ค่าที่น้อยที่สุด  b) ค่าที่มากที่สุด  c) ค่าแรกที่ใส่  — เฉลย: a. ฮีปแบบค่าต่ำสุดรักษาให้รากเป็นค่าที่เล็กที่สุดเสมอ
- ฮีปเรียงข้อมูลทั้งหมดไว้ล่วงหน้าเหมือนอาเรย์ที่เรียง — เฉลย: f. ฮีปรักษาเพียงความสัมพันธ์แม่กับลูก ไม่ได้เรียงทั้งหมด
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int[] h = arr(3);
h.push(2); h.push(7); h.push(4);
jout << h[0] + h[1] + h[2] << "\n";
}
```
  ผลลัพธ์ที่ได้: `13`. ผลรวมของค่าทุกช่องคือ 2 + 7 + 4 เท่ากับ 13 ไม่ว่าจะจัดลำดับอย่างไร
- ลูกซ้ายของโหนด i ในอาเรย์ฮีปอยู่ที่ตำแหน่ง 2 * i + ___ (เขียนเป็นคำอังกฤษ) — เฉลย: **one**. ลูกซ้ายคือ 2i+1 และลูกขวาคือ 2i+2
- การ pop ค่าต่ำสุดจากฮีป: เก็บค่าที่รากไว้ → เอาค่าท้ายมาที่ราก → ลดขนาดอาเรย์ → sift down จนเป็นฮีปอีกครั้ง. ต้องซ่อมฮีปหลังนำค่าท้ายมาวาง ไม่เช่นนั้นกฎแม่ลูกจะพัง
- pop ค่าต่ำสุดใช้เวลาเท่าใด
  - a) O(log n)  b) O(1) เสมอ  c) O(n^2)  — เฉลย: a. การ sift down ไปตามความสูงของต้นไม้ ซึ่งเป็น log n
**โจทย์**
- **ฮีปเล็ก** — push 5, 3, 8, 1 แล้ว pop ค่าต่ำสุดสองครั้งพิมพ์ 1 3. ผลลัพธ์ที่ได้: `1 3`. คำใบ้: ใช้ push และ pop_min ตามตัวอย่าง
- **ค่าสุดท้าย** — push 9, 4, 7 แล้ว pop ค่าต่ำสุดสามครั้งเพื่อพิมพ์ค่าที่ออกมาเป็นลำดับ 4 7 9. ผลลัพธ์ที่ได้: `4 7 9`. คำใบ้: ตัว pop ต้องคืนค่าเล็กที่สุดก่อนเสมอ

## กราฟและ BFS
**คืออะไร.** กราฟคือโหนดที่เชื่อมกันด้วยเส้นเชื่อม (edge) เช่นถนน เพื่อน หรือลิงก์ การค้นกว้าง (BFS) เยี่ยมโหนดตามระยะห่างจากจุดเริ่ม โดยใช้คิว ดังนั้นการเจอโหนดครั้งแรกคือเส้นทางที่สั้นที่สุดในจำนวนเส้นเชื่อม
**ทำไมต้องรู้.** แผนที่ เครือข่ายสังคม และการแก้ปัญหาการจัดลำดับล้วนเป็นกราฟ BFS ตอบคำถามว่า จากจุดนี้ต้องผ่านกี่ขั้นจึงถึงจุดนั้น
**ทำอย่างไร.**

เก็บกราฟเป็นรายการเพื่อนบ้านของแต่ละโหนด เริ่มที่โหนดต้นทางในคิว ดึงโหนดออกมาทีละตัว และเพิ่มเพื่อนบ้านที่ยังไม่เจอพร้อมระยะ +1
```jk
#import <stdlib>
using stdlib;

void main() {
    int[] dist = arr(2);
    dist.push(0); dist.push(0 - 1);
    int[] queue = arr(2);
    queue.push(0);
    dist[1] = dist[0] + 1;
    queue.push(1);
    jout << dist[1] << " " << queue.len << "\n";
}
```
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    int n = 4;
    int[] ea = arr(3); int[] eb = arr(3);
    ea.push(0); eb.push(1); ea.push(1); eb.push(2); ea.push(0); eb.push(3);
    int[] dist = arr(n);
    for v in 0..n { dist.push(0 - 1); }
    int[] queue = arr(n);
    queue.push(0);
    dist[0] = 0;
    int qh = 0;
    while qh < queue.len {
        int v = queue[qh];
        qh += 1;
        for e in 0..ea.len {
            int w = -1;
            if ea[e] == v { w = eb[e]; }
            if eb[e] == v { w = ea[e]; }
            if w >= 0 && dist[w] < 0 { dist[w] = dist[v] + 1; queue.push(w); }
        }
    }
    for v in 0..n { jout << dist[v] << "\n"; }
}
```

```
0
1
2
1
```

> **ระวัง:** BFS ต้องใช้ตัวนับหัวคิว ไม่ใช่การลบจากหน้า และต้องทำเครื่องหมายว่าโหนดถูกเจอแล้ว ไม่เช่นนั้นจะวนกลับไปมาไม่จบ
**แบบฝึกหัด**
- BFS ใช้โครงสร้างข้อมูลใดเป็นหลัก
  - a) คิว  b) สแตก  c) ฮีป  — เฉลย: a. การเยี่ยมตามชั้นต้องเข้าก่อนออกก่อน จึงใช้คิว
- ถ้าโหนดเชื่อมกันเป็นวงกลม BFS จะวนไม่จบ ถ้าไม่ทำเครื่องหมาย — เฉลย: t. ต้องจำโหนดที่เจอแล้วเพื่อไม่เพิ่มซ้ำ
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int[] d = arr(3);
d.push(0); d.push(0 - 1); d.push(0 - 1);
d[1] = d[0] + 1;
jout << d[1] << "\n";
}
```
  ผลลัพธ์ที่ได้: `1`. ระยะของโหนด 1 คือระยะของโหนด 0 บวก 1 ซึ่งเป็น 1
- โหนดที่ยังไม่เจอในการค้นกว้างมักมีระยะเป็นค่าสัญญาณ ___ (คำเดียว ตามภาษาอังกฤษ) — เฉลย: **unreached**. ใช้ -1 เป็นสัญญาณว่าไม่ถึง
- ขั้นของ BFS: ใส่โหนดเริ่มในคิว → ดึงโหนดหน้าคิว → เพิ่มเพื่อนบ้านที่ยังไม่เจอ → ทำซ้ำจนคิวว่าง. ทุกโหนดที่เจอจะเข้าคิวเพียงครั้งเดียว
- ทำไม BFS ได้เส้นทางสั้นที่สุด
  - a) เพราะเยี่ยมชั้นระยะ 1 ก่อนชั้น 2 เสมอ  b) เพราะมันเดาคำตอบ  c) เพราะมันดูเฉพาะโหนดปลาย  — เฉลย: a. โหนดที่เจอครั้งแรกมาจากชั้นที่ใกล้ที่สุด
**โจทย์**
- **ระยะถึงโหนด 3** — กราฟมีเส้นเชื่อม 0-1, 0-2, 1-3 หาระยะจาก 0 ถึง 3 แล้วพิมพ์ dist 2. ผลลัพธ์ที่ได้: `dist 2`. คำใบ้: ใช้ BFS ตามตัวอย่างของหัวข้อนี้
- **โหนดที่ไปไม่ถึง** — เส้นเชื่อม 0-1 และโหนด 2 แยกอยู่ หาระยะไป 2 จาก 0 แล้วพิมพ์ dist -1. ผลลัพธ์ที่ได้: `dist -1`. คำใบ้: โหนดที่ไปไม่ถึงคงค่า -1

## กราฟ: การค้นแบบลึก (DFS)
**คืออะไร.** การค้นลึก (DFS) เดินลงไปตามเส้นทางหนึ่งจนสุดทาง แล้วย้อนกลับเมื่อติดตัน โดยใช้สแตกโดยตรงหรือการเรียกฟังก์ชันซ้อน ใช้ตัวทำเครื่องหมาย visited กันการวนซ้ำ DFS ได้ลำดับที่ต่างจาก BFS และเหมาะกับการหาทุกโหนดที่ไปถึงได้
**ทำไมต้องรู้.** DFS ใช้ตรวจว่ามีวงในกราฟไหม จัดลำดับงานที่พึ่งพากัน และค้นทางเดินในเกมหรือเขาวงกต เราต้องรู้ว่าเมื่อไหร่ควรใช้ BFS หรือ DFS
**ทำอย่างไร.**

เขียนฟังก์ชันที่ทำเครื่องหมาย node แล้วเรียกตัวเองกับเพื่อนบ้านที่ยังไม่ถูกเยี่ยม การนับโหนดที่ไปถึงได้ทำได้ด้วยตัวนับที่เพิ่มขึ้นในแต่ละการเยี่ยม
```jk
#import <stdlib>
using stdlib;

int count = 0;

void visit(int v) {
    count += 1;
    if v < 2 { visit(v + 1); }
}

void main() {
    visit(0);
    jout << count << "\n";
}
```
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

int n = 4;
bool[] seen;
int count = 0;
int[] ea;
int[] eb;

void visit(int v) {
    seen[v] = true;
    count += 1;
    for e in 0..ea.len {
        int w = -1;
        if ea[e] == v { w = eb[e]; }
        if eb[e] == v { w = ea[e]; }
        if w >= 0 && !seen[w] { visit(w); }
    }
}

void main() {
    seen = arr(n);
    for i in 0..n { seen.push(false); }
    ea = arr(3); eb = arr(3);
    ea.push(0); eb.push(1); ea.push(1); eb.push(2); ea.push(0); eb.push(3);
    visit(0);
    jout << "reached " << count << "\n";
}
```

```
reached 4
```

> **ระวัง:** ถ้าลืม seen ก่อนเรียกตัวเอง ฟังก์ชันจะวนหาโหนดเดิมซ้ำไม่รู้จบ และการเรียกซ้อนลึกมากอาจทำให้โปรแกรมล้มเหลวด้วยสแตกเต็ม
**แบบฝึกหัด**
- DFS ใช้โครงสร้างข้อมูลใดโดยธรรมชาติ
  - a) สแตก หรือการเรียกซ้อน  b) คิว  c) ฮีป  — เฉลย: a. DFS ไปลึกก่อน ซึ่งตรงกับการเรียกฟังก์ชันซ้อนหรือสแตก
- DFS และ BFS ได้จำนวนโหนดที่ไปถึงได้เท่ากันเสมอ — เฉลย: t. ทั้งสองเยี่ยมทุกโหนดที่เชื่อมจากจุดเริ่ม ต่างกันแค่ลำดับ
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

int c = 0;

void f(int n) {
if n == 0 { return; }
c += 1;
f(n - 1);
}

void main() {
f(3);
jout << c << "\n";
}
```
  ผลลัพธ์ที่ได้: `3`. แต่ละการเรียกที่ n มากกว่าศูนย์เพิ่มค่า c หนึ่ง มีสามครั้งคือ n เป็น 3, 2, 1
- ตัวทำเครื่องหมายที่กันไม่ให้ DFS วนซ้ำคือ ___ — เฉลย: **visited**. visited บันทึกว่าโหนดถูกเยี่ยมแล้ว
- DFS จากโหนด 0: เยี่ยม 0 และทำเครื่องหมาย → เลือกเพื่อนบ้านที่ยังไม่เยี่ยม → เรียกตัวเองกับเพื่อนบ้าน → เมื่อหมดทางย้อนกลับ. การทำเครื่องหมายต้องเกิดก่อนการเรียกลึกเสมอ
- ถ้าลืมทำเครื่องหมาย DFS จะเป็นอย่างไรบนกราฟที่มีวง
  - a) วนไม่จบหรือสแตกเต็ม  b) ได้ผลเร็วขึ้น  c) ไม่มีผล  — เฉลย: a. โหนดในวงจะถูกเยี่ยมซ้ำไม่สิ้นสุด
**โจทย์**
- **นับโหนด** — ใช้ DFS บนกราฟ 0-1, 1-2, 0-3 กับ 4 โหนด แล้วพิมพ์ reached 4. ผลลัพธ์ที่ได้: `reached 4`. คำใบ้: ใช้ตัวอย่างในหัวข้อ
- **ไปไม่ถึง** — ใช้ DFS บนกราฟ 0-1 กับโหนด 3 โหนด แล้วพิมพ์ reached 2. ผลลัพธ์ที่ได้: `reached 2`. คำใบ้: โหนดที่ไม่มีเส้นเชื่อมจากต้นทางจะไม่ถูกนับ

## การโปรแกรมแบบพลวัต
**คืออะไร.** การโปรแกรมแบบพลวัต (dynamic programming, DP) แก้ปัญหาที่แยกเป็นปัญหาย่อยซ้ำกัน โดยแก้แต่ละปัญหาย่อยเพียงครั้งเดียวและเก็บคำตอบไว้ในตาราง แล้วสร้างคำตอบใหญ่จากตารางนั้น มี 2 แบบ คือจากบนลงล่างด้วยการจำ และจากล่างขึ้นบนด้วยตาราง
**ทำไมต้องรู้.** การเรียกซ้ำแบบเดิมโดยไม่จำค่าเก่าจะช้าแบบเอ็กซ์โพเนนเชียล เช่นฟิโบนักชีแบบธรรมดาคำนวณซ้ำมาก DP ทำให้ใช้เวลาเป็นพหุนาม
**ทำอย่างไร.**

กำหนดความหมายของ dp[i] ให้ชัด เขียนสูตรที่ dp[i] พึ่งค่าที่เล็กกว่า แล้ววนจากค่าเริ่มต้นไปถึงค่าที่ต้องการ
```jk
#import <stdlib>
using stdlib;

void main() {
    int[] dp = arr(4);
    dp.push(0); dp.push(1);
    for i in 2..4 { dp.push(dp[i - 1] + dp[i - 2]); }
    jout << dp[3] << "\n";
}
```
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

int fib(int n) {
    if n < 2 { return n; }
    int[] dp = arr(n + 1);
    dp.push(0);
    dp.push(1);
    for i in 2..n + 1 { dp.push(dp[i - 1] + dp[i - 2]); }
    return dp[n];
}

void main() {
    jout << fib(10) << "\n";
    jout << fib(1) << "\n";
    jout << fib(20) << "\n";
}
```

```
55
1
6765
```

> **ระวัง:** ลืมค่าเริ่มต้นเป็นความผิดพลาดที่พบบ่อย ค่า dp[0] และ dp[1] ต้องถูกใส่ก่อนลูปเริ่มเสมอ
**แบบฝึกหัด**
- DP ใช้ความคิดหลักอะไร
  - a) เก็บคำตอบปัญหาย่อยเพื่อไม่ต้องคำนวณซ้ำ  b) สุ่มคำตอบ  c) เรียงข้อมูลก่อน  — เฉลย: a. การเก็บค่าที่คำนวณแล้วทำให้ไม่ต้องทำซ้ำ
- ฟิโบนักชีแบบเรียกซ้ำธรรมดาไม่มีการคำนวณซ้ำ — เฉลย: f. ฟังก์ชันจะเรียกค่าย่อยเดิมซ้ำ ๆ มากมาย
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int a = 0;
int b = 1;
for i in 0..5 {
    int t = a + b;
    a = b;
    b = t;
}
jout << a << "\n";
}
```
  ผลลัพธ์ที่ได้: `5`. ลำดับ 0 1 1 2 3 5 ผ่านห้ารอบจะได้ค่า a เท่ากับ 5
- ความหมายของ dp[i] ควรเขียนให้ ___ ก่อนเริ่มเขียนสูตร (คำอังกฤษ) — เฉลย: **clear**. dp ที่ชัดช่วยให้สูตรถูกต้อง
- การทำ DP แบบตาราง: นิยามความหมายของตาราง → ใส่ค่าเริ่มต้น → เขียนสูตรจากค่าเล็กไปใหญ่ → ตอบจากช่องสุดท้าย. ค่าที่ต้องใช้ต้องถูกคำนวณก่อนเสมอ
- ทำไม fib แบบจำค่าจึงเร็วกว่าแบบเรียกซ้ำธรรมดา
  - a) เพราะไม่คำนวณปัญหาย่อยเดิมซ้ำ  b) เพราะใช้ฮีป  c) เพราะไม่ใช้ตัวแปร  — เฉลย: a. การจำค่าทำให้แต่ละปัญหาย่อยถูกคำนวณเพียงครั้งเดียว
**โจทย์**
- **ฟิโบนักชี** — ใช้ DP หา fib(10) แล้วพิมพ์ fib 55. ผลลัพธ์ที่ได้: `fib 55`. คำใบ้: ใช้ตารางค่าทีละช่องจากค่าเริ่มต้น 0 และ 1
- **บันไดสี่ขั้น** — จำนวนวิธีขึ้นบันได 4 ขั้น โดยก้าวทีละ 1 หรือ 2 ขั้น คือ ways 5 ให้พิมพ์ ways 5. ผลลัพธ์ที่ได้: `ways 5`. คำใบ้: ways[n] = ways[n-1] + ways[n-2] โดยเริ่มที่ 1 และ 2
