# Machine

## คอมพิวเตอร์ทำอะไรได้
**คืออะไร.** คอมพิวเตอร์ทำงานหลักสามอย่าง คือคำนวณ เก็บข้อมูลในความจำ และย้ายข้อมูลระหว่างความจำต่าง ๆ โปรแกรมทุกตัวประกอบด้วยการกระทำเล็ก ๆ เหล่านี้ เช่น การบวกหนึ่งครั้งหรือการอ่านค่าหนึ่งช่อง ซีพียูทำได้หลายล้านคำสั่งต่อวินาที แต่แต่ละคำสั่งเล็กมาก
**ทำไมต้องรู้.** เมื่อรู้ว่าโปรแกรมทำกี่คำสั่ง คุณจะเดาได้ว่ามันเร็วหรือช้า ลูปหนึ่งล้านรอบที่มีงานสามอย่างต่อรอบจะทำงานประมาณสามล้านครั้ง การนับแบบนี้คือพื้นฐานของการทำให้โปรแกรมเร็วขึ้น
**ทำอย่างไร.**

นับว่าลูปทำอะไรในหนึ่งรอบ แล้วคูณด้วยจำนวนรอบ ตัวอย่างด้านล่างบวกเลข 1 ถึง 1000 ซึ่งต้องทำ 1000 รอบ ผลรวมคือ 500500
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    int sum = 0;
    for i in 1..1001 { sum += i; }
    jout << "sum " << sum << "\n";
}
```

```
sum 500500
```

> **ระวัง:** การคิดว่าซีพียูทำทุกอย่างทันทีเป็นความเข้าใจผิดที่พบบ่อย ลูปที่วนนานจะช้าตามจำนวนคำสั่งที่ทำซ้ำ ไม่ว่าเครื่องจะเร็วแค่ไหน
**แบบฝึกหัด**
- ลูปที่วน 1000 รอบ และมีการบวกหนึ่งครั้งต่อรอบ ทำการบวกกี่ครั้ง
  - a) 1000  b) 1  c) 1000000  — เฉลย: a. หนึ่งรอบบวกหนึ่งครั้ง จึงรวมเป็น 1000 ครั้ง
- ซีพียูทำได้เพียงการคำนวณ ไม่ได้เกี่ยวข้องกับการเก็บข้อมูลเลย — เฉลย: f. ซีพียูต้องอ่านและเขียนความจำเพื่อเก็บค่า เช่นตัวแปร
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int sum = 0;
for i in 1..11 { sum += i; }
jout << sum << "\n";
}
```
  ผลลัพธ์ที่ได้: `55`. ตัวเลข 1 ถึง 10 รวมเป็น 55 ซึ่งตรงกับสูตรบวกเลขเรียงที่เคยเรียนมา
- ทุกคำสั่งที่โปรแกรมทำจริงเป็นการคำนวณ การอ่าน หรือการ ___ ข้อมูล (คำอังกฤษ) — เฉลย: **write**. ซีพียูทำงานกับข้อมูลโดยอ่านและเขียนความจำ
- ลำดับการคิดว่าโปรแกรมจะเร็วหรือช้า: ดูว่าลูปทำอะไรในหนึ่งรอบ → นับจำนวนรอบ → คูณจำนวนคำสั่งกับจำนวนรอบ → เปรียบเทียบกับเป้าหมาย. ต้องรู้ปริมาณงานก่อนจึงตัดสินได้
- ลูปหนึ่งลูปมีงานสองอย่างต่อรอบ วนหนึ่งพันรอบ จะทำงานกี่ครั้งรวม
  - a) 2000  b) 1000  c) 3000  — เฉลย: a. สองอย่างต่อรอบคูณหนึ่งพันรอบได้สองพันครั้ง
**โจทย์**
- **ผลรวม 100** — เขียนโปรแกรมที่รวมเลข 1 ถึง 100 แล้วพิมพ์ sum 5050. ผลลัพธ์ที่ได้: `sum 5050`. คำใบ้: ใช้ for i in 1..101
- **นับขั้น** — วนลูป 10 รอบ แต่ละรอบบวก 3 เข้า total แล้วพิมพ์ total 30. ผลลัพธ์ที่ได้: `total 30`. คำใบ้: ใช้ total += 3 ในลูป

## บิตและไบต์
**คืออะไร.** ข้อมูลในความจำเก็บเป็นบิต แปดบิตเป็นหนึ่งไบต์ ชนิดข้อมูลกำหนดว่าใช้กี่ไบต์ char ใช้หนึ่งไบต์ int ใน J2K ใช้แปดไบต์ float ใช้สี่ไบต์ และ double ใช้แปดไบต์ ขนาดนี้บอกว่าอาเรย์หนึ่งชุดกินความจำเท่าใด
**ทำไมต้องรู้.** เมื่อรู้ขนาดของชนิด คุณรู้ว่าอาเรย์ใหญ่แค่ไหนในความจำ และเมื่อใดข้อมูลจะไม่พอ การใช้ float แทน double ทำให้อาเรย์เล็กลงครึ่งหนึ่ง ซีพียูจึงอ่านข้อมูลได้มากขึ้นต่อหนึ่งครั้งที่ดึงจากความจำ
**ทำอย่างไร.**

ใช้ sizeof(ชนิด) เพื่อดูขนาดเป็นไบต์ และคำนวณขนาดอาเรย์จากจำนวนสมาชิกคูณขนาดของหนึ่งตัว
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    jout << "char " << sizeof(char) << " int " << sizeof(int) << "\n";
    jout << "float " << sizeof(float) << " double " << sizeof(double) << "\n";
    int n = 100;
    jout << "array of 100 floats: " << n * sizeof(float) << " bytes\n";
}
```

```
char 1 int 8
float 4 double 8
array of 100 floats: 400 bytes
```

> **ระวัง:** จำนวนบิตกับจำนวนไบต์ไม่เท่ากัน บิตคือหน่วยเล็กที่สุด ไบต์คือแปดบิต ถ้าตัวเลขบอกเป็นบิต ต้องหารด้วยแปดก่อนเทียบกับขนาดของความจำ
**แบบฝึกหัด**
- หนึ่งไบต์มีกี่บิต
  - a) 8  b) 4  c) 16  — เฉลย: a. หนึ่งไบต์คือแปดบิต
- double ใช้ความจำมากกว่า float — เฉลย: t. double ใช้แปดไบต์ ส่วน float ใช้สี่ไบต์
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
jout << sizeof(float) * 10 << "\n";
}
```
  ผลลัพธ์ที่ได้: `40`. float ใช้ 4 ไบต์ คูณ 10 ตัวได้ 40 ไบต์
- ฟังก์ชัน ___ บอกขนาดของชนิดเป็นไบต์ — เฉลย: **sizeof**. sizeof ใช้กับชนิดที่อยู่ในวงเล็บ
- คำนวณขนาดอาเรย์ float 50 ค่า: บอกจำนวนสมาชิก 50 → หาขนาด float เป็น 4 ไบต์ → คูณกัน → ได้ 200 ไบต์. ต้องรู้ขนาดต่อค่าก่อนจึงคูณด้วยจำนวนได้
- ทำไม float ทำให้อาเรย์กินความจำน้อยลง
  - a) เพราะใช้สี่ไบต์ต่อค่า แทนที่จะเป็นแปดไบต์  b) เพราะบวกได้เร็วกว่า  c) เพราะไม่มีเครื่องหมาย  — เฉลย: a. ขนาดต่อค่าเล็กกว่า จึงกินที่น้อยกว่า
**โจทย์**
- **ขนาด double** — พิมพ์ขนาดของ double เป็นไบต์. ผลลัพธ์ที่ได้: `8`. คำใบ้: ใช้ sizeof(double)
- **อาเรย์ float** — คำนวณขนาดรวมของอาเรย์ float 25 ค่าเป็นไบต์แล้วพิมพ์. ผลลัพธ์ที่ได้: `100`. คำใบ้: คูณ 25 ด้วย sizeof(float)

## ตัวแปร อาเรย์ และที่อยู่
**คืออะไร.** ทุกตัวแปรมีที่อยู่ในความจำ @x คือที่อยู่ของ x ตัวชี้ int^ p เก็บที่อยู่ของ int และ p^ คือค่าที่ตัวชี้นั้นชี้อยู่ อาเรย์เป็นช่องติดกัน ที่แต่ละช่องห่างกันเท่ากับขนาดของชนิด
**ทำไมต้องรู้.** การส่งที่อยู่ให้ฟังก์ชันทำให้แก้ค่าเดิมได้โดยไม่ต้องคัดลอกข้อมูลทั้งก้อน และการเข้าใจว่าช่องของอาเรย์ติดกันอธิบายได้ว่าทำไมการอ่านตามลำดับจึงเร็ว
**ทำอย่างไร.**

ประกาศตัวชี้ด้วยชนิดตามด้วย ^ แล้วกำหนดที่อยู่ด้วย @
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    int x = 1;
    int^ p = @x;
    p^ = 5;
    jout << "x " << x << "\n";
    int a[3];
    a[0] = 10; a[1] = 7; a[2] = 3;
    int^ q = @a;
    jout << "a[1] through the pointer: " << q[1] << "\n";
}
```

```
x 5
a[1] through the pointer: 7
```

> **ระวัง:** การแก้ค่าผ่านตัวชี้ทำให้ตัวแปรเดิมเปลี่ยนไปด้วย สะดวกแต่หาสาเหตุยาก ถ้าไม่ต้องการให้เปลี่ยน ให้ส่งค่าธรรมดาแทน
**แบบฝึกหัด**
- ค่า @x คืออะไร
  - a) ที่อยู่ของ x ในความจำ  b) ค่าของ x  c) ขนาดของ x  — เฉลย: a. @ ให้ที่อยู่ ส่วน x คือค่า
- p^ = 5 เปลี่ยนค่าที่ตัวชี้ p ชี้อยู่ — เฉลย: t. การใช้ ^ แล้วกำหนดค่าเปลี่ยนค่าที่ตัวชี้ชี้อยู่
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int v = 2;
int^ p = @v;
p^ = p^ * 10;
jout << v << "\n";
}
```
  ผลลัพธ์ที่ได้: `20`. p ชี้ไปที่ v ค่าที่ชี้ถูกคูณ 10 ทำให้ v เป็น 20
- ช่องในอาเรย์อยู่ติดกันในความจำ จึงเรียกว่า ___ — เฉลย: **contiguous**. ที่อยู่ติดกันทำให้อ่านต่อกันได้เร็ว
- ใช้ตัวชี้เปลี่ยนค่าตัวแปร: ประกาศ int x → สร้าง int^ p = @x → เขียน p^ = 5 → x ได้ค่า 5. ต้องชี้ไปที่ตัวแปรก่อนเขียนผ่านตัวชี้
- ทำไมการอ่านอาเรย์ตามลำดับจึงเร็ว
  - a) เพราะช่องถัดไปอยู่ติดกันในความจำ  b) เพราะซีพียูชอบเลขคู่  c) เพราะไม่มีตัวชี้  — เฉลย: a. ที่อยู่ติดกันทำให้ใช้บล็อกที่โหลดมาแล้วได้ครบ
**โจทย์**
- **ผ่านตัวชี้** — ประกาศ int n = 4 และ int^ p = @n แล้วคูณค่าที่ p ชี้ด้วย 3 พิมพ์ n. ผลลัพธ์ที่ได้: `12`. คำใบ้: แก้ผ่าน p^ = p^ * 3
- **อาเรย์ผ่านตัวชี้** — อาเรย์ a มี 4, 9, 16 ให้ int^ q = @a แล้วพิมพ์ q[2]. ผลลัพธ์ที่ได้: `16`. คำใบ้: ตัวชี้อ่านช่องด้วยดัชนีได้

## แรมช้าและ cache
**คืออะไร.** แรมช้ากว่าซีพียูมาก ซีพียูจึงมี cache ขนาดเล็กใกล้ตัวไว้เก็บข้อมูลที่ใช้บ่อย เมื่ออ่านค่าหนึ่งตัว ระบบดึงทั้งบล็อกประมาณ 64 ไบต์มาที่ cache ถ้าโปรแกรมใช้ข้อมูลทั้งบล็อกก่อนไปที่อื่น การทำงานจะเร็ว
**ทำไมต้องรู้.** ผลรวมที่ได้เท่ากันทุกประการอาจเร็วหรือช้าต่างกันมาก ตามลำดับที่อ่าน เพราะความช้ามาจากการรอแรม ไม่ใช่จากจำนวนการบวก
**ทำอย่างไร.**

เมื่ออ่านตารางสองมิติ ให้วนแถวด้านในตามคอลัมน์ เพราะแถวอยู่ติดกันในความจำ ตัวอย่างนี้รวมตารางทั้งสองแบบแล้วได้คำตอบเท่ากัน
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    int n = 4;
    int[] t = arr(n * n);
    for i in 0..n * n { t.push(i); }
    int by_rows = 0;
    for r in 0..n { for c in 0..n { by_rows += t[r * n + c]; } }
    int by_cols = 0;
    for c in 0..n { for r in 0..n { by_cols += t[r * n + c]; } }
    jout << "rows " << by_rows << " cols " << by_cols << "\n";
    jout << "same " << (by_rows == by_cols) << "\n";
}
```

```
rows 120 cols 120
same true
```

> **ระวัง:** ความเร็วต่างกันในเครื่องจริง แต่คำตอบต้องเหมือนกันเสมอ ถ้าคำตอบไม่เหมือน แปลว่าลูปเขียนผิด ไม่ใช่เพราะแคช
**แบบฝึกหัด**
- ทำไมการอ่านตามแถวจึงเร็วกว่าตามคอลัมน์
  - a) เพราะข้อมูลที่อยู่ติดกันถูกโหลดมาพร้อมกันใน cache  b) เพราะซีพียูเร็วกว่าในคอลัมน์  c) เพราะแถวสั้นกว่า  — เฉลย: a. บล็อกของ cache มีหลายค่าติดกัน การใช้ทั้งบล็อกทำให้ไม่ต้องรอแรมบ่อย
- ผลรวมตามแถวกับตามคอลัมน์ต้องเท่ากันเสมอ — เฉลย: t. ทั้งสองรวมสมาชิกทุกตัวเพียงครั้งเดียว ต่างกันแค่ลำดับ
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int[] t = arr(4);
t.push(1); t.push(2); t.push(3); t.push(4);
int s = 0;
for i in 0..4 { s += t[i]; }
jout << s << "\n";
}
```
  ผลลัพธ์ที่ได้: `10`. 1 + 2 + 3 + 4 = 10
- การใช้ข้อมูลที่อยู่ติดกันในความจำซ้ำ ๆ เรียกว่า ___ locality — เฉลย: **spatial**. บล็อกของ cache มักมี 64 ไบต์
- ทำให้การอ่านตารางเร็วขึ้น: วนแถวด้านนอก → วนคอลัมน์ด้านใน → อ่านทีละช่องที่อยู่ติดกัน → ได้คำตอบเดิมแต่เร็วกว่า. ลำดับการวนเปลี่ยนการใช้ cache แต่ไม่เปลี่ยนคำตอบ
- แรมต่างจาก cache อย่างไร
  - a) แรมใหญ่กว่าแต่ช้ากว่า cache  b) แรมเร็วกว่าเสมอ  c) ไม่ต่างกัน  — เฉลย: a. cache เล็กแต่เร็ว แรมใหญ่แต่ช้า
**โจทย์**
- **ผลรวมแถว** — ตาราง 3x3 เก็บค่า t[i] = i สำหรับ i 0 ถึง 8 แล้วรวมทุกค่า พิมพ์ 36. ผลลัพธ์ที่ได้: `36`. คำใบ้: 0 + 1 + ... + 8 = 36
- **ผลรวมคอลัมน์** — รวมค่าเดียวกันด้วยการวนตามคอลัมน์ก่อนแถว แล้วพิมพ์ 36. ผลลัพธ์ที่ได้: `36`. คำใบ้: เปลี่ยนลำดับวนลูปแล้วรวมให้ได้ผลเดิม

## เดินตามลำดับหรือกระโดด
**คืออะไร.** การอ่านอาเรย์ทีละช่องตามลำดับ เรียกว่า stride 1 การกระโดดข้ามช่องคือ stride ใหญ่ ทั้งสองอ่านข้อมูลชุดเดียวกันจนได้ผลรวมเท่ากัน แต่ stride ใหญ่ทำให้บล็อกของ cache ไม่คุ้ม เพราะแต่ละบล็อกให้ค่าที่ใช้เพียงบางค่า
**ทำไมต้องรู้.** ในโปรแกรมจริงมักมีการข้ามช่องโดยไม่ตั้งใจ เช่นอ่านคอลัมน์ของตารางที่เก็บเป็นแถว การรู้ว่าอะไรคือการเดินตามลำดับ ช่วยให้จัดลูปได้ถูก
**ทำอย่างไร.**

ลองวนด้วยดัชนี (i * 3) % n ในอาเรย์ที่มีขนาด n แล้วเทียบกับการเดินตามลำดับ
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    int n = 8;
    int[] a = arr(n);
    for i in 0..n { a.push(i * 2); }
    int walk = 0;
    for i in 0..n { walk += a[i]; }
    int jump = 0;
    for i in 0..n { jump += a[(i * 3) % n]; }
    jout << "walk " << walk << " jump " << jump << "\n";
}
```

```
walk 56 jump 56
```

> **ระวัง:** ผลรวมเท่ากันไม่ได้แปลว่าเร็วเท่ากัน ต้องดูว่าการอ่านเป็นลำดับหรือไม่ และถ้าไม่เป็นลำดับ ควรจัดข้อมูลใหม่หรือเปลี่ยนลูป
**แบบฝึกหัด**
- ดัชนีที่กระโดดข้ามช่องทำให้เกิดอะไร
  - a) การใช้บล็อกของ cache ไม่คุ้ม  b) ผลลัพธ์เปลี่ยน  c) โปรแกรมไม่คอมไพล์  — เฉลย: a. การข้ามช่องทำให้บล็อกถูกโหลดแล้วใช้เพียงบางค่า
- การกระโดดช่องทำให้ผลรวมต่างจากการเดินตามลำดับเสมอ — เฉลย: f. ถ้าอ่านทุกช่องครั้งเดียว ผลรวมเท่ากัน ต่างกันเพียงความเร็ว
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int[] a = arr(3);
a.push(5); a.push(6); a.push(7);
int s = 0;
for i in 0..3 { s += a[(i * 2) % 3]; }
jout << s << "\n";
}
```
  ผลลัพธ์ที่ได้: `18`. ดัชนี 0, 2, 1 อ่านค่า 5, 7, 6 รวมเป็น 18
- การอ่านทีละช่องที่ติดกันเรียกว่า stride ___ (เขียนเป็นคำอังกฤษ) — เฉลย: **one**. stride 1 คือเดินทีละช่อง
- ทดลองเปรียบเทียบการเดินสองแบบ: สร้างอาเรย์เดียวกัน → วนตามลำดับ → วนแบบกระโดด → เทียบผลรวมและเวลา. ผลต้องเท่ากันก่อนจะเทียบความเร็ว
- เมื่อไม่แน่ใจว่าการเข้าถึงแบบใดเร็วกว่า ควรทำอย่างไร
  - a) วัดด้วยเวลาที่เชื่อถือได้  b) เดาแล้วเชื่อ  c) ไม่ต้องทำอะไร  — เฉลย: a. การวัดให้ความจริงมากกว่าการเดา
**โจทย์**
- **กระโดดหกช่อง** — อาเรย์ 0 ถึง 5 ที่ใส่ค่าเท่ากับดัชนี วนดัชนี (i * 5) % 6 รวมค่า แล้วพิมพ์ sum 15. ผลลัพธ์ที่ได้: `sum 15`. คำใบ้: ดัชนีที่ได้เป็นการเรียงใหม่ของ 0 ถึง 5 ทุกตัวหนึ่งครั้ง
- **กระโดดสี่ช่อง** — ในอาเรย์ 1, 2, 3, 4 ใช้ดัชนี (i * 3) % 4 แล้วรวมค่า พิมพ์ 10. ผลลัพธ์ที่ได้: `10`. คำใบ้: การกระโดดแบบนี้ไปทุกช่องครั้งเดียว

## ท่อคำสั่งและการกระโดด
**คืออะไร.** ซีพียูทำคำสั่งเป็นท่อ คือขณะทำคำสั่งหนึ่ง ก็ดึงและแปลคำสั่งถัดไปพร้อมกันไป คำสั่ง if เป็นการกระโดดที่ซีพียูต้องเดาว่าจะไปทางไหน ถ้าเดาถูกก็เร็ว ถ้าเดาผิดต้องทิ้งงานที่ทำไว้และเริ่มใหม่ การเดาแม่นขึ้นเมื่อผลของเงื่อนไขมีรูปแบบที่คาดได้
**ทำไมต้องรู้.** ลูปที่มี if อยู่ข้างในอาจช้าเพราะการเดาผิด ถ้าข้อมูลถูกจัดให้ผลเงื่อนไขเป็นกลุ่มติดกัน ซีพียูจะเดาได้แม่นขึ้น
**ทำอย่างไร.**

เขียนเงื่อนไขในลูปให้เรียบง่าย และถ้าจัดข้อมูลให้ผลเป็นกลุ่มได้ ให้ทำ คำตอบจะยังเหมือนเดิม
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    int n = 10;
    int[] a = arr(n);
    for i in 0..n { a.push(i); }
    int count = 0;
    for i in 0..n {
        if a[i] >= 5 { count += 1; }
    }
    jout << "count " << count << "\n";
}
```

```
count 5
```

> **ระวัง:** การเพิ่มคำสั่งกระโดดในลูปร้อนมักทำให้ช้า ให้ดูว่า if ในลูปเกิดบ่อยหรือไม่ก่อนตัดสิน
**แบบฝึกหัด**
- ทำไมการเดาผิดของการกระโดดจึงช้า
  - a) ซีพียูต้องทิ้งคำสั่งที่เดาไว้แล้วเริ่มใหม่  b) เพราะคำสั่งหายไป  c) เพราะ if ไม่ทำงาน  — เฉลย: a. คำสั่งที่เดาผิดต้องถูกทิ้ง ทำให้เสียรอบ
- ท่อคำสั่งหมายความว่าซีพียูทำคำสั่งทีละคำสั่งจนจบแล้วค่อยดึงคำสั่งใหม่เสมอ — เฉลย: f. ท่อทำให้หลายขั้นของคำสั่งทำพร้อมกัน
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int count = 0;
for i in 0..6 {
    if i % 2 == 0 { count += 1; }
}
jout << count << "\n";
}
```
  ผลลัพธ์ที่ได้: `3`. ค่า 0, 2, 4 เป็นเลขคู่ จึงนับได้สามครั้ง
- การเลือกทางด้วย if ทำให้ซีพียูต้อง ___ ว่าจะไปทางไหน (คำอังกฤษ) — เฉลย: **guess**. การเดาถูกหรือผิดส่งผลต่อความเร็ว
- ซีพียูจัดการ if ในลูป: ดึงคำสั่ง if → เดาทางที่จะไป → ทำคำสั่งต่อ → ถ้าเดาผิดทิ้งงานที่ทำไปและเริ่มใหม่. การเดาผิดเป็นต้นทุนที่ต้องจ่าย
- ข้อมูลแบบใดทำให้ if ในลูปเดาได้แม่น
  - a) ผลเป็นกลุ่มติดกัน เช่นค่าเล็กทั้งหมดก่อนค่าใหญ่  b) ค่าสุ่มทุกตัว  c) ไม่มีข้อมูลเลย  — เฉลย: a. เมื่อผลเหมือนกันติดกัน การเดาจากรอบก่อนหน้าจะถูก
**โจทย์**
- **นับ if** — นับค่าในอาเรย์ 0 ถึง 9 ที่มากกว่า 5 แล้วพิมพ์ count 4. ผลลัพธ์ที่ได้: `count 4`. คำใบ้: ค่า 6, 7, 8, 9 มากกว่า 5 รวมสี่ค่า
- **เลขคู่** — นับเลขคู่ใน 1 ถึง 10 ด้วย if แล้วพิมพ์ even 5. ผลลัพธ์ที่ได้: `even 5`. คำใบ้: ใช้ % 2 == 0

## SIMD: ทำหลายค่าพร้อมกัน
**คืออะไร.** SIMD คือคำสั่งที่ทำกับหลายค่าพร้อมกันในหนึ่งคำสั่ง รีจิสเตอร์ NEON ของ ARM64 มีขนาด 128 บิต ใส่ float ได้สี่ค่าในคราวเดียว ชนิด f32x4 ใน J2K เก็บสี่ค่า และการบวกกับตัวมันเองทำทั้งสี่ช่องในคำสั่งเดียว
**ทำไมต้องรู้.** ภาพ เสียง และการคูณเมทริกซ์มีงานเหมือนกันซ้ำหลายล้านครั้ง ถ้าทำทีละค่าจะช้า SIMD ทำงานได้หลายค่าต่อคำสั่ง และคอมไพเลอร์บางครั้งสร้างให้เองจากลูปธรรมดา
**ทำอย่างไร.**

ประกาศค่า f32x4 ด้วยวงเล็บปีกกา แล้วใช้ + หรือเมธอด sum ซึ่งทำงานกับทุกช่องพร้อมกัน
**ตัวอย่าง.**

```jk
#import <stdlib>
#import <simd>
using stdlib;

void main() {
    f32x4 f = {1.0, 2.0, 3.0, 4.0};
    jout << f.sum() << " " << f.min() << " " << f.max() << "\n";
    f32x4 g = f * 2.0;
    jout << g.w << "\n";
}
```

```
10.000000 1.000000 4.000000
8.000000
```

> **ระวัง:** ต้อง import simd ก่อนใช้ f32x4 และ vector ไม่ใช่อาเรย์ทั่วไป การผสมชนิดต้องตรงกันทั้งสองข้าง
**แบบฝึกหัด**
- f32x4 ทำงานกับกี่ค่าในคำสั่งเดียว
  - a) 4  b) 2  c) 8  — เฉลย: a. ชื่อ f32x4 บอกว่ามีสี่ค่า แต่ละค่า 32 บิต
- SIMD เร็วขึ้นได้เพราะทำหลายค่าพร้อมกันในหนึ่งคำสั่ง — เฉลย: t. นี่คือแนวคิดหลักของ SIMD
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
#import <simd>
using stdlib;

void main() {
f32x4 a = {1.0, 2.0, 3.0, 4.0};
jout << (a + a).sum() << "\n";
}
```
  ผลลัพธ์ที่ได้: `20.000000`. a + a ได้ 2, 4, 6, 8 ซึ่งรวมกันได้ 20
- ค่าแต่ละช่องใน vector เรียกว่า ___ — เฉลย: **lanes**. lanes คือช่องของ vector
- ใช้ SIMD หาผลรวมของสี่ค่า: ประกาศ f32x4 → บวกกับตัวเอง → เรียก sum → พิมพ์ผล. ต้องมีค่าก่อนจึงบวกและรวมได้
- ต้อง import ไลบรารีใดก่อนใช้ f32x4
  - a) simd  b) jout  c) sum  — เฉลย: a. simd ให้ชนิดและเมธอดของ vector
**โจทย์**
- **รวม vector** — ประกาศ f32x4 {1, 2, 3, 4} แล้วพิมพ์ sum ของมันเป็น 10.000000. ผลลัพธ์ที่ได้: `10.000000`. คำใบ้: ใช้ .sum()
- **คูณทุกช่อง** — สร้าง f32x4 {1, 1, 1, 1} คูณ 3.0 แล้วพิมพ์ sum ของผล. ผลลัพธ์ที่ได้: `12.000000`. คำใบ้: สี่ช่องคูณสามได้สิบสองในผลรวม

## float และ double: เลขทศนิยมในเครื่อง
**คืออะไร.** ตัวเลขทศนิยมในเครื่องเก็บเป็นเลขฐานสองโดยประมาณ เลขบางตัวอย่าง 0.1 เก็บไม่ได้เป๊ะ float ใช้ 32 บิต และ double ใช้ 64 บิต ทำให้ double แม่นกว่า การเปรียบเทียบทศนิยมด้วย == มักผิด เพราะมีเศษเล็ก ๆ
**ทำไมต้องรู้.** โปรแกรมการเงิน วิทยาศาสตร์ และกราฟิกต้องเข้าใจความคลาดเคลื่อนนี้ เช่น 0.1 + 0.2 ไม่เท่ากับ 0.3 ในเครื่อง
**ทำอย่างไร.**

ตรวจความต่างด้วยค่าเล็กที่ยอมรับได้ แทนการใช้ ==
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    double x = 0.1 + 0.2;
    jout << (x == 0.3) << " " << x << "\n";
    float f = 1.5;
    jout << (double)f * 2.0 << "\n";
    double diff = x - 0.3;
    if diff < 0.000001 && diff > -0.000001 { jout << "close enough\n"; }
}
```

```
false 0.300000
3.000000
close enough
```

> **ระวัง:** การพิมพ์ 0.300000 ไม่ได้บอกว่าค่าเป๊ะ ผลพิมพ์มีหกตำแหน่ง ค่าจริงอาจต่างจาก 0.3 เล็กน้อย
**แบบฝึกหัด**
- double ต่างจาก float อย่างไร
  - a) double มี 64 บิตและแม่นกว่า  b) double เก็บแต่จำนวนเต็ม  c) ไม่ต่างกัน  — เฉลย: a. double ใช้แปดไบต์และแม่นกว่า float
- 0.1 + 0.2 == 0.3 เป็น true ในเครื่องเสมอ — เฉลย: f. ค่าทศนิยมบางค่าเก็บไม่เป๊ะ ผลรวมจึงมีเศษเล็ก
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
double a = 0.5 + 0.25;
jout << (a == 0.75) << "\n";
}
```
  ผลลัพธ์ที่ได้: `true`. 0.5 และ 0.25 เก็บได้เป๊ะในฐานสอง ผลรวมจึงเท่ากับ 0.75 พอดี
- การเปรียบเทียบทศนิยมให้ปลอดภัย มักใช้ค่า ___ ที่ยอมรับได้ (คำอังกฤษ) — เฉลย: **tolerance**. tolerance คือค่าความคลาดเคลื่อนที่ยอมรับได้
- เปรียบเทียบ 0.1 + 0.2 กับ 0.3 อย่างปลอดภัย: คำนวณผลต่าง → ดูค่าสัมบูรณ์ของผลต่าง → เทียบกับค่าเล็กที่ยอมรับได้ → ตัดสิน. ไม่ควรเทียบด้วย == โดยตรง
- float ใช้กี่บิต
  - a) 32  b) 64  c) 16  — เฉลย: a. float ใช้ 32 บิต คือสี่ไบต์
**โจทย์**
- **ทศนิยมพอดี** — พิมพ์ผลของ 0.5 + 0.25 == 0.75. ผลลัพธ์ที่ได้: `true`. คำใบ้: 0.5 และ 0.25 เก็บได้เป๊ะ
- **ผลต่าง** — คำนวณ 1.0 - 0.9 แล้วพิมพ์ close ถ้าผลนี้ต่างจาก 0.1 ไม่เกิน 0.000001 มิฉะนั้นพิมพ์ far. ผลลัพธ์ที่ได้: `close`. คำใบ้: ผลจะต่างจาก 0.1 เพียงเศษเล็กมาก

## การคูณแล้วบวกในคำสั่งเดียว (FMA)
**คืออะไร.** ซีพียูบางตัวมีคำสั่ง fused multiply-add คือทำ a * b + c ในคำสั่งเดียวและปัดเศษครั้งเดียว ผลอาจต่างจากการคูณก่อนแล้วบวกทีหลังซึ่งปัดเศษสองครั้ง คอมไพเลอร์ J2K ใช้คำสั่งนี้ให้โดยอัตโนมัติ และตัวเลือก -nofma ปิดไว้เพื่อเทียบผล
**ทำไมต้องรู้.** คำสั่งเดียวเร็วขึ้นและแม่นขึ้นเล็กน้อย แต่ผลอาจต่างเล็กน้อยจากที่คาด ถ้าเทียบผลกับโปรแกรมอื่นต้องรู้เรื่องนี้
**ทำอย่างไร.**

เขียนสูตรตามปกติ a * b + c คอมไพเลอร์เลือกใช้คำสั่งรวมเองเมื่อทำได้
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    double a = 2.0;
    double b = 3.0;
    double c = 1.0;
    double r = a * b + c;
    jout << r << "\n";
    jout << (r == 7.0) << "\n";
}
```

```
7.000000
true
```

> **ระวัง:** FMA ไม่ได้ทำให้ผลผิดเสมอไป มันปัดเศษน้อยครั้งกว่า แต่ถ้าเทียบผลต่อกับการคำนวณอื่น ให้ใช้ค่าความคลาดเคลื่อนที่ยอมรับได้
**แบบฝึกหัด**
- FMA ทำอะไร
  - a) คูณและบวกในคำสั่งเดียว  b) หารและลบ  c) เก็บค่าในไฟล์  — เฉลย: a. fused multiply-add คือคูณแล้วบวกรวมกัน
- FMA ปัดเศษสองครั้งเสมอ — เฉลย: f. FMA ปัดเศษครั้งเดียวหลังคูณและบวก
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
double x = 4.0 * 2.0 + 1.0;
jout << x << "\n";
}
```
  ผลลัพธ์ที่ได้: `9.000000`. 4 คูณ 2 ได้ 8 บวก 1 ได้ 9
- ตัวเลือกคอมไพเลอร์ที่ปิด FMA คือ -___ — เฉลย: **nofma**. -nofma ปิดการใช้คำสั่งรวมไว้เทียบผล
- ลำดับของสูตร a * b + c: คูณ a กับ b → บวก c → ถ้าใช้ FMA ปัดเศษครั้งเดียว → ได้ผล. การคูณก่อนบวกเป็นลำดับทางคณิตศาสตร์
- ทำไมผลของ FMA อาจต่างจากการคูณแล้วบวกแยก
  - a) เพราะการปัดเศษเกิดน้อยครั้งกว่า  b) เพราะค่าเปลี่ยน  c) เพราะ FMA ไม่ใช้ตัวเลข  — เฉลย: a. จำนวนครั้งที่ปัดเศษต่างกันทำให้ผลต่างได้เล็กน้อย
**โจทย์**
- **FMA ง่าย** — คำนวณ 5.0 * 2.0 + 3.0 แล้วพิมพ์ 13.000000. ผลลัพธ์ที่ได้: `13.000000`. คำใบ้: ผลทั้งสองแบบเท่ากันสำหรับเลขนี้
- **สูตรสองขั้น** — คำนวณ x = 1.5 * 4.0 แล้ว y = x + 0.5 พิมพ์ y. ผลลัพธ์ที่ได้: `6.500000`. คำใบ้: ใช้ตัวแปรสองตัว

## thread และ race condition
**คืออะไร.** Thread คือการรันฟังก์ชันพร้อมกันกับฟังก์ชันอื่น ถ้าสอง thread เพิ่มค่าตัวแปรเดียวกันด้วย counter += 1 ค่าอาจหายได้ เพราะการเพิ่มค่ามีสามขั้นคือ อ่าน บวก เขียน ถ้าสองชุดของขั้นเหล่านี้แทรกกัน ผลจะขาด สภาพนี้เรียกว่า race condition Atomic::add ทำสามขั้นนี้เป็นขั้นเดียวที่ขัดจังหวะไม่ได้
**ทำไมต้องรู้.** โปรแกรมที่ใช้หลายแกนของซีพียูต้องแชร์ข้อมูล ถ้าแชร์โดยไม่ป้องกัน ผลจะไม่แน่นอนและหาสาเหตุยาก
**ทำอย่างไร.**

สร้าง thread ด้วย create ใส่ชื่อฟังก์ชันและอาร์กิวเมนต์ แล้วใช้ join เพื่อรอให้จบ ใช้ Atomic::add กับตัวแปรที่แชร์
**ตัวอย่าง.**

```jk
#import <stdlib>
#import <cpu>
using stdlib;
using cpu::thread;

int counter;

void work(void^ arg) {
    for i in 0..10000 { Atomic::add(@counter, 1); }
}

void main() {
    Thread a = create(work, null);
    Thread b = create(work, null);
    Thread c = create(work, null);
    a.join();
    b.join();
    c.join();
    jout << counter << "\n";
}
```

```
30000
```

> **ระวัง:** counter += 1 ใน thread หลายตัวไม่ปลอดภัย แม้บางครั้งผลดูถูก ต้องใช้ Atomic หรือกลไกล็อกทุกครั้งที่แชร์ค่า
**แบบฝึกหัด**
- race condition คืออะไร
  - a) ผลขึ้นกับลำดับที่ thread ทำงานแทรกกัน  b) การแข่งวิ่ง  c) การคอมไพล์ช้า  — เฉลย: a. เมื่อลำดับไม่แน่นอน ผลอาจผิดได้
- Atomic::add ป้องกันการแทรกของการเพิ่มค่า — เฉลย: t. ทำการอ่าน บวก เขียนเป็นขั้นเดียวที่ไม่ถูกแบ่ง
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int n = 0;
Atomic::add(@n, 5);
Atomic::add(@n, 2);
jout << n << "\n";
}
```
  ผลลัพธ์ที่ได้: `7`. Atomic::add บวกค่าลงในตัวแปร ได้ 5 แล้วบวก 2 ได้ 7
- เมธอดที่รอให้ thread จบคือ ___ — เฉลย: **join**. join รอจนกว่า thread นั้นทำงานเสร็จ
- ใช้ thread กับตัวนับที่แชร์: สร้าง thread ด้วย create → ทุก thread ใช้ Atomic::add → join ทุกตัว → พิมพ์ค่าสุดท้าย. ต้องรอให้ทุก thread จบก่อนอ่านผล
- ทำไมต้อง join thread ก่อนอ่านตัวนับ
  - a) เพื่อให้แน่ใจว่าทุก thread เพิ่มค่าเสร็จแล้ว  b) เพื่อให้ thread เร็วขึ้น  c) เพื่อปิดโปรแกรม  — เฉลย: a. ถ้าไม่รอ ค่าที่อ่านอาจยังไม่สมบูรณ์
**โจทย์**
- **ตัวนับสองตัว** — สร้าง thread สองตัวที่แต่ละตัวเพิ่มค่า 1000 ครั้ง แล้ว join ทั้งคู่ และพิมพ์ 2000. ผลลัพธ์ที่ได้: `2000`. คำใบ้: ใช้ Atomic::add กับตัวนับ
- **ห้าครั้ง** — เพิ่มตัวนับด้วย Atomic::add ห้าครั้งในโปรแกรมเดียว แล้วพิมพ์ 5. ผลลัพธ์ที่ได้: `5`. คำใบ้: ใช้ Atomic::add หนึ่งครั้งต่อหนึ่งการเพิ่ม

## คูณเมทริกซ์แบบ ijk
**คืออะไร.** การคูณเมทริกซ์ C = A * B คือ C[i][j] เท่ากับผลรวมของ A[i][k] คูณ B[k][j] เมื่อ k วนจาก 0 ถึง n-1 วิธีตรงไปตรงมาคือวน i ด้านนอก j ตรงกลาง และ k ด้านในสุด ชื่อ ijk มาจากลำดับลูปนี้
**ทำไมต้องรู้.** การคูณเมทริกซ์เป็นงานหลักของการเรียนรู้ของเครื่องและกราฟิก ถ้าเข้าใจลำดับลูปนี้ คุณจะเห็นว่าทำไมลำดับอื่นจึงเร็วกว่า
**ทำอย่างไร.**

ตั้งค่า C ให้เป็นศูนย์ก่อน แล้วสะสมผลคูณในแต่ละช่องของ C
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    int n = 2;
    int[] a = arr(4); int[] b = arr(4); int[] c = arr(4);
    a.push(1); a.push(2); a.push(3); a.push(4);
    b.push(5); b.push(6); b.push(7); b.push(8);
    for i in 0..4 { c.push(0); }
    for i in 0..n {
        for j in 0..n {
            for k in 0..n {
                c[i * n + j] += a[i * n + k] * b[k * n + j];
            }
        }
    }
    jout << c[0] << " " << c[1] << "\n";
    jout << c[2] << " " << c[3] << "\n";
}
```

```
19 22
43 50
```

> **ระวัง:** ถ้าลืมตั้งค่า C เป็นศูนย์ก่อน ผลจะผิดเพราะสะสมค่าเดิม อาเรย์ที่สร้างด้วย push ต้องถูกเติมค่าศูนย์เอง
**แบบฝึกหัด**
- ในการคูณ C[i][j] ดัชนี k ทำอะไร
  - a) วิ่งผ่านคอลัมน์ของ A และแถวของ B  b) เลือกแถวของ C  c) ไม่ทำอะไร  — เฉลย: a. k คือดัชนีที่รวมผลคูณของแถว A กับคอลัมน์ B
- ในการคูณ A * B จำนวนคอลัมน์ของ A ต้องเท่ากับจำนวนแถวของ B — เฉลย: t. ถ้าไม่เท่ากันจะคูณกันไม่ได้
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int a = 2;
int b = 3;
jout << a * b + a << "\n";
}
```
  ผลลัพธ์ที่ได้: `8`. 2 คูณ 3 ได้ 6 บวก 2 ได้ 8
- ลำดับลูปแบบตรงไปตรงมาคือ i, j แล้วตามด้วย ___ — เฉลย: **k**. ตัวสุดท้ายคือ k
- คูณเมทริกซ์ 2x2: ตั้งค่า C เป็นศูนย์ → วน i และ j → วน k สะสมผลคูณ → พิมพ์ค่าแต่ละช่อง. ต้องเตรียมค่าศูนย์ก่อนสะสม
- ทำไมดัชนีเขียนเป็น i * n + j
  - a) เพราะเก็บตารางแบบแถวต่อกันในอาเรย์มิติเดียว  b) เพราะ n ต้องคูณ  c) เพราะ j อยู่ก่อน  — เฉลย: a. เมทริกซ์ถูกเก็บเป็นแถวติดกันในอาเรย์เดียว
**โจทย์**
- **คูณด้วยเอกลักษณ์** — ใช้ A = [[1,2],[3,4]] และ B = [[1,0],[0,1]] แล้วพิมพ์ C[0] กับ C[3] คั่นด้วยช่องว่าง. ผลลัพธ์ที่ได้: `1 4`. คำใบ้: ผลคูณกับเมทริกซ์เอกลักษณ์ได้ A เอง
- **ผลคูณ 19** — ใช้ A = [[1,2],[3,4]] และ B = [[5,6],[7,8]] แล้วพิมพ์ C[0]. ผลลัพธ์ที่ได้: `19`. คำใบ้: 1 * 5 + 2 * 7 = 19

## ลำดับลูปของการคูณเมทริกซ์
**คืออะไร.** ลำดับของลูป i j k มีหกแบบ ทุกแบบให้คำตอบเท่ากัน แต่ลำดับ ikj ทำให้ลูปด้านในเดินบนแถวของ B และ C ซึ่งติดกันในความจำ cache ทำงานได้ดี ส่วนลำดับ ijk เดินบน B ตามคอลัมน์ที่กระโดด จึงช้ากว่า
**ทำไมต้องรู้.** เมื่อเขียนลูปซ้อนหลายชั้น ลำดับของลูปมีผลต่อความเร็วมาก ทั้งที่คำตอบไม่เปลี่ยน ซึ่งเป็นสิ่งที่ผู้เขียนโปรแกรมประสิทธิภาพต้องรู้
**ทำอย่างไร.**

ย้ายลูป k ขึ้นมาอยู่กลาง ทำให้ลูปด้านในสุดวนคอลัมน์ j ของ C และ B ตามแถว
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    int n = 3;
    int[] a = arr(9); int[] b = arr(9); int[] c1 = arr(9); int[] c2 = arr(9);
    for i in 0..9 { a.push(i + 1); b.push(9 - i); c1.push(0); c2.push(0); }
    for i in 0..n {
        for j in 0..n {
            for k in 0..n { c1[i * n + j] += a[i * n + k] * b[k * n + j]; }
        }
    }
    for i in 0..n {
        for k in 0..n {
            for j in 0..n { c2[i * n + j] += a[i * n + k] * b[k * n + j]; }
        }
    }
    bool same = true;
    for i in 0..9 { if c1[i] != c2[i] { same = false; } }
    jout << "same " << same << "\n";
    jout << c2[0] << " " << c2[8] << "\n";
}
```

```
same true
30 90
```

> **ระวัง:** ลำดับลูปเปลี่ยนความเร็วได้มาก แต่ต้องทดสอบว่าคำตอบเหมือนเดิม ก่อนจะเชื่อว่าการปรับนั้นถูกต้อง
**แบบฝึกหัด**
- ลำดับ ikj ทำให้ลูปในวนตามแถวของ B และ C ได้อย่างไร
  - a) ดัชนี j อยู่ด้านในสุด จึงเดินช่องที่ติดกัน  b) ไม่มีผล  c) ทำให้ผลต่างกัน  — เฉลย: a. ลูป j ด้านในทำให้เข้าถึงช่องที่ติดกัน
- ลำดับลูปต่างกันทำให้คำตอบของการคูณเมทริกซ์ต่างกันเสมอ — เฉลย: f. คำตอบเท่าเดิม เพราะเป็นการบวกผลคูณชุดเดิม เพียงลำดับต่างกัน
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int s = 0;
for i in 0..2 {
    for k in 0..3 { s += 1; }
}
jout << s << "\n";
}
```
  ผลลัพธ์ที่ได้: `6`. ลูปนอก 2 รอบ ลูปใน 3 รอบ รวมหกครั้ง
- การย้ายลูป k ไปอยู่กลาง ทำให้ได้ลำดับ i, k แล้วตามด้วย ___ — เฉลย: **j**. ลำดับใหม่คือ i, k, j
- ทดสอบลำดับลูปใหม่: เขียนเวอร์ชันเดิม → เขียนเวอร์ชันใหม่ → เทียบผลทุกช่อง → วัดเวลาถ้าผลเหมือน. ต้องแน่ใจว่าผลเหมือนก่อนวัดความเร็ว
- ทำไมต้องเทียบผลก่อนเชื่อการปรับลูป
  - a) เพราะการเขียนผิดอาจทำให้ผลต่างได้  b) เพราะคอมไพเลอร์ไม่ทำงาน  c) เพราะเวลาเปลี่ยน  — เฉลย: a. ผลต้องเหมือนเดิมเสมอ ถ้าไม่เหมือน แปลว่าลูปผิด
**โจทย์**
- **สลับลูป** — ใช้ A = [[1,2],[3,4]] และ B = [[5,6],[7,8]] คูณด้วยลำดับ i, k, j แล้วพิมพ์ C[0]. ผลลัพธ์ที่ได้: `19`. คำใบ้: ลำดับต่างแต่ผลเท่าเดิม
- **เทียบลำดับ** — เทียบผลของ ijk กับ ikj บนเมทริกซ์ 2x2 เดียวกัน แล้วพิมพ์ same true. ผลลัพธ์ที่ได้: `same true`. คำใบ้: ผลทั้งสองต้องเท่ากัน

## blocking: แบ่งการคูณเป็นก้อน
**คืออะไร.** Blocking คือการแบ่งเมทริกซ์เป็นก้อนย่อยที่พอดีกับ cache แล้วคูณทีละก้อน ก้อนที่ถูกใช้ซ้ำจะอยู่ใน cache ระหว่างทำงาน จึงไม่ต้องดึงจากแรมซ้ำ คำตอบยังเหมือนเดิม เพราะเป็นเพียงการจัดลำดับการบวกใหม่โดยรายการผลคูณยังครบเท่าเดิม
**ทำไมต้องรู้.** เมทริกซ์ใหญ่ไม่พอดี cache ทั้งหมด การแบ่งก้อนทำให้ใช้ cache ได้ดีขึ้นมาก ไลบรารีคณิตศาสตร์เกือบทุกตัวใช้เทคนิคนี้
**ทำอย่างไร.**

วนก้อนด้านนอกด้วยขนาด bs แล้วคูณเฉพาะช่วงของก้อนแต่ละก้อนด้วยลูปภายใน
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    int n = 4;
    int bs = 2;
    int[] a = arr(16); int[] b = arr(16); int[] c = arr(16);
    for i in 0..16 { a.push(i % 5); b.push((i * 3) % 7); c.push(0); }
    int ii = 0;
    while ii < n {
        int jj = 0;
        while jj < n {
            for i in ii..ii + bs {
                for k in 0..n {
                    for j in jj..jj + bs { c[i * n + j] += a[i * n + k] * b[k * n + j]; }
                }
            }
            jj += bs;
        }
        ii += bs;
    }
    int plain = 0;
    for i in 0..n {
        for j in 0..n {
            for k in 0..n { plain += a[i * n + k] * b[k * n + j]; }
        }
    }
    int total = 0;
    for i in 0..16 { total += c[i]; }
    jout << "blocked total " << total << "\n";
    jout << "plain total " << plain << "\n";
}
```

```
blocked total 339
plain total 339
```

> **ระวัง:** Blocking ต้องครอบคลุมทุกช่องพอดีหนึ่งครั้ง ตรวจขอบของก้อนสุดท้ายให้ดีเมื่อ n ไม่หารด้วยขนาดก้อนลงตัว
**แบบฝึกหัด**
- ทำไมก้อนข้อมูลขนาดเล็กจึงเร็วขึ้น
  - a) เพราะอยู่ใน cache และถูกใช้ซ้ำ  b) เพราะไม่ต้องบวก  c) เพราะเป็นทศนิยม  — เฉลย: a. ก้อนที่พอดี cache ถูกใช้หลายครั้งโดยไม่ต้องดึงจากแรม
- blocking เปลี่ยนคำตอบของการคูณเมทริกซ์ — เฉลย: f. ยังคูณและบวกทุกคู่ครบ เพียงจัดลำดับใหม่
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int total = 0;
for i in 0..4 {
    if i % 2 == 0 { total += i; }
}
jout << total << "\n";
}
```
  ผลลัพธ์ที่ได้: `2`. ลูป 0 ถึง 3 พบเลขคู่ 0 และ 2 รวมได้ 2
- การแบ่งการคูณเมทริกซ์เป็นก้อนเรียกว่า ___ — เฉลย: **blocking**. blocking หมายถึงการแบ่งเป็นก้อน
- การเขียนการคูณแบบ blocking: เลือกขนาดก้อน → วนก้อนด้านนอก → วนภายในก้อน → ตรวจผลเทียบกับแบบธรรมดา. ต้องเทียบผลกับวิธีธรรมดาเสมอ
- ต้องระวังอะไรเมื่อ n ไม่หารด้วยขนาดก้อนลงตัว
  - a) ก้อนสุดท้ายต้องครอบคลุมช่องที่เหลือ  b) ไม่ต้องระวัง  c) ต้องเปลี่ยนชนิด  — เฉลย: a. ถ้าขอบของก้อนผิด บางช่องจะถูกข้ามหรือซ้ำ
**โจทย์**
- **ก้อนสองขนาด** — ทำ blocking ของ A = [[1,2],[3,4]] กับ B = [[1,0],[0,1]] ขนาด 2 แล้วพิมพ์ C[0]. ผลลัพธ์ที่ได้: `1`. คำใบ้: ผลคูณกับเอกลักษณ์ได้ A
- **ผลรวมทุกช่อง** — คูณ A = [[1,2],[3,4]] กับ B = [[5,6],[7,8]] แล้วพิมพ์ผลรวมของทั้ง 4 ช่องของ C. ผลลัพธ์ที่ได้: `134`. คำใบ้: 19 + 22 + 43 + 50 = 134

## ทำโค้ดให้เร็วและวัดให้ยุติธรรม
**คืออะไร.** การทำให้โปรแกรมเร็วเริ่มจากการวัด ไม่ใช่การเดา ใช้ Time::mono_ns() อ่านนาฬิกาก่อนและหลังงาน แล้วลบกันเป็นนาโนวินาที รันหลายรอบและเลือกเวลาที่สั้นที่สุด เพราะการรันแต่ละครั้งมีสัญญาณรบกวนจากระบบ
**ทำไมต้องรู้.** ถ้าไม่วัด คุณอาจปรับส่วนที่ไม่ใช่คอขวดและเสียเวลา การวัดอย่างยุติธรรมทำให้เปรียบเทียบเวอร์ชันได้ถูกต้อง
**ทำอย่างไร.**

เก็บเวลาเริ่ม ทำงาน แล้วเก็บเวลาหลัง ลบกัน ทำซ้ำหลายรอบ และตรวจว่าคำตอบเหมือนเดิมทุกครั้งที่วัด
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

int work(int[] a) {
    int s = 0;
    for i in 0..a.len { s += a[i] * 3; }
    return s;
}

void main() {
    int[] a = arr(1000);
    for i in 0..1000 { a.push(i % 10); }
    int best = 0;
    int check = 0;
    for run in 0..5 {
        int t0 = Time::mono_ns();
        check = work(a);
        int dt = Time::mono_ns() - t0;
        if run == 0 || dt < best { best = dt; }
    }
    if Time::mono_ns() >= 0 { jout << "ok: the clock went forward\n"; }
    jout << "checksum: " << check << "\n";
}
```

```
ok: the clock went forward
checksum: 13500
```

> **ระวัง:** เวลาที่วัดได้เปลี่ยนทุกครั้ง อย่าเอาผลวัดจากการรันเดียวไปเทียบ และตรวจค่า checksum ทุกครั้งว่าไม่เปลี่ยน
**แบบฝึกหัด**
- ทำไมควรเลือกเวลาที่สั้นที่สุดจากหลายรอบ
  - a) เพราะสัญญาณรบกวนทำให้บางรอบช้าเกินจริง  b) เพราะเวลาที่สั้นมักผิด  c) เพราะไม่ต้องวัด  — เฉลย: a. การรบกวนจากระบบทำให้เวลาเพิ่ม ค่าน้อยที่สุดเป็นตัวแทนที่ดีกว่า
- ผลวัดเวลาเหมือนกันทุกครั้งที่รันโปรแกรม — เฉลย: f. เวลาเปลี่ยนทุกครั้ง เพราะระบบทำงานอื่นพร้อมกัน
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int a = 4;
int b = a * 3;
jout << b << "\n";
}
```
  ผลลัพธ์ที่ได้: `12`. 4 คูณ 3 ได้ 12 ค่าแบบนี้ไม่เปลี่ยนตามเวลา
- สิ่งที่ต้องตรวจทุกครั้งหลังปรับโค้ดให้เร็วคือ ___ ของผลลัพธ์ — เฉลย: **checksum**. checksum ยืนยันว่าคำตอบยังถูกต้อง
- ขั้นตอนการทำโค้ดให้เร็ว: วัดเวลาเดิม → หาคอขวด → ปรับและตรวจคำตอบ → วัดซ้ำและเทียบ. ต้องรู้คอขวดก่อนปรับ และต้องตรวจคำตอบทุกครั้ง
- ก่อนปรับโค้ดให้เร็วควรทำอย่างไร
  - a) วัดเวลาก่อนและเก็บคำตอบอ้างอิง  b) ลบโค้ดเก่า  c) ไม่ต้องวัด  — เฉลย: a. ต้องมีค่าอ้างอิงเพื่อเทียบ
**โจทย์**
- **นับเวลา** — ใช้ Time::mono_ns อ่านเวลาสองครั้ง แล้วพิมพ์ done ถ้าเวลาหลังไม่น้อยกว่าเวลาก่อน. ผลลัพธ์ที่ได้: `done`. คำใบ้: ใช้ if กับผลต่างของเวลา
- **คำตอบอ้างอิง** — รวม 3 * i สำหรับ i 0 ถึง 9 แล้วพิมพ์ checksum 135. ผลลัพธ์ที่ได้: `checksum 135`. คำใบ้: ผลรวม 3 คูณ 45 ได้ 135
