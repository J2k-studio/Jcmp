# Basics

## คอมพิวเตอร์คืออะไร
**คืออะไร.** คอมพิวเตอร์คือเครื่องที่รับข้อมูลเข้าไป ทำการคำนวณหรือจัดการข้อมูลนั้นตามชุดคำสั่ง แล้วส่งผลลัพธ์ออกมา มันทำงานเร็ว ทำซ้ำได้เหมือนเดิมทุกครั้ง และไม่เหนื่อยหรือเผลอ แต่มันทำได้เฉพาะสิ่งที่มีคำสั่งบอกไว้เท่านั้น
**ทำไมต้องรู้.** ทุกอย่างที่คุณใช้อยู่ ทั้งโทรศัพท์ ตู้เอทีเอ็ม ไฟจราจร และเครื่องคิดเลข ล้วนเป็นคอมพิวเตอร์ที่ทำตามคำสั่ง เมื่อเข้าใจว่ามันทำตามคำสั่งเท่านั้น คุณจะเข้าใจว่าทำไมโปรแกรมต้องละเอียดและถูกต้องทุกบรรทัด
**ทำอย่างไร.**

วงจรการทำงานมีสามขั้น: รับข้อมูลเข้า (input) ประมวลผล (process) แล้วส่งผลลัพธ์ออก (output)
ลองดูเครื่องคิดเลข: กดเลข 2 แล้วบวก แล้วกด 3 แล้วกดเท่ากับ ข้อมูลเข้าคือ 2 บวก 3 การประมวลผลคือการบวก ผลลัพธ์ที่โชว์บนจอคือ 5
โปรแกรมด้านล่างทำวงจรเดียวกันในรูปของโค้ด ข้อความที่เขียนหลัง jout คือผลลัพธ์
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    int a = 2;
    int b = 3;
    int sum = a + b;
    jout << "result " << sum << "\n";
}
```

```
result 5
```

> **ระวัง:** คนมักคิดว่าคอมพิวเตอร์เข้าใจความต้องการของเราเอง มันไม่เข้าใจ มันทำตามบรรทัดที่เขียนเท่านั้น ถ้าผลลัพธ์ผิด ให้อ่านโค้ดทีละบรรทัดก่อนโทษเครื่อง
**แบบฝึกหัด**
- คอมพิวเตอร์ทำงานอย่างไรเป็นหลัก
  - a) ทำตามชุดคำสั่งที่มีคนเขียนไว้  b) คิดและตัดสินใจเองได้ทุกเรื่อง  c) เดาคำตอบที่ถูกที่สุดจากอินเทอร์เน็ต  — เฉลย: a. คอมพิวเตอร์ไม่มีความเข้าใจเอง มันเดินตามคำสั่งทีละขั้น ความฉลาดที่เราเห็นมาจากคำสั่งที่คนเขียนไว้
- คอมพิวเตอร์ทำสิ่งที่ไม่มีคำสั่งบอก ได้เองโดยอัตโนมัติ — เฉลย: f. ถ้าไม่มีคำสั่ง มันไม่รู้ว่าต้องทำอะไร ต่อให้เร็วแค่ไหนก็ไม่ทำงานที่ไม่ได้ถูกสั่ง
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int x = 6;
jout << x * 7 << "\n";
}
```
  ผลลัพธ์ที่ได้: `42`. 6 คูณ 7 เท่ากับ 42 เครื่องทำตามบรรทัดจากบนลงล่าง ไม่มีอะไรนอกเหนือจากนี้
- วงจรการทำงานของคอมพิวเตอร์มีสามขั้น คือรับข้อมูลเข้า ประมวลผล และส่งผลลัพธ์ ___ — เฉลย: **output**. คำว่า output แปลว่าผลลัพธ์ที่ออกจากเครื่อง ตรงข้ามกับ input ที่เข้าเครื่อง
- ลำดับของการทำงานหนึ่งรอบของคอมพิวเตอร์: รับข้อมูลเข้า → ประมวลผลตามคำสั่ง → ส่งผลลัพธ์ออก → รอข้อมูลชุดต่อไป. ต้องรู้ข้อมูลก่อนจึงประมวลผลได้ และต้องประมวลผลก่อนจะมีผลลัพธ์ให้ส่งออก
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
jout << 10 - 4 * 2 << "\n";
}
```
  ผลลัพธ์ที่ได้: `2`. การคูณทำก่อนการลบ จึงได้ 4 * 2 เท่ากับ 8 แล้วจึงเอาไปลบ 10 ได้ 2 ลำดับนี้เหมือนในวิชาเลขที่เราเรียนมา
**โจทย์**
- **พื้นที่สี่เหลี่ยม** — เขียนโปรแกรมที่เก็บความกว้าง 4 และความสูง 5 ในตัวแปร int แล้วคูณกัน พิมพ์ข้อความ area ตามด้วยพื้นที่. ผลลัพธ์ที่ได้: `area 20`. คำใบ้: ใช้ int w = 4; และ jout << "area " << w * h << "\n";
- **ซื้อของ** — เก็บราคา 25 บาทและจำนวน 4 ชิ้นในตัวแปร แล้วพิมพ์ยอดรวมในรูป total 100. ผลลัพธ์ที่ได้: `total 100`. คำใบ้: ยอดรวมคือราคาคูณจำนวน ไม่ต้องพิมพ์ทีละชิ้น

## ฮาร์ดแวร์และซอฟต์แวร์
**คืออะไร.** ฮาร์ดแวร์คือส่วนที่จับต้องได้ เช่น ซีพียู แรม จอ และแป้นพิมพ์ ซอฟต์แวร์คือชุดคำสั่งที่เก็บเป็นข้อมูล เช่นเว็บเบราว์เซอร์ ระบบปฏิบัติการ หรือโปรแกรมที่คุณเขียนเอง ซอฟต์แวร์ไม่มีตัวจริง แต่มันต้องมีฮาร์ดแวร์ให้ทำงาน
**ทำไมต้องรู้.** ถ้าคุณจะซื้อหรือแก้ปัญหาคอมพิวเตอร์ คุณต้องแยกได้ว่าปัญหาอยู่ที่เครื่องหรือที่โปรแกรม เช่นจอแตกเป็นฮาร์ดแวร์ แต่แอปค้างเป็นซอฟต์แวร์ การเขียนโปรแกรมคือการสร้างซอฟต์แวร์ที่วิ่งบนฮาร์ดแวร์ที่มีอยู่
**ทำอย่างไร.**

แยกทีละชิ้นว่าเป็นอะไร: ถ้าเอาค้อนทุบได้ มันคือฮาร์ดแวร์ ถ้าลบได้โดยไม่ทำให้เครื่องพัง มันคือซอฟต์แวร์
โปรแกรมที่คุณเขียนเป็นซอฟต์แวร์ ตัวคอมไพล์เลอร์ก็เป็นซอฟต์แวร์ ไฟล์ที่คอมไพล์แล้วก็เป็นซอฟต์แวร์อีกตัวหนึ่ง ทั้งสามทำงานบนซีพียูตัวเดียวกันได้
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    // this text is software: a program that the computer runs
    int speed = 3;
    int hours = 4;
    jout << "distance " << speed * hours << " km\n";
}
```

```
distance 12 km
```

> **ระวัง:** บางคนเรียกทั้งเครื่องว่าโปรแกรม ทำให้คุยกันยาก ให้ถามตัวเองว่าสิ่งนั้นจับต้องได้หรือไม่ ถ้าลบไฟล์ได้เร็วกว่าการเปลี่ยนชิ้นส่วนก็คือซอฟต์แวร์
**แบบฝึกหัด**
- ข้อใดเป็นฮาร์ดแวร์
  - a) แป้นพิมพ์  b) เว็บเบราว์เซอร์  c) ภาษา J2K  — เฉลย: a. แป้นพิมพ์เป็นชิ้นส่วนจับต้องได้ ส่วนเบราว์เซอร์และภาษาเป็นชุดคำสั่งที่เก็บเป็นข้อมูล
- ซอฟต์แวร์สามารถทำงานได้เองโดยไม่ต้องมีฮาร์ดแวร์ — เฉลย: f. ซอฟต์แวร์เป็นคำสั่งที่ต้องให้ซีพียูอ่านและทำ ถ้าไม่มีเครื่อง มันเป็นเพียงข้อความบนกระดาษหรือบนดิสก์
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int speed = 3;
jout << "km " << speed * 4 << "\n";
}
```
  ผลลัพธ์ที่ได้: `km 12`. โค้ดเป็นซอฟต์แวร์ มันให้ผลลัพธ์เท่ากับที่คำนวณได้ 3 คูณ 4 เท่ากับ 12
- ชิ้นส่วนที่จับต้องได้ของคอมพิวเตอร์เรียกว่า ___ — เฉลย: **hardware**. ฮาร์ดแวร์คือเหล็ก ซิลิคอน และสายที่มองเห็นและสัมผัสได้ ซอฟต์แวร์คือคำสั่งที่เก็บในนั้น
- การเปลี่ยนโค้ดที่เขียนให้เป็นโปรแกรมที่รันได้: เขียนโค้ดเป็นไฟล์ข้อความ → คอมไพล์ด้วย jcmp → ได้ไฟล์โปรแกรม → สั่งรันบนซีพียู. โค้ดข้อความยังรันเองไม่ได้ ต้องถูกแปลงเป็นคำสั่งของเครื่องก่อน
- เมื่อเปิดโปรแกรมแล้วโปรแกรมค้าง ปัญหาน่าจะอยู่ที่ไหนก่อน
  - a) ซอฟต์แวร์ เช่นคำสั่งที่ทำให้วนไม่จบ  b) ฮาร์ดแวร์ เช่นแรมเสีย  c) ไฟที่บ้านดับ  — เฉลย: a. อาการค้างมักมาจากคำสั่ง แต่ต้องตรวจก่อนว่าเครื่องทำงานอื่นได้ปกติหรือไม่
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int n = 0;
n += 5;
n += 5;
jout << n << "\n";
}
```
  ผลลัพธ์ที่ได้: `10`. ตัวแปร n เก็บค่า 0 แล้วถูกบวก 5 ถึงสองครั้ง โดยค่าที่เก็บอยู่ถูกเขียนทับทุกครั้ง
**โจทย์**
- **ตัวนับ** — เขียนโปรแกรมที่เก็บค่า 1 ในตัวแปร n แล้วบวก 2 ไปสามครั้ง พิมพ์ค่าสุดท้ายของ n. ผลลัพธ์ที่ได้: `7`. คำใบ้: ใช้ n += 2; สามครั้ง ค่าเริ่มต้นคือ 1

## ซีพียู: ส่วนที่ทำตามคำสั่ง
**คืออะไร.** ซีพียู (CPU) คือหน่วยประมวลผลกลาง มันอ่านคำสั่งทีละคำสั่งจากหน่วยความจำ แปลความหมายของคำสั่งนั้น แล้วทำมัน เช่นการบวกหรือการเทียบค่า ความเร็วของซีพียูวัดเป็นจำนวนรอบต่อวินาที หรือเฮิรตซ์ แต่จำนวนคำสั่งที่ทำได้ในหนึ่งรอบก็สำคัญพอกัน
**ทำไมต้องรู้.** ทุกโปรแกรมที่คุณเขียนจะกลายเป็นคำสั่งสำหรับซีพียูสุดท้าย ถ้าคุณรู้ว่าซีพียูทำอะไรในแต่ละรอบ คุณจะเข้าใจว่าทำไมลูปที่ยาวนานช้า และทำไมการนับจำนวนครั้งจึงสำคัญ
**ทำอย่างไร.**

ซีพียูทำงานเป็นวงซ้ำ: ดึงคำสั่งจากหน่วยความจำ (fetch) แปลความ (decode) แล้วทำ (execute) จากนั้นไปคำสั่งถัดไป
คำสั่งที่ซีพียูเข้าใจคือตัวเลขในรูปแบบของเครื่อง ภาษาที่มนุษย์อ่านได้อย่าง J2K ถูกแปลเป็นตัวเลขเหล่านั้นโดยคอมไพเลอร์
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    // each turn of this loop is a few CPU instructions: fetch, decode, execute
    int total = 0;
    for i in 1..5 {
        total += i;
    }
    jout << "sum " << total << "\n";
}
```

```
sum 10
```

> **ระวัง:** ซีพียูเร็วไม่ได้หมายความว่าโปรแกรมเร็ว การวนลูปหนึ่งล้านรอบที่ทำงานซ้ำโดยไม่จำเป็น ยังช้ากว่าโปรแกรมที่คิดให้ดีก่อนเริ่มลูป
**แบบฝึกหัด**
- ซีพียูทำงานเป็นวงซ้ำสามขั้นตามลำดับใด
  - a) ดึง แปลความ แล้วทำ  b) ทำ ดึง แล้วแปลความ  c) แปลความ ส่งออก แล้วดึง  — เฉลย: a. ซีพียูต้องดึงคำสั่งมาก่อนจึงแปลความได้ และต้องแปลความก่อนจะทำได้
- ซีพียูทำคำสั่งหลายคำสั่งพร้อมกันได้ทั้งหมดในรอบเดียวเสมอ — เฉลย: f. ซีพียูบางตัวทำหลายงานพร้อมกันได้ในบางส่วน แต่คำสั่งถัดไปมักต้องรอผลจากคำสั่งก่อนหน้า จึงไม่ใช่ทุกอย่างพร้อมกันเสมอ
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int sum = 0;
for i in 1..4 { sum += i; }
jout << sum << "\n";
}
```
  ผลลัพธ์ที่ได้: `6`. ลูป 1..4 นับ 1, 2, 3 โดยไม่รวม 4 เมื่อรวมกันได้ 6
- ความเร็วของซีพียูวัดเป็นจำนวนรอบต่อวินาที เรียกว่า ___ — เฉลย: **hertz**. เฮิรตซ์ (Hz) คือรอบต่อวินาที เช่น 2 GHz หมายถึงสองพันล้านรอบต่อวินาที
- ซีพียูทำคำสั่งหนึ่งคำสั่ง: ดึงคำสั่งจากหน่วยความจำ → แปลความหมายของคำสั่ง → ทำคำสั่ง → ไปคำสั่งถัดไป. ลำดับนี้เกิดซ้ำทุกคำสั่ง ถ้าขั้นแรกไม่ได้ทำ ขั้นที่เหลือก็ไม่มีอะไรให้ทำ
- ทำไมลูปที่วนหนึ่งล้านรอบจึงช้ากว่าการคำนวณสูตรเดียว
  - a) เพราะต้องทำคำสั่งซ้ำจำนวนมาก  b) เพราะซีพียูนอนหลับระหว่างลูป  c) เพราะตัวอักษรในโค้ดยาวเกินไป  — เฉลย: a. ลูปทุกรอบทำคำสั่งจริงซ้ำอีก ยิ่งรอบมาก ยิ่งต้องดึงและทำคำสั่งมาก
**โจทย์**
- **นับผลรวม** — เขียนโปรแกรมที่บวกเลข 1 ถึง 100 ด้วย for แล้วพิมพ์ข้อความ sum ตามด้วยผลรวม. ผลลัพธ์ที่ได้: `sum 5050`. คำใบ้: ใช้ for k in 1..101 ซึ่งหมายถึง 1 ถึง 100
- **นับเฉพาะคู่** — เขียนโปรแกรมที่รวมเฉพาะเลขคู่ตั้งแต่ 1 ถึง 10 แล้วพิมพ์ even 30. ผลลัพธ์ที่ได้: `even 30`. คำใบ้: ใช้ if กับ % 2 == 0 ภายในลูป

## หน่วยความจำ (RAM)
**คืออะไร.** RAM คือหน่วยความจำที่ทำงานอยู่ ทุกตัวแปรที่โปรแกรมใช้จะถูกเก็บในนี้ แต่ละช่องมีที่อยู่ของตัวเองเหมือนบ้านเลขที่ เมื่อปิดเครื่อง ข้อมูลในแรมจะหายหมด ทำให้มันต่างจากที่เก็บถาวรที่จะคงอยู่
**ทำไมต้องรู้.** ซีพียูทำงานได้เร็วกว่าแรมมาก ถ้าโปรแกรมใช้แรมเกินความจำที่มี ระบบจะช้าลงมาก และโปรแกรมที่ล่มมักเกิดจากการเข้าถึงตำแหน่งในแรมที่ไม่ควรเข้าถึง
**ทำอย่างไร.**

เมื่อคุณประกาศตัวแปร ระบบจองช่องในแรมให้ เมื่อคุณเปลี่ยนค่า ค่าเก่าจะถูกเขียนทับ
ใน J2K จำนวนเต็ม int มีขนาด 8 ไบต์ ดังนั้น int ที่เก็บตัวเลขหนึ่งตัวใช้แรม 8 ไบต์
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    int a = 10;
    int b = 20;
    a = a + b;
    jout << "a = " << a << ", b = " << b << "\n";
    jout << "one int takes " << sizeof(int) << " bytes\n";
}
```

```
a = 30, b = 20
one int takes 8 bytes
```

> **ระวัง:** การเปลี่ยนค่าตัวแปรเป็นการเขียนทับ ค่าเก่าหายไป ถ้าต้องการเก็บค่าเก่าไว้ ให้ใช้ตัวแปรอีกตัวหนึ่ง
**แบบฝึกหัด**
- ข้อมูลในตัวแปรจะหายเมื่อใด
  - a) เมื่อปิดเครื่องหรือโปรแกรมจบ  b) เมื่อพิมพ์บรรทัดถัดไป  c) ไม่มีวันหาย  — เฉลย: a. แรมเป็นหน่วยความจำชั่วคราวที่ต้องใช้ไฟ ข้อมูลที่ต้องอยู่ต่อควรเก็บในที่เก็บถาวร
- แรมกับซีพียูเป็นชิ้นเดียวกัน จึงเร็วเท่ากันเสมอ — เฉลย: f. ซีพียูเร็วกว่าการอ่านแรมมาก ซีพียูจึงมีแคชเล็ก ๆ ไว้เก็บข้อมูลที่ใช้บ่อย
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int x = 4;
x = x * x;
x = x + 1;
jout << x << "\n";
}
```
  ผลลัพธ์ที่ได้: `17`. x เริ่มเป็น 4 แล้วเปลี่ยนเป็น 16 และ 17 ทุกครั้งเขียนทับค่าเดิมในช่องเดิม
- เมื่อเขียนค่าใหม่ลงตัวแปร ค่า ___ (เดิม ตามภาษาอังกฤษ) จะถูกทับและหายไป — เฉลย: **old**. ค่าเดิมถูกเขียนทับในช่องเดิม ค่าเดิมจึงหายไป
- ลำดับการทำงานของตัวแปรหนึ่งตัว: ประกาศ int x → จองช่องในแรม → ให้ค่า 5 → อ่านค่าเพื่อพิมพ์. ต้องมีช่องก่อนจึงเก็บค่าได้ แล้วค่าจึงถูกอ่านได้
- ไบต์คืออะไร
  - a) หน่วยวัดขนาดข้อมูลที่เท่ากับ 8 บิต  b) ชื่อของซีพียู  c) ชื่อของแรม  — เฉลย: a. ไบต์คือหน่วยเล็กที่ใช้วัดขนาด แต่ละไบต์มีแปดบิต
**โจทย์**
- **เขียนทับ** — ตัวแปร n เริ่มเป็น 3 ให้เปลี่ยนเป็น n * 10 แล้วพิมพ์ค่า n. ผลลัพธ์ที่ได้: `30`. คำใบ้: เมื่อเปลี่ยนค่าแล้ว ค่า 3 จะหายไป
- **สองตัวแปร** — เก็บ 7 ใน a และ 5 ใน b สลับค่าโดยใช้ตัวแปรที่สาม tmp แล้วพิมพ์ a กับ b. ผลลัพธ์ที่ได้: `a 5 b 7`. คำใบ้: ค่าแรกต้องถูกเก็บไว้ก่อนเขียนทับ

## ที่เก็บข้อมูลถาวร
**คืออะไร.** ที่เก็บข้อมูลถาวรคือส่วนที่เก็บข้อมูลไว้แม้ปิดเครื่อง เช่นฮาร์ดดิสก์ เอสเอสดี และแฟลชในโทรศัพท์ ข้อมูลเป็นไฟล์ที่มีชื่อ เข้าถึงได้ช้ากว่าแรม แต่ความจุมากกว่ามาก
**ทำไมต้องรู้.** งานเขียนของคุณ รูปถ่าย และโปรแกรมที่ติดตั้งอยู่ในที่เก็บถาวร ถ้าโปรแกรมต้องการบันทึกผลไว้ใช้ในวันต่อไป มันต้องเขียนลงไฟล์ ไม่ใช่เก็บแค่ในตัวแปร
**ทำอย่างไร.**

เปิดไฟล์ด้วย File::open และบอกโหมด Write หรือ Read เขียนด้วย File::write และอ่านด้วย File::read_line แล้วปิดด้วย File::close เสมอ
ไฟล์ที่เปิดไว้แล้วไม่ปิดจะค้างอยู่ในระบบ ทำให้ข้อมูลบางส่วนยังไม่ถูกเขียนลงดิสก์จริง
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    i32 f = File::open("note.txt", FileMode::Write);
    File::write(f, "saved on disk\n");
    File::close(f);
    char line[64];
    i32 g = File::open("note.txt", FileMode::Read);
    File::read_line(g, line);
    File::close(g);
    jout << line << "\n";
}
```

```
saved on disk
```

> **ระวัง:** ลืมปิดไฟล์ หรือเปิดไฟล์ที่ไม่มีอยู่ในโหมดอ่าน จะไม่ได้ข้อมูล ให้เช็กว่าค่าที่ได้จาก File::open ไม่น้อยกว่า 0
**แบบฝึกหัด**
- ข้อใดคือที่เก็บถาวร
  - a) ฮาร์ดดิสก์  b) แรม  c) ซีพียู  — เฉลย: a. ฮาร์ดดิสก์เก็บข้อมูลไว้แม้ไฟดับ ส่วนแรมและซีพียูไม่เก็บข้อมูลไว้เมื่อปิดเครื่อง
- ข้อมูลในไฟล์ยังอยู่หลังจากปิดเครื่องแล้วเปิดใหม่ — เฉลย: t. ไฟล์เขียนลงที่เก็บถาวรแล้ว เป็นคุณสมบัติหลักของที่เก็บถาวร
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
char line[64];
i32 f = File::open("note.txt", FileMode::Write);
File::write(f, "hi\n");
File::close(f);
i32 g = File::open("note.txt", FileMode::Read);
File::read_line(g, line);
File::close(g);
jout << line << "\n";
}
```
  ผลลัพธ์ที่ได้: `hi`. ข้อความถูกเขียนลงไฟล์แล้วอ่านกลับมาในบรรทัดเดียวกัน ไม่มีค่าที่ไม่รู้จักแทรกเข้ามา
- การบันทึกข้อมูลให้อยู่หลังปิดโปรแกรมต้องเขียนลง ___ — เฉลย: **file**. ไฟล์คือหน่วยของข้อมูลที่มีชื่อบนที่เก็บถาวร
- การเขียนไฟล์ข้อความหนึ่งไฟล์: เปิดไฟล์โหมด Write → เขียนข้อความ → ปิดไฟล์ → เปิดอีกครั้งเพื่ออ่าน. ต้องปิดหลังเขียนก่อนจึงอ่านได้ครบ
- ทำไมที่เก็บถาวรจึงช้ากว่าแรม
  - a) เพราะต้องอ่านจากจานหรือแฟลช ซึ่งกลไกช้ากว่า  b) เพราะเป็นของเก่า  c) เพราะมีแค่บางไบต์  — เฉลย: a. อุปกรณ์เก็บถาวรใช้กลไกหรือวิธีที่ช้ากว่าแรม ความจุจึงมากกว่าได้โดยไม่แพง
**โจทย์**
- **บันทึกชื่อ** — เขียนไฟล์ชื่อ name.txt ที่มีข้อความ Ann แล้วอ่านกลับมาพิมพ์. ผลลัพธ์ที่ได้: `Ann`. คำใบ้: ใช้เปิดด้วย Write ก่อน ปิด แล้วเปิด Read อ่าน
- **สองบรรทัด** — เขียนไฟล์ ids.txt บรรทัดแรก 1 บรรทัดที่สอง 2 แล้วอ่านบรรทัดแรกกลับมาพิมพ์. ผลลัพธ์ที่ได้: `1`. คำใบ้: File::write เขียนบรรทัดแรกก่อนแล้วปิดไฟล์ การอ่านด้วย read_line อ่านได้หนึ่งบรรทัด

## รับเข้าและส่งออก
**คืออะไร.** อุปกรณ์รับเข้า (input) ส่งข้อมูลเข้าเครื่อง เช่นแป้นพิมพ์ เมาส์ ไมโครโฟน และกล้อง อุปกรณ์ส่งออก (output) รับข้อมูลออกจากเครื่อง เช่นจอ ลำโพง และเครื่องพิมพ์ บางอุปกรณ์ทำทั้งสองอย่าง เช่นจอสัมผัส
**ทำไมต้องรู้.** โปรแกรมที่ไม่มีทางรับข้อมูลเข้าก็ทำได้แค่งานที่ตายตัว และโปรแกรมที่ไม่มีทางส่งผลออกก็ไม่มีใครเห็นผล เมื่อคุณเขียนโปรแกรม คุณต้องคิดว่าข้อมูลจะเข้าทางไหนและผลจะออกทางไหน
**ทำอย่างไร.**

คิดเป็นสามช่อง: ข้อมูลเข้ามาจากไหน ใครจัดการ และผลออกไปที่ไหน
ในภาษา J2K เส้นทางเข้าของโปรแกรมที่ทำงานกับแป้นพิมพ์ใช้คำสั่ง jin และเส้นทางออกใช้ jout ซึ่งเราจะเรียนใน หมวดเขียนโปรแกรม
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    // output: the program sends text to the screen with jout
    int price = 25;
    int qty = 4;
    jout << "price " << price << "\n";
    jout << "total " << price * qty << "\n";
}
```

```
price 25
total 100
```

> **ระวัง:** นึกว่าการพิมพ์ลงจอคือการเก็บลงไฟล์ ไม่ใช่ การแสดงผลบนจอหายไปทันทีเมื่อโปรแกรมปิด ถ้าต้องการเก็บต้องเขียนลงไฟล์
**แบบฝึกหัด**
- ข้อใดเป็นอุปกรณ์รับเข้า
  - a) แป้นพิมพ์  b) ลำโพง  c) จอภาพ  — เฉลย: a. แป้นพิมพ์ส่งตัวอักษรเข้าเครื่อง ส่วนลำโพงและจอภาพรับผลจากเครื่องออกไป
- จอสัมผัสเป็นทั้งอุปกรณ์รับเข้าและส่งออกได้ — เฉลย: t. จอสัมผัสรับการแตะเป็นข้อมูลเข้า และแสดงภาพเป็นข้อมูลออกบนจอเดียวกัน
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int a = 4;
int b = 5;
jout << "in " << a << " and " << b << "\n";
jout << "out " << a * b << "\n";
}
```
  ผลลัพธ์ที่ได้: `in 4 and 5 / out 20`. สองบรรทัดแรกคือข้อมูลที่โปรแกรมรับมาจากตัวแปร และบรรทัดหลังคือผลที่ประมวลผลแล้ว
- อุปกรณ์ที่ส่งผลลัพธ์ออกไปให้คนเห็น เช่นจอ คือ ___ — เฉลย: **output**. จากคำศัพท์ในหัวข้อนี้ output คือส่วนที่ออกจากเครื่อง
- การรับค่าจากคีย์บอร์ดเข้าโปรแกรม: คนพิมพ์บนแป้นพิมพ์ → ตัวอักษรเข้าสู่เครื่อง → โปรแกรมรับด้วย jin → เก็บเป็นตัวแปร. ข้อมูลจากคนต้องเดินทางเข้าเครื่องก่อนที่โปรแกรมจะอ่านได้
- ลำโพงเป็นอุปกรณ์ประเภทใด
  - a) ส่งออก  b) รับเข้า  c) ทั้งสองแบบ  — เฉลย: a. ลำโพงรับสัญญาณจากเครื่องแล้วทำให้เกิดเสียง ไม่ได้รับอะไรจากคน
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
jout << "a" << "b" << 3 << "\n";
}
```
  ผลลัพธ์ที่ได้: `ab3`. เมื่อต่อหลาย ๆ ค่าด้วย << แต่ละค่าจะถูกพิมพ์ต่อกันโดยไม่มีช่องว่าง
**โจทย์**
- **ใบเสร็จ** — ราคาต่อชิ้น 40 บาท ซื้อ 2 ชิ้น พิมพ์บรรทัดแรกเป็น item 80 แล้วบรรทัดที่สองเป็น total 80 โดยคำนวณจากตัวแปร. ผลลัพธ์ที่ได้: `item 80 / total 80`. คำใบ้: ราคารวมคือราคาต่อชิ้นคูณจำนวน ใช้ตัวแปรเก็บค่าทั้งสอง
- **สองบรรทัด** — พิมพ์ A แล้วขึ้นบรรทัดใหม่ แล้วพิมพ์ B. ผลลัพธ์ที่ได้: `A / B`. คำใบ้: ใช้ \n เพื่อขึ้นบรรทัดใหม่

## ข้อมูลกับโปรแกรม
**คืออะไร.** ข้อมูล (data) คือสิ่งที่เก็บไว้ เช่นตัวเลข ตัวอักษร รูป และเสียง ส่วนโปรแกรม (program) คือคำสั่งที่บอกว่าจะทำอะไรกับข้อมูลนั้น ข้อมูลเดียวกันจะให้ผลต่างกันเมื่อคำสั่งเปลี่ยนไป ข้อมูลจะไม่ทำอะไรเองจนกว่าจะมีโปรแกรมมาอ่าน
**ทำไมต้องรู้.** เมื่อคุณเข้าใจว่าสองอย่างนี้ต่างกัน คุณจะรู้ว่าโปรแกรมที่ผิดต้องแก้ที่คำสั่ง หรือข้อมูลที่ป้อนผิด เช่นตัวเลข 42 เป็นข้อมูล แต่การคูณด้วย 2 เป็นโปรแกรม
**ทำอย่างไร.**

แยกตัวเลขหรือตัวอักษรที่โปรแกรมเก็บเป็นข้อมูล และคำสั่งที่ใช้กับมันเป็นโปรแกรม
ตัวเลขที่อยู่ในเครื่องหมายคำพูดเป็นข้อความ ไม่ใช่ตัวเลขจนกว่าจะแปลงด้วย to_int
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    String text = "42";
    int n = text.to_int();
    jout << text + "!\n";
    jout << n + 1 << "\n";
}
```

```
42!
43
```

> **ระวัง:** ข้อความ "42" กับตัวเลข 42 ไม่เหมือนกัน การบวก 1 กับข้อความจะทำไม่ได้หรือให้ผลแปลก ต้องแปลงก่อน
**แบบฝึกหัด**
- ข้อใดเป็นข้อมูล
  - a) ตัวเลข 42  b) คำสั่ง jout  c) ฟังก์ชัน main  — เฉลย: a. ตัวเลข 42 เป็นค่าที่เก็บไว้ ส่วน jout และ main เป็นคำสั่งของโปรแกรม
- ข้อมูลจะเปลี่ยนความหมายได้โดยไม่ต้องเปลี่ยนโปรแกรม — เฉลย: f. ความหมายของข้อมูลขึ้นกับโปรแกรมที่อ่านมัน ถ้าโปรแกรมทำงานต่างไป ผลก็ต่างไป
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
String s = "7";
int n = s.to_int();
jout << n * 6 << "\n";
}
```
  ผลลัพธ์ที่ได้: `42`. to_int แปลงข้อความ 7 เป็นตัวเลข 7 แล้วคูณ 6 ได้ 42
- ข้อความที่ประกอบด้วยตัวเลขเป็นตัวอักษรต้องแปลงด้วยคำสั่ง ___ ก่อนใช้คำนวณ — เฉลย: **to_int**. ชื่อเมธอดนี้ใช้ได้กับ String ทุกตัว แปลงข้อความเป็นจำนวนเต็ม
- การนำตัวเลขจากข้อความมาคำนวณ: รับข้อความจากผู้ใช้ → แปลงด้วย to_int → คำนวณกับตัวเลข → พิมพ์ผล. ต้องแปลงก่อน จึงจะคำนวณได้
- โปรแกรมที่ใช้ข้อมูลหนึ่งชุดให้ผลต่างกัน เพราะเหตุใด
  - a) คำสั่งที่ใช้กับข้อมูลต่างกัน  b) ข้อมูลเปลี่ยนเอง  c) เครื่องเปลี่ยนแรม  — เฉลย: a. ข้อมูลไม่ทำงานเอง ผลต่างเกิดจากคำสั่งที่ต่างกัน
**โจทย์**
- **แปลงข้อความ** — เก็บ "10" ในข้อความ แปลงเป็นจำนวน แล้วพิมพ์ค่าที่ได้คูณ 3. ผลลัพธ์ที่ได้: `30`. คำใบ้: ใช้ to_int แล้วคูณ 3
- **เปรียบข้อมูล** — เก็บ 7 ไว้เป็นตัวเลข และ "7" เป็นข้อความ แปลงข้อความเป็นตัวเลขแล้วพิมพ์ผลบวกทั้งสองอย่าง. ผลลัพธ์ที่ได้: `14`. คำใบ้: แปลงข้อความก่อนแล้วบวกกับตัวเลข

## เลขฐานสองและบิต
**คืออะไร.** ทุกข้อมูลในคอมพิวเตอร์เป็นเลขฐานสอง คือเลข 0 กับ 1 หนึ่งหลักเรียกว่า บิต (bit) แปดบิตเป็นหนึ่งไบต์ ในเลขฐานสอง ตำแหน่งแต่ละหลักมีค่าเป็น 1, 2, 4, 8, 16 และเพิ่มเป็นสองเท่าไปเรื่อย ๆ เลข 13 เขียนเป็น 1101 เพราะ 8 + 4 + 1 เท่ากับ 13
**ทำไมต้องรู้.** การรู้เลขฐานสองทำให้เข้าใจขีดจำกัดของตัวเลข เช่นเลข int 8 ไบต์มี 64 บิต และอ่านการเปิดปิดสวิตช์ของชิป การดีบักหรือการอ่านตัวเลขจากไฟล์ก็ต้องรู้เรื่องนี้
**ทำอย่างไร.**

เขียนตัวเลขเป็นเลขฐานสองโดยการหารด้วย 2 แล้วเก็บเศษ ทำซ้ำจนได้ศูนย์ แล้วอ่านเศษจากล่างขึ้นบน
ในภาษา J2K ใช้ตัวดำเนินการ >> เลื่อนบิตไปทางขวา และ & เพื่อดูเฉพาะบิตที่ต้องการ
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void show_bits(int n) {
    String s = "";
    for i in 0..4 {
        s.push((char)(48 + ((n >> (3 - i)) & 1)));
    }
    jout << s << "\n";
}

void main() {
    show_bits(13);
    show_bits(5);
}
```

```
1101
0101
```

> **ระวัง:** ตัวเลข 0101 กับ 101 ให้ค่าเท่ากัน เพราะเลขศูนย์นำหน้าไม่มีความหมาย แต่ในการแสดงผลแบบบิตต้องกำหนดจำนวนหลักให้ชัดเจน
**แบบฝึกหัด**
- 1011 ในเลขฐานสองมีค่าเท่าใดในฐานสิบ
  - a) 11  b) 1011  c) 5  — เฉลย: a. 8 + 0 + 2 + 1 เท่ากับ 11 โดยหลักแต่ละหลักมีค่าเป็นยกกำลังของ 2
- บิตที่มีค่า 1 ตำแหน่งที่สี่จากขวา มีค่าเท่ากับ 8 — เฉลย: t. ตำแหน่งจากขวาเป็น 1, 2, 4, 8 ดังนั้นตำแหน่งที่สี่คือ 8
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
jout << (6 & 3) << "\n";
}
```
  ผลลัพธ์ที่ได้: `2`. 6 เป็น 110 และ 3 เป็น 011 บิตที่ตรงกันทั้งสองมีแค่ตำแหน่งที่มีค่า 2 ผลจึงได้ 2
- ตัวดำเนินการ >> ในภาษา J2K ทำการเลื่อนบิตไปทางขวา คำนี้ในภาษาอังกฤษคือ ___ shift — เฉลย: **right**. เครื่องหมาย >> ทำให้ค่าเลื่อนขวาหนึ่งตำแหน่งต่อหนึ่งครั้งคล้ายการหารด้วย 2
- การเขียนเลข 5 เป็นฐานสอง: หารด้วย 2 เก็บเศษ → ทำซ้ำกับผลหารจนได้ 0 → อ่านเศษจากล่างขึ้นบน → ได้ 101. เศษแรกอยู่หลักขวาสุดเสมอ จึงต้องอ่านกลับจากท้ายขึ้นมา
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
jout << (1 << 3) << "\n";
}
```
  ผลลัพธ์ที่ได้: `8`. การเลื่อนซ้ายหนึ่งตำแหน่งเท่ากับคูณ 2 การเลื่อนซ้ายสามครั้งคูณ 8
- ไบต์หนึ่งไบต์มีจำนวนบิตเท่าใด
  - a) 8  b) 4  c) 16  — เฉลย: a. หนึ่งไบต์มีแปดบิต ซึ่งแสดงค่าได้ตั้งแต่ 0 ถึง 255
**โจทย์**
- **ตัวเลขฐานสอง** — เขียนโปรแกรมที่เลื่อนค่า 10 ไปทางขวาหนึ่งตำแหน่งแล้วพิมพ์ผล. ผลลัพธ์ที่ได้: `5`. คำใบ้: 10 เป็น 1010 เมื่อเลื่อนขวาจะได้ 101 ซึ่งเท่ากับ 5
- **นับบิต** — เขียนโปรแกรมที่นับว่าเลข 13 มีบิตที่เป็น 1 กี่ตัว โดยดูสี่หลัก แล้วพิมพ์ bits 3. ผลลัพธ์ที่ได้: `bits 3`. คำใบ้: 1101 มี 1 สามตัว ใช้ for และ & 1 เพื่อนับ

## ตัวอักษรและ Unicode
**คืออะไร.** คอมพิวเตอร์เก็บตัวอักษรเป็นตัวเลข ตัวอักษร A มีรหัส 65 ตัว a มีรหัส 97 ตาราง Unicode รวมรหัสของตัวอักษรเกือบทุกภาษาในโลก เช่นตัวอักษรไทย ก มีรหัสของตัวเอง ใน J2K ข้อความ String เก็บเป็นไบต์แบบ UTF-8 ซึ่งตัวอักษรบางตัวใช้หลายไบต์
**ทำไมต้องรู้.** ถ้าไม่รู้เรื่องนี้ คุณจะคิดว่า ก มีความยาวหนึ่งตัว แต่โปรแกรมบอกว่าความยาวสามไบต์ การนับความยาวและการตัดข้อความต้องรู้ว่าสิ่งที่นับคือไบต์หรือตัวอักษร
**ทำอย่างไร.**

ใช้ (int)'A' เพื่อดูรหัสของตัวอักษร และ (char) กับตัวเลขเพื่อกลับเป็นตัวอักษร
ตัวอักษรเดี่ยวอยู่ในเครื่องหมายคำพูดเดี่ยว ข้อความอยู่ในเครื่องหมายคำพูดคู่
.len ของ String นับไบต์ ไม่ใช่จำนวนตัวอักษรที่คนเห็น
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    char c = 'A';
    jout << (int)c << "\n";
    String word = "Jao";
    jout << word.len << "\n";
    String th = "ก";
    jout << th.len << "\n";
}
```

```
65
3
3
```

> **ระวัง:** ตัวอักษรไทยหนึ่งตัวใช้มากกว่าหนึ่งไบต์ ดังนั้น len ของ "ก" คือ 3 ถ้าตัดข้อความตามไบต์อาจทำให้ตัวอักษรแตกเป็นอักขระเสีย
**แบบฝึกหัด**
- รหัสของตัวอักษร A ในตาราง ASCII หรือ Unicode คือเท่าใด
  - a) 65  b) 97  c) 1  — เฉลย: a. A คือ 65 และ a คือ 97 เป็นคนละตัวอักษรในตาราง
- ข้อความ "ก" มีความยาวหนึ่งไบต์เสมอ — เฉลย: f. ตัวอักษรไทยใช้หลายไบต์ในรูปแบบ UTF-8 ดังนั้น len ของ ก จึงไม่ใช่ 1
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
char c = 'B';
jout << (int)c << "\n";
}
```
  ผลลัพธ์ที่ได้: `66`. B อยู่ถัดจาก A หนึ่งตำแหน่งในตาราง จึงเป็น 65 + 1 เท่ากับ 66
- ตารางที่รวมรหัสตัวอักษรของทุกภาษาเรียกว่า ___ — เฉลย: **unicode**. Unicode เป็นมาตรฐานกลางที่กำหนดรหัสให้ตัวอักษรเกือบทุกตัวในโลก
- การหารหัสของตัวอักษร Z ในโปรแกรม: เขียนตัวอักษร 'Z' → แปลงเป็น int ด้วย (int) → พิมพ์ค่าที่ได้ → ได้ 90. ตัวอักษรต้องเป็นตัวเลขก่อนจึงแสดงรหัสได้
- ตัวเลข 1 ใน ASCII คือตัวอักษร
  - a) ไม่ใช่ตัวอักษรของค่า 1 แต่เป็นรหัส 49  b) ตัวเลข 1  c) ตัวอักษร a  — เฉลย: a. ตัวอักษร '1' มีรหัส 49 ไม่ใช่ค่า 1 ผู้เขียนโปรแกรมต้องแยกสองอย่างนี้ให้ชัด
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
String w = "ab";
jout << w.len << "\n";
}
```
  ผลลัพธ์ที่ได้: `2`. ตัวอักษรภาษาอังกฤษแต่ละตัวใช้หนึ่งไบต์ จึงรวมเป็นสองไบต์
**โจทย์**
- **รหัสของ Z** — พิมพ์รหัสของตัวอักษร 'Z' ด้วย (int). ผลลัพธ์ที่ได้: `90`. คำใบ้: Z มีรหัส 90 ใน ASCII
- **ความยาวไทย** — พิมพ์ความยาวไบต์ของข้อความ "กา". ผลลัพธ์ที่ได้: `6`. คำใบ้: ตัวอักษรไทยแต่ละตัวใช้สามไบต์ใน UTF-8 จึงรวมเป็นหก

## ระบบปฏิบัติการ
**คืออะไร.** ระบบปฏิบัติการ (operating system) คือซอฟต์แวร์ชุดแรกที่ทำงานหลังเปิดเครื่อง มันจัดการซีพียู แรม ที่เก็บถาวร และอุปกรณ์ทุกชิ้น และให้โปรแกรมอื่นขอใช้บริการผ่านระบบเรียกระบบ (system call) โปรแกรมไม่ควรแตะฮาร์ดแวร์เองโดยตรง
**ทำไมต้องรู้.** โปรแกรมแต่ละตัวจะได้แรมของตัวเอง เปิดไฟล์ได้โดยไม่ต้องรู้ว่าดิสก์อยู่ที่ไหน และใช้เครือข่ายได้ ทั้งหมดนี้เป็นงานของระบบปฏิบัติการ ถ้าคุณเข้าใจสิ่งนี้ คุณจะเข้าใจว่าโปรแกรมของคุณขอบริการจากใครบ้าง
**ทำอย่างไร.**

เมื่อโปรแกรมต้องการอะไรจากเครื่อง เช่นอ่านไฟล์ มันขอผ่านระบบปฏิบัติการ ไม่ได้อ่านดิสก์เอง
ในภาษา J2K ฟังก์ชันอย่าง File::open และ Env::get ทำงานโดยขอให้ระบบปฏิบัติการทำให้ ผลที่กลับมาอาจเป็น Option หรือตัวเลขที่บอกว่าล้มเหลว
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    // the operating system answers: a variable that is not set gives an empty Option
    Option<String> v = Env::get("J2K_SURELY_NOT_SET");
    if v.is_none() { jout << "no such variable\n"; }
    jout << "the program asked the system for it\n";
}
```

```
no such variable
the program asked the system for it
```

> **ระวัง:** อย่าเชื่อว่าโปรแกรมจะเข้าถึงทุกที่ได้เสมอ ระบบปฏิบัติการมีกฎการอนุญาต และถ้าโปรแกรมขออะไรผิด ระบบจะปฏิเสธ ต้องเช็กผลทุกครั้ง
**แบบฝึกหัด**
- ระบบปฏิบัติการทำหน้าที่ใดเป็นหลัก
  - a) จัดการอุปกรณ์และให้โปรแกรมขอบริการ  b) แต่งเพลง  c) แปลงโค้ดเป็นตัวอักษร  — เฉลย: a. ระบบปฏิบัติการดูแลทรัพยากรของเครื่องและเป็นตัวกลางระหว่างโปรแกรมกับฮาร์ดแวร์
- โปรแกรมควรแตะฮาร์ดแวร์โดยตรงทุกครั้งเพื่อให้เร็วที่สุด — เฉลย: f. ระบบปฏิบัติการคุมการแชร์ทรัพยากร ถ้าโปรแกรมแตะตรง ๆ อาจทำให้โปรแกรมอื่นและระบบล่ม
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
Option<String> v = Env::get("J2K_SURELY_NOT_SET");
jout << v.is_some() << "\n";
}
```
  ผลลัพธ์ที่ได้: `false`. ตัวแปรสภาพแวดล้อมนี้ไม่ได้ตั้งไว้ จึงไม่มีค่า is_some ให้ค่าเป็น false
- ชุดคำสั่งที่โปรแกรมขอให้ระบบปฏิบัติการทำงานเรียกว่า ___ call — เฉลย: **system**. system call คือการเรียกเข้าสู่ระบบปฏิบัติการ
- โปรแกรมเปิดไฟล์หนึ่งไฟล์: โปรแกรมเรียก File::open → ระบบปฏิบัติการเปิดไฟล์บนดิสก์ → ได้หมายเลขไฟล์กลับมา → โปรแกรมอ่านหรือเขียนด้วยหมายเลขนั้น. โปรแกรมไม่รู้ว่าดิสก์อยู่ที่ไหน ต้องรอให้ระบบเปิดให้ก่อน
- ทำไมไฟล์บางไฟล์เปิดไม่ได้ทั้งที่โปรแกรมถูก
  - a) เพราะระบบปฏิบัติการไม่อนุญาต หรือไม่มีไฟล์นั้น  b) เพราะซีพียูเบื่อ  c) เพราะตัวอักษรเป็นภาษาไทย  — เฉลย: a. ระบบปฏิบัติการตรวจสิทธิ์และการมีอยู่ของไฟล์ก่อนให้เข้าถึง
**โจทย์**
- **ตัวแปรที่ไม่มี** — อ่านตัวแปรชื่อ J2K_NOT_HERE ด้วย Env::get แล้วพิมพ์ none ถ้าไม่มี. ผลลัพธ์ที่ได้: `none`. คำใบ้: ใช้ is_none() ในเงื่อนไข if
- **ขอเรียกระบบ** — เขียนโปรแกรมที่ขอตัวแปร J2K_NOT_HERE สองครั้ง แล้วพิมพ์ 2 ครั้ง. ผลลัพธ์ที่ได้: `2`. คำใบ้: แต่ละครั้งเป็น Env::get แยกกัน แล้วบวกหนึ่งต่อครั้ง

## ไฟล์และโฟลเดอร์
**คืออะไร.** ไฟล์คือก้อนข้อมูลที่มีชื่อบนที่เก็บถาวร โฟลเดอร์คือที่รวมไฟล์และโฟลเดอร์ย่อยเป็นลำดับชั้น เส้นทาง (path) คือการบอกตำแหน่งจากจุดเริ่มต้น เช่น docs/plan.txt หมายถึงไฟล์ plan.txt ที่อยู่ในโฟลเดอร์ docs
**ทำไมต้องรู้.** โปรแกรมเกือบทุกโปรแกรมต้องรู้ว่าจะหาไฟล์ที่ไหน ถ้าเส้นทางผิดนิดเดียว การอ่านจะล้มเหลวเพราะไม่มีไฟล์ คุณต้องรู้ทั้งชื่อไฟล์และโฟลเดอร์ที่มัน
**ทำอย่างไร.**

เส้นทางที่ไม่เริ่มด้วยเครื่องหมายขึ้นต้นเป็นเส้นทางสัมพัทธ์ คือเริ่มนับจากโฟลเดอร์ที่โปรแกรมทำงานอยู่
ในโปรแกรมเราเขียนเส้นทางเป็นข้อความ เช่น "docs/plan.txt" แล้วส่งให้ File::open
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    String dir = "docs";
    String path = dir + "/" + "plan.txt";
    jout << path << " has " << path.len << " characters\n";
}
```

```
docs/plan.txt has 13 characters
```

> **ระวัง:** ชื่อไฟล์เป็นตัวพิมพ์เล็กใหญ่ต่างกันในหลายระบบ Plan.txt กับ plan.txt อาจเป็นคนละไฟล์ ให้เขียนชื่อให้ตรงทุกตัวอักษร
**แบบฝึกหัด**
- ไฟล์ docs/plan.txt หมายความว่าอย่างไร
  - a) ไฟล์ plan.txt ที่อยู่ในโฟลเดอร์ docs  b) โฟลเดอร์ plan  c) ไฟล์ docs ที่อยู่ใน plan.txt  — เฉลย: a. เส้นทางอ่านจากซ้ายไปขวา โฟลเดอร์ก่อน แล้วชื่อไฟล์ท้ายสุด
- โฟลเดอร์สามารถมีไฟล์และโฟลเดอร์ย่อยอยู่ข้างในได้ — เฉลย: t. โฟลเดอร์ซ้อนกันได้หลายชั้น ทำให้จัดระเบียบข้อมูลได้
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
String d = "a";
String p = d + "/" + "b.txt";
jout << p << "\n";
}
```
  ผลลัพธ์ที่ได้: `a/b.txt`. การต่อข้อความด้วยเครื่องหมายบวกทำให้ได้เส้นทางตามที่ต้องการ
- ตำแหน่งของไฟล์บอกด้วย ___ ซึ่งเป็นชื่อโฟลเดอร์และชื่อไฟล์เรียงกัน — เฉลย: **path**. path คือเส้นทาง เช่น docs/plan.txt
- ลำดับการหาไฟล์ docs/plan.txt: เริ่มที่โฟลเดอร์ที่โปรแกรมทำงาน → เข้าโฟลเดอร์ docs → หาไฟล์ plan.txt → เปิดไฟล์. ระบบต้องเข้าโฟลเดอร์ก่อนจึงหาไฟล์ที่อยู่ข้างในได้
- ข้อใดทำให้เปิดไฟล์ไม่ได้
  - a) เขียนชื่อผิดหนึ่งตัวอักษร  b) ใช้ตัวแปร  c) ใช้ for  — เฉลย: a. ชื่อผิดหนึ่งตัวทำให้ระบบหาไฟล์ไม่เจอ ต้องตรวจทุกตัวอักษรในเส้นทาง
**โจทย์**
- **ต่อเส้นทาง** — สร้างเส้นทาง notes/day1.txt จากตัวแปร dir เป็น notes และ name เป็น day1.txt แล้วพิมพ์. ผลลัพธ์ที่ได้: `notes/day1.txt`. คำใบ้: ต่อด้วย + และ "/"
- **นับความยาว** — พิมพ์ความยาวของเส้นทาง "src/main.jk". ผลลัพธ์ที่ได้: `11`. คำใบ้: นับทุกตัวอักษรรวมตัวหารโฟลเดอร์และจุด

## อินเทอร์เน็ตและเครือข่าย
**คืออะไร.** เครือข่ายคือการต่อคอมพิวเตอร์เข้าด้วยกัน อินเทอร์เน็ตคือเครือข่ายของเครือข่ายทั่วโลก ข้อมูลถูกหั่นเป็นแพ็กเก็ต แต่ละแพ็กเก็ตมีที่อยู่ปลายทาง (IP address) และถูกส่งผ่านหลายจุดจนถึงปลายทาง เว็บไซต์ใช้โปรโตคอล HTTP หรือ HTTPS ในการส่งข้อความ
**ทำไมต้องรู้.** เกือบทุกโปรแกรมสมัยนี้ใช้เครือข่าย ไม่ว่าจะเปิดเว็บ ดาวน์โหลดแพ็กเกจ หรือแชต การเข้าใจว่าข้อมูลแยกเป็นแพ็กเก็ตและมีที่อยู่ช่วยให้คุณเข้าใจความล่าช้าและความล้มเหลวของการเชื่อมต่อ
**ทำอย่างไร.**

URL เช่น http://example.com/a แบ่งเป็นสามส่วน: โปรโตคอล (http) ชื่อโฮสต์ (example.com) และเส้นทางในเซิร์ฟเวอร์ (/a)
โปรแกรมแยกส่วนได้ด้วย find หาตำแหน่งของ :// แล้วใช้ slice ตัดข้อความ
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    String url = "http://example.com/a";
    int at = url.find("://");
    jout << "protocol " << url.slice(0, at) << "\n";
    jout << "host and path " << url.slice(at + 3, url.len) << "\n";
}
```

```
protocol http
host and path example.com/a
```

> **ระวัง:** ลืมว่าข้อความ find ได้ตำแหน่งเริ่มต้นและนับจาก 0 ถ้าใช้ at + 3 ผิด จะตัดตัวอักษรของโฮสต์ไปหนึ่งตัวได้
**แบบฝึกหัด**
- ข้อมูลบนอินเทอร์เน็ตถูกส่งเป็นอะไร
  - a) แพ็กเก็ต  b) หนึ่งไฟล์ยาวไม่มีวันจบ  c) ตัวอักษรเดี่ยว  — เฉลย: a. ข้อมูลถูกแบ่งเป็นชิ้นเล็ก ๆ ที่มีที่อยู่ปลายทาง แพ็กเก็ตอาจไปคนละเส้นทาง
- URL ทุกตัวต้องมี :// หลังโปรโตคอล — เฉลย: t. โปรโตคอลกับโฮสต์ถูกคั่นด้วย :// ตามมาตรฐาน URL
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
String u = "https://x.io/p";
jout << u.find("://") << "\n";
}
```
  ผลลัพธ์ที่ได้: `5`. ตัวอักษร h t t p s ใช้ห้าตำแหน่งแรก เครื่องหมาย :// เริ่มที่ตำแหน่งที่ 5 โดยนับจาก 0
- ระบบบอกที่อยู่ปลายทางของแพ็กเก็ตด้วย ___ address — เฉลย: **ip**. IP address คือที่อยู่ที่เครื่องใช้ค้นหาปลายทาง
- การเปิดหน้าเว็บหนึ่งหน้า: พิมพ์ URL ในเบราว์เซอร์ → แปลงชื่อโฮสต์เป็น IP → ส่งคำขอ HTTP → รับข้อความตอบกลับและแสดงผล. ต้องรู้ปลายทางก่อนจึงส่งคำขอได้ และต้องได้คำตอบก่อนแสดงผล
- แพ็กเก็ตที่หายไประหว่างทางจะเกิดอะไรขึ้น
  - a) โปรโตคอลส่งใหม่หรือรายงานความล้มเหลว  b) ข้อมูลทั้งหมดหาย  c) ทุกอย่างกลับมาเอง  — เฉลย: a. โปรโตคอลอย่าง TCP ตรวจและส่งใหม่เมื่อจำเป็น แต่โปรแกรมต้องรองรับความล้มเหลวด้วย
**โจทย์**
- **แยกชื่อโฮสต์** — จาก URL "https://site.org/x" พิมพ์ชื่อโปรโตคอล (ก่อน ://). ผลลัพธ์ที่ได้: `https`. คำใบ้: ใช้ find แล้ว slice(0, at)
- **ตัดเส้นทาง** — จาก "http://a.b/hello" พิมพ์เส้นทางที่อยู่หลังโฮสต์ทั้งหมด โดยไม่รวม http. ผลลัพธ์ที่ได้: `a.b/hello`. คำใบ้: ตัดหลัง ://

## โปรแกรมรันอย่างไร
**คืออะไร.** โปรแกรมที่คุณเขียนเป็นข้อความ คอมไพเลอร์แปลงเป็นชุดคำสั่งของซีพียู (ไฟล์เรียกทำงาน) แล้วระบบปฏิบัติการโหลดไฟล์นั้นเข้าแรม ตั้งค่าเริ่มต้น แล้วให้ซีพียูเริ่มทำงานที่ main ทีละคำสั่งจนจบหรือจนเจอข้อผิดพลาด
**ทำไมต้องรู้.** เมื่อโปรแกรมล่มหรือช้า คุณต้องรู้ว่าปัญหาอยู่ระดับไหน ข้อความแปลภาษาผิด ข้อผิดตอนรัน หรือความช้าจากลูป ทุกระดับต่างกันมาก
**ทำอย่างไร.**

ขั้นของการทำงาน: เขียนโค้ด แล้วคอมไพล์ด้วย jcmp แล้วรันไฟล์ที่ได้
ถ้าคอมไพล์ผ่านแล้วโปรแกรมยังผิด ปัญหาอยู่ในลอจิกของโค้ด ไม่ใช่ในการแปล
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    // this file becomes machine instructions; the program starts at main
    for i in 1..4 {
        jout << "instruction " << i << " runs\n";
    }
}
```

```
instruction 1 runs
instruction 2 runs
instruction 3 runs
```

> **ระวัง:** บางคนรันไฟล์เก่าโดยไม่คอมไพล์ใหม่ แล้วคิดว่าการแก้ของตนไม่มีผล ให้คอมไพล์ทุกครั้งหลังแก้โค้ด
**แบบฝึกหัด**
- ซีพียูอ่านโค้ดที่เขียนด้วย J2K ตรง ๆ ได้หรือไม่
  - a) ไม่ได้ ต้องแปลเป็นชุดคำสั่งของเครื่องก่อน  b) ได้เลย  c) ได้ถ้าเปิดแรม  — เฉลย: a. ซีพียูเข้าใจเฉพาะรหัสเครื่อง คอมไพเลอร์เป็นตัวแปลภาษาระดับสูงให้เป็นรหัสนั้น
- ระบบปฏิบัติการโหลดไฟล์โปรแกรมเข้าแรมก่อนรัน — เฉลย: t. โปรแกรมต้องอยู่ในแรมเพื่อให้ซีพียูดึงคำสั่งจากที่นั่นได้
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
for i in 1..3 { jout << i << "\n"; }
}
```
  ผลลัพธ์ที่ได้: `1 / 2`. for i in 1..3 วนได้ 1 และ 2 โดยไม่รวม 3 ตามที่ภาษาตั้งไว้
- ไฟล์ที่คอมไพล์แล้วพร้อมรันเรียกว่า ___ file — เฉลย: **executable**. executable คือไฟล์โปรแกรมที่รันได้
- ขั้นตอนหลังเขียนโค้ดจนได้ผลลัพธ์: คอมไพล์ด้วย jcmp → รันไฟล์ที่ได้ → อ่านผลลัพธ์ → แก้โค้ดถ้าไม่ตรง. ต้องคอมไพล์ใหม่ทุกครั้งที่แก้ จึงจะเห็นผลจริง
- โปรแกรมเริ่มทำงานที่ฟังก์ชันใด
  - a) main  b) jout  c) Env  — เฉลย: a. J2K เริ่มทำงานที่ main เสมอ ฟังก์ชันอื่นถูกเรียกจาก main หรือจากกันเอง
**โจทย์**
- **นับถอยหลัง** — เขียนโปรแกรมที่พิมพ์ตัวเลข 3 2 1 แต่ละบรรทัด. ผลลัพธ์ที่ได้: `3 / 2 / 1`. คำใบ้: ใช้ for ที่นับจากมากไปน้อยด้วย int i = 3; i > 0; i--
- **ข้อความบรรทัดเดียว** — พิมพ์ข้อความ run ok และขึ้นบรรทัดใหม่. ผลลัพธ์ที่ได้: `run ok`. คำใบ้: ใช้ jout ครั้งเดียว

## อัลกอริทึมและบั๊ก
**คืออะไร.** อัลกอริทึม (algorithm) คือลำดับขั้นตอนที่ชัดเจน ทำได้จริง และจบในที่สุด สำหรับแก้ปัญหาหนึ่ง เช่นวิธีหาเลขที่มากที่สุดในกลุ่ม บั๊ก (bug) คือความผิดพลาดในโค้ดที่ทำให้ผลไม่ตรงกับที่ต้องการ ซึ่งมักเกิดจากการคิดขั้นตอนไม่ครบหรือการนับเกิน
**ทำไมต้องรู้.** ภาษาโปรแกรมเปลี่ยนไปได้ แต่อัลกอริทึมคิดได้ก่อนจะเขียนโค้ด เมื่อคุณเข้าใจวิธีแก้ปัญหา คุณจะรู้ว่าบั๊กอยู่ตรงไหนในความคิด ไม่ใช่แค่ในไวยากรณ์
**ทำอย่างไร.**

เขียนขั้นตอนเป็นภาษาคนก่อน แล้วทดลองกับตัวอย่างเล็กที่คำนวณในหัวได้
บั๊กที่พบบ่อยที่สุดคือ off-by-one: วนลูปขาดหรือเกินหนึ่งรอบ ทำให้พลาดตัวสุดท้ายหรือนับซ้ำ
**ตัวอย่าง.**

```jk
#import <stdlib>
using stdlib;

void main() {
    int nums[5];
    nums[0] = 4; nums[1] = 9; nums[2] = 2; nums[3] = 7; nums[4] = 5;
    int best = nums[0];
    for i in 1..5 {
        if nums[i] > best { best = nums[i]; }
    }
    jout << "largest " << best << "\n";
}
```

```
largest 9
```

> **ระวัง:** ลูป for i in 0..4 จะไม่ดูตัวที่ห้า คือตัว 5 ถ้าเลขที่มากที่สุดอยู่ท้ายสุดแล้วได้คำตอบผิด ให้ตรวจขอบของลูปก่อน
**แบบฝึกหัด**
- อัลกอริทึมที่ดีต้องมีคุณสมบัติใดเป็นอย่างน้อย
  - a) ขั้นตอนชัดเจนและจบในที่สุด  b) ต้องยาวมาก  c) ต้องใช้ภาษาเฉพาะ  — เฉลย: a. อัลกอริทึมคือขั้นตอนที่ทำได้จริงและไม่วนไม่จบ ความยาวไม่ใช่เงื่อนไข
- บั๊กทุกตัวเกิดจากเครื่องเสีย — เฉลย: f. ส่วนใหญ่ของบั๊กเกิดจากการคิดขั้นตอนผิดหรือเขียนโค้ดผิด ไม่ใช่เครื่อง
- ทายผลลัพธ์ของโค้ด:

```jk
#import <stdlib>
using stdlib;

void main() {
int count = 0;
for i in 0..3 { count += 1; }
jout << count << "\n";
}
```
  ผลลัพธ์ที่ได้: `3`. for i in 0..3 วนสามรอบ คือ 0, 1, 2 ทำให้นับได้ 3
- การวนลูปเกินหรือขาดหนึ่งรอบเรียกว่า ___ by one — เฉลย: **off**. off-by-one คือบั๊กที่ขอบของลูปผิดไปหนึ่ง
- วิธีแก้บั๊กที่ดี: ทำซ้ำจนเห็นอาการ → ลดตัวอย่างให้เล็ก → คิดคำตอบที่ถูกด้วยมือ → แก้ตรงจุดแล้วทดสอบอีกครั้ง. ต้องทำซ้ำได้ก่อน แล้วค่อยหาสาเหตุ และตรวจผลหลังแก้เสมอ
- ถ้าโปรแกรมให้ผลผิดกับอินพุตเล็ก ควรทำอย่างไร
  - a) พิมพ์ค่าระหว่างทางแล้วเปรียบกับที่คิดไว้  b) เปลี่ยนเครื่อง  c) ลบโค้ดทั้งหมด  — เฉลย: a. การดูค่าระหว่างทางทำให้เห็นว่าเริ่มผิดตรงไหน
**โจทย์**
- **ขนาดกลุ่ม** — เขียนโปรแกรมที่นับจำนวนตัวเลขในอาเรย์ 2, 4, 6, 8 แล้วพิมพ์ count 4. ผลลัพธ์ที่ได้: `count 4`. คำใบ้: ใช้ .len ของอาเรย์
- **หาค่าสูงสุด** — ในอาเรย์ 3, 8, 1, 9, 4 หาค่าที่มากที่สุดแล้วพิมพ์ max 9. ผลลัพธ์ที่ได้: `max 9`. คำใบ้: เริ่มจากตัวแรก วนตั้งแต่ตัวที่สอง
